第 2 / 35 节 · 入门与案例

DeepSeek Harness（命令行入口为 dsh）把文件、命令、会话和审批交给插件。项目用 Cordis 管理插件的组合与生命周期；下文依据官方仓库的 README 和公开文档，前半看它如何组织这些能力，后半从启动服务走到提交第一条任务，再看本地插件怎么挂进去。

Harness 是模型外面那层运行环境

模型本身只负责理解上下文和生成下一步行动。让 agent 能“工作”的是周围那层运行环境，它决定 agent 能访问哪些文件，能调用哪些命令，如何保存会话，如何执行计划，以及哪些动作需要人工批准。

DeepSeek Harness 把这些能力放进插件体系：插件注册服务、工具和事件处理逻辑，运行时负责组合、启动和管理它们。要换一项能力，可以从对应插件和它的依赖关系查起。

图：模型只给出下一步，文件、命令、会话、计划和审批由 Harness 分层承接，最终落到测试工作区。

插件通过 Context 注册能力

官方文档给出的最小插件是一个导出 apply 函数的 TypeScript 模块。Harness 加载插件时传入上下文，插件通过上下文注册自己的能力：

import type { Context } from '@deepseek-ai/cordis'

export const name = 'hello-plugin'

export function apply(ctx: Context) {
  console.log('[hello-plugin] plugin loaded!')
}

hello-plugin 只用到运行时传入的上下文，不需要知道整个应用的内部实现。更复杂的插件可以在同一个上下文中注册工具、监听事件、提供 LLM 适配器或暴露服务，再由 cordis.yml 插入运行配置。代价是开发者需要理解插件边界、依赖关系和加载顺序。

图：运行时把 ctx 传给插件的 apply，插件在同一个上下文里注册服务、工具、事件和命令。

图：根据 DeepSeek Harness 官方插件、生命周期和能力分层文档绘制的解释图，不是项目官方原图。

卸载时自动清理见第 4 篇，inject 依赖见第 5 篇，事件见第 6 篇，插件树见第 7 篇，可替换的服务提供者见第 8 篇。

启动配置和会话日志各管一件事

按与本系列相同源码版本的官方架构文档，dsh 启动时先按 profile 把组合包和补丁叠成插件树。web 在共享的基础组合上加入浏览器应用；profile、home 与命令行补丁还可能改变最终插件树，用户补丁能替换树中的配置项。第 7 篇会拆插件树，第 30 篇再看 headless 和 SDK 两种进程外入口。这里依据文档说明组装方式，没有实测启动配置的叠加顺序。

运行起来后，三类事件的用途不同：会话事件写入日志，供恢复和回放；agent/* 事件处理正在进行的轮次；tools/* 等能力事件让插件接入执行策略。一次工具调用为什么被拦、模型当时看到什么，要沿着这些事件分别查，第 9、11、16 篇会用本机输出展开。

适合研究和评估，当前只适合在隔离环境试用

DeepSeek Harness 适合这几类需求：

  • 研究 agent 工具、服务和生命周期如何组合。
  • 把本地项目接入 Web 工作台。
  • 开发或评估自己的 Harness 插件。
  • 将模型能力与文件系统、命令执行、会话状态和审批策略分层管理。

如果只是偶尔问答，聊天产品会更省事；Harness 面向的是要扩展 agent 工具、控制它能做什么的场景。

截至 2026-09，官方仓库将 DeepSeek Harness 标为 developer preview，并明确提示可能出现不兼容变更。官方安全说明（SAFETY.md）还写明：项目未经安全审计，不应视为安全或可用于生产的软件。

因此当前版本暂时不适合追求长期稳定 API 和生产部署的团队，只适合学习、原型和隔离环境中的试用；试用时固定依赖版本，优先放在一次性虚拟机或容器里，检查插件及第三方依赖的权限范围，以及每次升级带来的行为变化。

项目采用 MIT 许可证，但第三方依赖的许可证需要查看仓库中的 THIRD_PARTY_NOTICES.md。安全相关行为应先阅读官方安全说明，再决定是否开放命令执行或扩大工作区范围。

一条 npx 命令就能启动 Web UI

Web UI 把上面这些能力搬进浏览器，同时要求你显式指定本地项目：要先配置模型、选中工作区，才能发出第一条任务。

最省事的方式是直接通过 npm 启动。机器上需要先安装 Node.js。

图：官方 Quickstart 页面展示的模型配置、工作区选择和任务运行路径。

npx @deepseek-ai/dsh web

这条命令选择 web profile。本文只走默认启动路径。

默认情况下，服务会监听 http://127.0.0.1:3080。命令行会打印实际访问地址；打开它，就能进入 Web UI。不希望自动打开浏览器时加上 --no-open。

图：本机 0.1.5-rc.2 构建的 Web UI 首页，左侧是会话与工作区，中间是任务输入区。

如果你希望从源码运行，可以使用官方仓库：

git clone https://github.com/deepseek-ai/deepseek-harness.git
cd deepseek-harness
pnpm install
pnpm run build
pnpm dsh web

dsh 会把“启动命令所在的目录”作为默认文件系统位置，这一点容易忽略。准备操作某个项目时，最好先进入那个项目目录，再启动服务。不过这还不等于 Web UI 已经选中了工作区，后面仍需要手动确认。

模型保存后立即可用

进入 设置 → 模型，填入 DeepSeek API Key，然后保存。

图：模型设置页显示已配置的 DeepSeek 与 minimax-cn 提供方。

官方 Quickstart 写明：保存后，模型路由立即可用，不需要重启服务，试用时改完就能发任务。

如果你不打算使用 DeepSeek，也可以继续看官方的模型配置指南，那里介绍了其他提供方和自定义 OpenAI 兼容端点。建议把 API Key 当作凭据管理，不要写进项目代码、提交到 Git，或复制进公开截图。

不选工作区就不能发任务

点击 选择工作区，添加启动 dsh 时所在的项目目录，然后选中它。服务启动后并不会自动选中一个项目。

图：选择工作区入口；截图中的 docs 是本机测试工作区。

工作区决定 agent 默认在哪个项目里工作，内建文件工具的相对路径按它解析；但它不是隔离边界：命令和插件仍可能读到工作区之外。没有选中工作区时，会话输入框不会开放，界面要求先明确“agent 可以在哪个项目里工作”。

第一次使用时，建议选一个专门的测试目录，别直接指向生产仓库。先放入一个包含 README 和少量源文件的小项目，确认读取、编辑和命令执行都符合预期，再扩大权限范围。

第一条任务先只读仓库

启动一个新会话，发送这条官方示例提示词：

Summarize this repository and identify its main packages.

这条提示词风险低、结果容易核对，agent 只需要阅读仓库并整理结构，不必一上来就修改代码。正常情况下，agent 可以读取和编辑工作区文件、运行命令、委派工作，并维护一个执行计划。

能打开页面，只说明服务已经启动；任务运行时，写文件和执行命令是否需要人确认，取决于当前权限策略。当某项操作需要审批时，Web UI 会先询问你。遇到文件写入、命令执行或其他有副作用的动作，先看清楚目标路径和命令，再决定是否批准；不要为了让流程“自动跑完”而无条件放行。

挂一个本地插件试试

想先挂一个本地插件，分两步。第一步在 cordis.yml 里插入插件，官方教程的最小示例要求 name 写绝对路径：

- insert:
    - id: hello
      name: '/absolute/path/to/deepseek-harness/scratch-plugin/src/my-plugin.ts'

第二步在源码仓库根目录用 patch 启动 Web UI，写法沿用第 3 篇实测跑通的命令：

pnpm dsh --profile web --patch ./scratch-plugin/cordis.yml

需要加 --no-open、--port 时，--patch 必须放在它们之前，否则启动报 unknown option '--patch'，完整过程见第 3 篇 发布记录查询插件实战。

社区插件以各自 README 为准

GitHub 上已有社区维护的 Awesome DSH Plugin 精选列表，项目 README 还提供了插件市场和插件发现工具。截至 2026-09-29 各项目 README 的描述：dsh-market 在 Web UI 设置页提供插件市场，dsh-web 增强 Web 工作台（标注需要 DSH 0.2.0-rc.1 及以上），dsh-TUI 提供终端界面（public beta），dsh-mnemon 增加跨会话记忆，ModLens 给纯文本模型补视觉能力。

插件生态变化快，安装命令和版本要求以各项目 README 为准。Awesome 列表明确提醒：进入精选列表不等于完成安全审查，插件可能读取工作区、使用本机凭据并访问网络。安装前查看最近提交、Issue、许可证和权限需求，固定版本或 commit，在不含密钥的测试项目中试用，并保留卸载和回滚路径。

下一步先用小仓库完整跑一遍

第一次只读任务跑完后，先核对它读到的仓库结构和权限提示，再试修改代码的任务。需要换模型可查模型配置文档；想在脚本里调用它，可看 Python SDK。
