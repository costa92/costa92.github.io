第 3 / 36 节 · 入门与案例

打开 Web UI 后，要先配置模型、选中工作区，才能发出第一条任务。这篇从启动服务走到提交任务，再看本地插件怎么挂进去。

Harness 是 agent 的运行外壳

DeepSeek Harness 的命令行入口是 dsh。它基于 Cordis 把文件、命令、会话和权限等能力装成插件；定位与分层见第 1 篇 项目介绍。

Web UI 把这些能力搬进浏览器，同时要求你显式指定本地项目。服务启动后并不会自动选中一个项目；工作区必须由你主动添加和选择。

图：根据 DeepSeek Harness 官方插件、生命周期和能力分层文档绘制的解释图，不是项目官方原图。

一条 npx 命令就能启动 Web UI

最省事的方式是直接通过 npm 启动。机器上需要先安装 Node.js。

图：官方 Quickstart 页面展示的模型配置、工作区选择和任务运行路径。

npx @deepseek-ai/dsh web

这条命令选择 web profile。按与本系列相同源码版本的官方架构文档，它先装共享基础组合，再加入浏览器应用；profile、home 与命令行补丁还可能改变最终插件树。本文只走默认启动路径，没有实测这些补丁的叠加顺序。

默认情况下，服务会监听 http://127.0.0.1:3080。命令行会打印实际访问地址；打开它，就能进入 Web UI。

如果你希望从源码运行，可以使用官方仓库：

git clone https://github.com/deepseek-ai/deepseek-harness.git
cd deepseek-harness
pnpm install
pnpm run build
pnpm dsh web

dsh 会把“启动命令所在的目录”作为默认文件系统位置，这一点容易忽略。准备操作某个项目时，最好先进入那个项目目录，再启动服务。不过这还不等于 Web UI 已经选中了工作区，后面仍需要手动确认。

模型保存后立即可用

进入 设置 → 模型，填入 DeepSeek API Key，然后保存。

官方 Quickstart 写明：保存后，模型路由立即可用，不需要重启服务，试用时改完就能发任务。

如果你不打算使用 DeepSeek，也可以继续看官方的模型配置指南，那里介绍了其他提供方和自定义 OpenAI 兼容端点。建议把 API Key 当作凭据管理，不要写进项目代码、提交到 Git，或复制进公开截图。

不选工作区就不能发任务

点击 选择工作区，添加启动 dsh 时所在的项目目录，然后选中它。

工作区决定 agent 默认在哪个项目里工作，但它不是隔离边界：命令和插件仍可能读到工作区之外。没有选中工作区时，会话输入框不会开放，界面要求先明确“agent 可以在哪个项目里工作”。

第一次使用时，建议选一个专门的测试目录，别直接指向生产仓库。先放入一个包含 README 和少量源文件的小项目，确认读取、编辑和命令执行都符合预期，再扩大权限范围。

第一条任务先只读仓库

启动一个新会话，发送这条官方示例提示词：

Summarize this repository and identify its main packages.

这条提示词风险低、结果容易核对，agent 只需要阅读仓库并整理结构，不必一上来就修改代码。正常情况下，agent 可以读取和编辑工作区文件、运行命令、委派工作，并维护一个执行计划。

当某项操作在当前权限策略下需要审批时，Web UI 会先询问你。遇到文件写入、命令执行或其他有副作用的动作，先看清楚目标路径和命令，再决定是否批准；不要为了让流程“自动跑完”而无条件放行。

工作区和审批比打开页面更重要

能打开页面，只说明服务已经启动。发送任务前还要选中工作区；任务运行时，写文件和执行命令是否需要人确认，取决于当前权限策略。第一次试用可以沿用上面的只读任务，先核对它实际访问了哪些文件。

Harness 把能力都装进插件

DeepSeek Harness 把能力拆成插件：插件是导出 apply 函数的 TypeScript 模块，Harness 加载时传入 ctx，插件通过它注册工具、监听事件、提供 LLM 适配器或暴露服务，再由 cordis.yml 插入运行配置。

最小插件见第 1 篇 项目介绍；卸载时自动清理见第 4 篇，inject 依赖见第 5 篇，事件见第 6 篇，插件树见第 7 篇，可替换的服务提供者见第 8 篇。

想先挂一个本地插件试试，分两步。第一步在 cordis.yml 里插入插件，官方教程的最小示例要求 name 写绝对路径：

- insert:
    - id: hello
      name: '/absolute/path/to/deepseek-harness/scratch-plugin/src/my-plugin.ts'

第二步在源码仓库根目录用 patch 启动 Web UI，写法沿用第 3 篇实测跑通的命令：

pnpm dsh --profile web --patch ./scratch-plugin/cordis.yml

需要加 --no-open、--port 时，--patch 必须放在它们之前，否则启动报 unknown option '--patch'，完整过程见第 3 篇 发布记录查询插件实战。

适合本地试用，暂不适合生产

第一次试用时，选一个测试仓库，确认工作区路径和审批提示符合预期，再让 agent 读写文件或运行命令。

DeepSeek Harness 暂时不适合追求长期稳定 API 和生产部署的团队，预览版与安全审计方面的风险见第 1 篇 项目介绍。试用时固定依赖版本，在隔离环境中运行，并检查每次升级带来的行为变化。

先装插件市场，再按需加插件

GitHub 上已经出现了一个社区维护的 Awesome DSH Plugin 精选列表，项目 README 还提供了插件市场和插件发现工具。

下面这份推荐按“第一次使用能获得什么”来排，不把 GitHub Star 数量直接等同于质量；插件生态仍在快速变化，建议安装前查看最近提交、Issue、许可证和权限需求。

以下 dsh 指已全局安装的命令；用 npx 启动的读者换成 npx -y @deepseek-ai/dsh，从源码运行的读者换成 pnpm dsh。

1. dsh-market：先装插件市场

dsh-market 把社区插件集中到 Web UI 的 Settings → Plugin Market，支持搜索、分类、安装、升级、卸载和主题切换，并读取 Awesome DSH Plugin 的精选目录；第一次安装后重启 dsh web，再从设置页浏览插件。

图：dsh-market README 展示的插件市场界面。

dsh plugin --profile web add dshmarket

2. dsh-web：一套完整的 Web 工作台增强

dsh-web（原名 dsh-web-ui）提供任务看板、Git 图谱、右侧文件/变更面板、移动端远程、SSH 运维和使用统计。

截至 2026-09-29，README 推荐安装下面的聚合包（原聚合包 @linxin666/dsh-web-ui-all 已停止更新），并标注需要 DSH 0.2.0-rc.1 及以上；它的改动面较大，先在测试工作区安装，安装后重启 dsh web。

dsh plugin --profile web add @linxin666/dsh-web-all@latest

图：dsh-web README 在 2026-08-15 展示的任务看板、Git 图谱和 Web 工作台。

3. dsh-TUI：喜欢终端就选它

dsh-TUI 提供全屏终端界面，包含流式 Markdown、工具卡片、文件引用、历史搜索、会话恢复、上下文进度和 Token 统计等能力，适合习惯 SSH 或想在终端里操作多个项目的人。项目标注为 public beta，安装前确认终端环境和 pnpm 版本满足其 README 的要求。

npm install -g @deepseek-ai/dsh @deepseek-harness-tui/dsh-tui
dsh-tui

图：dsh-TUI README 中的终端交互与快速开始信息。

4. dsh-mnemon：需要跨会话记忆时再装

dsh-mnemon 把 Mnemon 接入 DeepSeek Harness，给 agent 增加运行时记忆、项目文档、长期 Memory Space、语义检索、知识图谱和侧边栏工作台等持久化记忆层，还支持多个接入 Mnemon 的 agent 共享长期记忆。

长期 Memory Space 需要安装 Mnemon CLI（也可在 Memory Spaces 页改用其他提供方），只想快速试用可以先跳过。

dsh plugin --profile web add dsh-mnemon

图：dsh-mnemon README 展示的本地记忆、文档和知识图谱工作台。

5. ModLens：给纯文本模型补视觉能力

ModLens 让 DeepSeek 等纯文本模型接收粘贴进对话的图片，再通过视觉引擎输出 OCR、布局和结构化证据，前端截图分析、UI 还原、错误提示识别等场景比较实用。

下面的版本号取自截至 2026-09-29 的安装文档示例，升级以安装文档为准；它会用到额外的视觉模型或已有 CLI 凭据，不要把含有密钥、客户资料或内部代码的图片交给不清楚数据流向的视觉服务。

dsh plugin --profile web add @liustack/modlens@3.26.5

图：ModLens README 对“为纯文本模型补充视觉能力”的说明。

建议的安装顺序

如果你刚开始使用，按下面的顺序最省事：先装 dsh-market 发现插件；只用 Web UI 就试 dsh-web，偏终端就试 dsh-TUI；确认工作流稳定后，再按需要增加 dsh-mnemon 或 ModLens。

所有社区插件都应视为第三方代码。Awesome 列表明确提醒：进入精选列表不等于完成安全审查，插件可能读取工作区、使用本机凭据并访问网络。稳妥起见，固定版本或 commit，在不含密钥的测试项目中试用，并保留卸载和回滚路径。

下一步先用小仓库完整跑一遍

第一次只读任务跑完后，先核对它读到的仓库结构和权限提示，再试修改代码的任务。需要换模型可查模型配置文档；想在脚本里调用它，可看 Python SDK。
