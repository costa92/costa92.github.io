kubeconfig 多集群管理

kubectl 通过 kubeconfig 找到 API Server 和身份凭据。一个 context 组合了集群、用户和默认命名空间。多集群操作最容易出错的地方不是命令语法，而是把正确的命令发到错误的 context。

先看，再执行

以下命令只读取本机配置或集群状态：

kubectl config get-contexts
kubectl config current-context
kubectl config view --minify
kubectl get namespaces

get-contexts 中的 * 表示当前 context。view --minify 只展示当前选择的集群与用户配置，但输出仍可能包含连接信息；不要把完整 kubeconfig 或其中的证书、令牌发到公开 Issue 和聊天记录。

若已有多个 context，推荐在一次性查看时显式指定目标，而非先改变全局默认值：

kubectl --context=YOUR_CONTEXT get nodes
kubectl --context=YOUR_CONTEXT -n k8s-lab get pods

把 YOUR_CONTEXT 替换为 kubectl config get-contexts 中实际存在的名称。确需持续切换时，使用 kubectl config use-context YOUR_CONTEXT，执行后再次运行 kubectl config current-context。对创建、更新和删除命令，最好同时写明 --context 与 -n，减少终端状态变化带来的误操作。

多个 kubeconfig 文件

KUBECONFIG 环境变量可以列出多个配置文件，kubectl 会合并读取。合并时同名集群、用户或 context 可能产生覆盖或优先级问题，因此应检查合并后的 kubectl config get-contexts 和目标 server。只使用可信来源的 kubeconfig：它包含访问凭据，也可能包含可执行的认证插件配置。

本页不创建新集群；仅有一个 minikube context 时，也可以练习目标核对流程。集群操作权限由 kubeconfig 中的身份及 RBAC 决定，切换 context 不会自动获得额外权限。

详见 官方多集群访问教程与 kubeconfig 组织方式。
