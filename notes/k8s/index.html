这个专栏写什么

这里的 63 篇笔记，每一篇都对应一次在集群里真正做过的实验，不是对官方文档的转述。写法基本固定为三步：先把要验证的行为说清楚，再在集群里跑一遍、贴出真实输出，最后故意把配置写错，看报错长什么样、该去哪里查。比如 Deployment 滚动更新逐秒记录新旧 Pod 的数量，ConfigMap 与 Secret量出卷文件改动要多久才生效，DNS 故障定位数出一个短名到底发出几次查询。

官方文档讲的是”应该怎样”，这些笔记更关心”实际怎样”：默认值是多少、状态多久才变、错误信息原文是什么。碰到文档没写清、我也没在源码里确认的地方，正文会标”推测”，读的时候可以把它当成待核实的结论。

实验环境

除非笔记开头另有说明，下文所有输出都来自同一个集群：

项目配置
集群kind 建的三节点集群：1 个控制平面，2 个 worker
Kubernetesv1.31.0，kubectl 客户端 v1.30.0
容器运行时containerd 1.7.18，节点为 cgroup v2
网络Calico v3.32.1 替换 kindnet，kube-proxy 为 iptables 模式，CoreDNS v1.11.1
附加组件metrics-server v0.8.1、Traefik v3.7.9、Gateway API CRD v1.5.0
存储默认 StorageClass standard，由 local-path 提供
节点资源每个节点可分配 28 核 CPU、约 61 GiB 内存

集群怎么从零建出来、这些组件装在哪里、kind 和 minikube、k3d 的区别，都写在本地实验环境里。想照着做的话，先读那一篇。

kubeadm 安装、证书检查、升级检查这几篇讲的是真实主机上的 kubeadm 集群，环境在各篇开头单独写明。Helm 相关的四篇用的客户端是 Helm v4.3.0。

输出里的约定

  • 每篇的资源都放在单独的 notes-lab namespace 里，做完按文末的”清理”一节删掉，不影响集群里的其他东西。
  • 节点名简化成 control-plane、worker、worker2；Pod IP、Cluster IP、节点 IP 换成 <pod-ip>、<cluster-ip>、<node-ip> 这样的占位符。
  • 时间默认是 UTC；个别笔记的脚本或控制器日志用的是 UTC+8，会在开头注明。笔记里的耗时都是这台机器上的实测值，换一台机器、换一个版本，具体数字会变。

阅读路线

左侧目录按五章排列，从上到下读是最顺的路线。

基础概念（3 篇）：先读概念和术语，弄清”期望状态”和控制器在做什么；再读集群组件和 API 对象与控制器关系，知道一个 Deployment 提交后经过了哪些组件。

动手入门（14 篇）：从本地实验环境开始，接着是 Pod、Deployment、标签、探针、Service 和 Ingress。这一章读完，能独立把一个无状态服务部署出来并对外暴露。

配置与运维（17 篇）：ConfigMap、Secret、存储、StatefulSet、Helm、RBAC 和安全上下文。最后一篇常见故障排查把前面复现过的故障串成一张排查顺序表，可以当速查用。

进阶实践（21 篇）：kubectl 的高级用法、调度和亲和性、网络策略与 CNI、HPA、Kustomize、CRD 和 Operator。这些篇目相互独立，按需挑着读即可。

集群搭建（8 篇）：kubeadm 安装与高可用、升级、证书、etcd 快照、多集群 kubeconfig 和可观测性，最后是一篇按 CKA 大纲整理的原创练习路线。

怎么用这些笔记

如果只是遇到了具体问题，直接用搜索或左侧目录找对应主题，不少笔记都有”排查顺序”或”排查清单”一节。如果是系统学习，建议自己建一个同样的 kind 集群，边读边敲命令。输出对不上的时候，先对照上面的环境表看版本，很多行为差异来自版本和 CNI，而不是命令写错了。
