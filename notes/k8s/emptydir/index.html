emptyDir 临时卷

emptyDir 在 Pod 分配到节点时创建，Pod 内的容器可以挂载同一个卷共享文件。容器重启通常不会清空该卷；Pod 从节点删除后，卷中数据会被清除。需要跨 Pod 重建保留数据时，应使用 PVC，而不是 emptyDir。

两个容器共享文件

确认当前上下文是实验集群，将以下内容保存为 emptydir-demo.yaml：

apiVersion: v1
kind: Pod
metadata:
  name: emptydir-demo
  namespace: k8s-lab
spec:
  volumes:
    - name: shared
      emptyDir:
        sizeLimit: 64Mi
  containers:
    - name: writer
      image: busybox:1.36
      command: ["sleep", "3600"]
      volumeMounts:
        - name: shared
          mountPath: /shared
      resources:
        requests:
          cpu: 10m
          memory: 16Mi
    - name: reader
      image: busybox:1.36
      command: ["sleep", "3600"]
      volumeMounts:
        - name: shared
          mountPath: /shared
      resources:
        requests:
          cpu: 10m
          memory: 16Mi
kubectl config current-context
kubectl apply -f emptydir-demo.yaml
kubectl -n k8s-lab wait --for=condition=Ready pod/emptydir-demo --timeout=120s
kubectl -n k8s-lab exec emptydir-demo -c writer -- sh -c 'echo shared-data > /shared/message'
kubectl -n k8s-lab exec emptydir-demo -c reader -- cat /shared/message

读取结果应为 shared-data。两个容器共享的是同一 Pod 的卷，不需要通过网络传输。

验证生命周期

kubectl delete -f emptydir-demo.yaml
kubectl apply -f emptydir-demo.yaml
kubectl -n k8s-lab wait --for=condition=Ready pod/emptydir-demo --timeout=120s
kubectl -n k8s-lab exec emptydir-demo -c reader -- sh -c 'if test -e /shared/message; then echo unexpected-data; else echo volume-is-empty; fi'
kubectl delete -f emptydir-demo.yaml

重新创建后的 Pod 应输出 volume-is-empty。即使名称相同，它也是一个新 Pod，获得一个新的 emptyDir。默认卷使用节点的临时存储；若设置 medium: Memory，卷会使用内存，写入的数据计入写入容器的内存使用量。sizeLimit 不等同于备份或持久化保障，也可能受节点临时存储剩余容量限制。

详见 Kubernetes 卷文档。
