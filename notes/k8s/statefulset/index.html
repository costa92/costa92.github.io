有稳定身份的 Pod

Deployment 的副本通常可互换；StatefulSet 为每个副本提供稳定的序号、网络身份，并可通过 volumeClaimTemplates 为每个 Pod 创建单独的 PVC。它适合需要稳定身份或独立存储的应用，但不会替数据库实现复制、备份或故障恢复。

先完成持久卷实验并确认 StorageClass 可用。保存为 stateful.yaml：

apiVersion: v1
kind: Service
metadata:
  name: stateful-demo
spec:
  clusterIP: None
  selector:
    app: stateful-demo
  ports:
    - name: web
      port: 80
---
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: stateful-demo
spec:
  serviceName: stateful-demo
  replicas: 2
  selector:
    matchLabels:
      app: stateful-demo
  template:
    metadata:
      labels:
        app: stateful-demo
    spec:
      containers:
        - name: nginx
          image: nginx:1.27
          ports:
            - containerPort: 80
              name: web
          volumeMounts:
            - name: data
              mountPath: /usr/share/nginx/html
  volumeClaimTemplates:
    - metadata:
        name: data
      spec:
        accessModes: ["ReadWriteOnce"]
        resources:
          requests:
            storage: 1Gi
kubectl apply -f stateful.yaml
kubectl rollout status statefulset/stateful-demo
kubectl get pods -l app=stateful-demo
kubectl get pvc
kubectl exec stateful-demo-0 -- sh -c 'echo pod-0 > /usr/share/nginx/html/index.html'
kubectl delete pod stateful-demo-0
kubectl wait --for=condition=Ready pod/stateful-demo-0 --timeout=120s
kubectl exec stateful-demo-0 -- cat /usr/share/nginx/html/index.html

新 Pod 仍叫 stateful-demo-0，且重新挂载自己的 PVC；文件应保留。每个副本的 PVC 名类似 data-stateful-demo-0，不要误以为两个 Pod 共用一个卷。Headless Service 为每个 Pod 提供可发现的 DNS 名称；实际解析还受 Pod 就绪状态影响。

删除 StatefulSet 通常不会自动删除由其模板生成的 PVC。实验结束先运行 kubectl delete -f stateful.yaml，确认不再需要数据后，再检查并删除 data-stateful-demo-0、data-stateful-demo-1。

参考：StatefulSets、Persistent Volumes。
