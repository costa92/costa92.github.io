从整份 JSON 里只取需要的字段

kubectl 常用命令介绍了 get -o yaml 和单字段查询。排查时经常要把一批对象的几个字段排成列表，-o jsonpath 可以直接从 API 返回的 JSON 中取值，不用装别的工具。它看上去简单，但有几处行为和直觉不一样：字段缺失时静默输出空、过滤条件碰到缺失字段一律不匹配、方括号里的点号照样当路径分隔符。下面用一组小对象把这些行为逐条跑一遍。

下文的输出来自一个三节点 kind 集群（Kubernetes v1.31.0，containerd 1.7.18），实验放在单独的 notes-lab namespace 里。JSONPath 是 kubectl 在客户端解析和执行的，所以客户端版本更要紧：这里用的是 kubectl v1.30.0。节点名简化成 control-plane、worker、worker2，IP 用占位符代替。

实验对象

kubectl create namespace notes-lab
until kubectl -n notes-lab get serviceaccount default >/dev/null 2>&1; do sleep 1; done
kubectl -n notes-lab apply -f objects.yaml

四个 busybox Pod、一个单副本 nginx Deployment 和一个 ConfigMap。标签和注解刻意设计得参差不齐，好让「有这个字段」和「没有这个字段」都能出现：

基本语法：列表、range 和换行

get pods 返回的是一个 List，Pod 都在 .items 数组里。[*] 取数组的全部元素，多个结果之间用空格连接：

$ kubectl -n notes-lab get pods -o jsonpath='{.items[*].metadata.name}'; echo "<END>"
api-1 api-2 nginx-5b566885b5-7q6z6 stuck-1 web-1<END>

jsonpath 输出末尾不带换行，<END> 直接贴在了最后一个名字后面。交互使用时在模板末尾加 {"\n"}。

想一行一个对象，用 range … end，{"\t"} 和 {"\n"} 输出制表符和换行：

$ kubectl -n notes-lab get pods -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.spec.nodeName}{"\t"}{.status.phase}{"\n"}{end}'
api-1	worker	Running
api-2	worker	Running
nginx-5b566885b5-7q6z6	worker	Running
stuck-1		Pending
web-1	worker2	Running

stuck-1 没被调度，没有 spec.nodeName 字段，这一格是空的，两个制表符挨在一起。用 range 时每个对象各占一行，空格子不会把别的行带乱。不用 range、直接 [*] 取同一个字段，就是另一回事了：

$ kubectl -n notes-lab get pods -o jsonpath='{.items[*].spec.nodeName}{"\n"}'
worker worker worker worker2
$ kubectl -n notes-lab get pods -o jsonpath='{.items[*].spec.nodeName}' | wc -w
4

5 个 Pod 只出来 4 个值，缺字段的那个直接被跳过，不会留一个空位。如果分别用 {.items[*].metadata.name} 和 {.items[*].spec.nodeName} 取两列再按位置拼起来，从 stuck-1 开始就会错位，web-1 会被配上 worker 而不是 worker2。多个字段要对齐时，一律用 range。

嵌套数组可以再套一层 range，比如列出每个 Pod 的所有容器：

$ kubectl -n notes-lab get pods -o jsonpath='{range .items[*]}{.metadata.name}:{range .spec.containers[*]} {.name}={.image}{end}{"\n"}{end}'
api-1: app=busybox:1.36 sidecar=busybox:1.36
api-2: app=busybox:1.36
nginx-5b566885b5-7q6z6: nginx=nginx:alpine
stuck-1: app=busybox:1.36
web-1: app=busybox:1.36

路径要跟对象的形状对上

get pod <名称> 返回单个对象，没有 .items；get pods 返回列表，顶层也没有 .metadata.name。把路径用反了，kubectl 不报错，什么也不输出，退出码还是 0：

$ kubectl -n notes-lab get pod api-1 -o jsonpath='{.metadata.name}{"\t"}{.status.phase}{"\n"}'
api-1	Running
$ kubectl -n notes-lab get pod api-1 -o jsonpath='{.items[*].metadata.name}'; echo "<END>"
<END>
$ kubectl -n notes-lab get pods -o jsonpath='{.metadata.name}'; echo "<END>"
<END>

拼写错误也一样：{.spec.nodeNmae} 输出空、退出码 0。这是 --allow-missing-template-keys 默认为 true 的结果，后面专门讲。拿不到值的时候，先 -o json 看一眼真实结构，比反复改模板快。

下标、切片、并集与递归

下标从 0 开始，支持负数；切片是 [start:end:step]，不含 end：

$ kubectl -n notes-lab get pods -o jsonpath='{.items[0].metadata.name} {.items[-1].metadata.name}{"\n"}'
api-1 web-1
$ kubectl -n notes-lab get pods -o jsonpath='{.items[1:3].metadata.name}{"\n"}'
api-2 nginx-5b566885b5-7q6z6
$ kubectl -n notes-lab get pods -o jsonpath='{.items[::2].metadata.name}{"\n"}'
api-1 nginx-5b566885b5-7q6z6 web-1
$ kubectl -n notes-lab get pods -o jsonpath='{.items[0,2].metadata.name}{"\n"}'
api-1 nginx-5b566885b5-7q6z6

列表的顺序就是 API 返回的顺序，这里是按名字排的。依赖 [0]、[-1] 取「最新」或「第一个」对象是靠不住的，需要的话配合后面的 --sort-by。

空列表上用下标会报错，[*] 则安静地输出空，脚本里两种情况都要考虑：

$ kubectl -n notes-lab get pods -l app=nosuch -o jsonpath='{.items[*].metadata.name}'; echo "<END exit=$?>"
<END exit=0>
$ kubectl -n notes-lab get pods -l app=nosuch -o jsonpath='{.items[0].metadata.name}'; echo "<END exit=$?>"
error: error executing jsonpath "{.items[0].metadata.name}": Error executing template: array index out of bounds: index 0, length 0. Printing more information for debugging the template:
	template was:
	object given to jsonpath engine was:
<END exit=1>

（object given to jsonpath engine was: 后面还有整个对象的转储，这里省略了，见下文「报错会把整个对象打出来」。）

并集 ['a','b'] 一次取多个字段。注意输出是按字段分组的：先是 5 个名字，再是 5 个 phase，而不是一个 Pod 一组：

$ kubectl -n notes-lab get pods -o jsonpath="{.items[*]['metadata.name','status.phase']}{\"\n\"}"
api-1 api-2 nginx-5b566885b5-7q6z6 stuck-1 web-1 Running Running Running Pending Running

这条命令外层用的是双引号。习惯性地全用单引号，内层的单引号会被 shell 吃掉，kubectl 收到的是 [metadata.name,status.phase]，当成了数组下标：

$ kubectl -n notes-lab get pods -o jsonpath='{.items[*]['metadata.name','status.phase']}{"\n"}'
error: error parsing jsonpath {.items[*][metadata.name,status.phase]}{"\n"}, invalid array index metadata.name

递归下降 .. 在整棵树里找同名字段，结果往往比想象的多：

$ kubectl -n notes-lab get pod api-1 -o jsonpath='{..image}{"\n"}'
busybox:1.36 busybox:1.36 docker.io/library/busybox:1.36 docker.io/library/busybox:1.36
$ kubectl -n notes-lab get pod api-1 -o jsonpath='{..name}{"\n"}'
api-1 kube-api-access-ggl77 kube-root-ca.crt app kube-api-access-ggl77 sidecar kube-api-access-ggl77 app kube-api-access-ggl77 sidecar kube-api-access-ggl77

..image 同时命中了 spec.containers[*].image（写在清单里的 busybox:1.36）和 status.containerStatuses[*].image（运行时解析后的 docker.io/library/busybox:1.36）；..name 把 Pod 名、卷名、ConfigMap 名、容器名、volumeMount 名全捞了出来。.. 适合「这个值到底藏在哪」的探索，正式脚本里写全路径。

过滤：能写什么，不能写什么

?() 按条件筛数组元素，@ 代表当前元素：

$ kubectl -n notes-lab get pods -o jsonpath='{.items[?(@.status.phase=="Pending")].metadata.name}{"\n"}'
stuck-1
$ kubectl -n notes-lab get pods -o jsonpath='{.items[?(@.metadata.labels.tier=="backend")].metadata.name}{"\n"}'
api-1 api-2
$ kubectl -n notes-lab get pods -o jsonpath='{range .items[?(@.status.phase=="Running")]}{.metadata.name}{"\n"}{end}'
api-1
api-2
nginx-5b566885b5-7q6z6
web-1

最常用的是在数组里按 type 挑一项，比如节点的 Ready 状态和 InternalIP（只读查询）：

$ kubectl get nodes -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.status.conditions[?(@.type=="Ready")].status}{"\t"}{.status.addresses[?(@.type=="InternalIP")].address}{"\n"}{end}'
control-plane	True	<node-ip>
worker	True	<node-ip>
worker2	True	<node-ip>

只写字段不写比较，表示「这个字段存在」，这一条是能用的：

$ kubectl -n notes-lab get pods -o jsonpath='{.items[?(@.metadata.labels.team)].metadata.name}{"\n"}'
api-1 web-1

字段不存在时，比较一律不成立

反过来想找「team 不是 pay 的 Pod」，期望是 api-2、nginx、stuck-1、web-1 四个：

$ kubectl -n notes-lab get pods -o jsonpath='{.items[?(@.metadata.labels.team!="pay")].metadata.name}{"\n"}'
web-1

只出来 web-1。没有 team 标签的三个 Pod 不参与比较，!= 对它们也不成立。同样，想用空字符串找未调度的 Pod，也找不到：

$ kubectl -n notes-lab get pods -o jsonpath='{.items[?(@.spec.nodeName=="")].metadata.name}{"\n"}'; echo "<END>"

<END>
$ kubectl -n notes-lab get pods -o jsonpath='{.items[?(@.spec.nodeName!="worker")].metadata.name}{"\n"}'
web-1

第二条想要的是「不在 worker 上的 Pod」，应该包括未调度的 stuck-1，结果同样把它漏掉了。

那给存在判断取个反呢？不行，! 不是合法字符：

$ kubectl -n notes-lab get pods -o jsonpath='{.items[?(!@.metadata.labels.team)].metadata.name}{"\n"}'
error: error parsing jsonpath {.items[?(!@.metadata.labels.team)].metadata.name}{"\n"}, unrecognized character in action: U+0021 '!'

所以 jsonpath 没法表达「字段不存在」（标签与注解里查孤儿 Pod 就碰到了这个问题），具体就是这两点：存在判断不能取反，比较运算又会跳过缺字段的元素。标签恰好可以绕开，标签选择器本身支持 !key：

$ kubectl -n notes-lab get pods -l 'tier=frontend,!team' -o name
pod/nginx-5b566885b5-7q6z6
pod/stuck-1

但 spec.nodeName、ownerReferences 这类普通字段没有对应的选择器，只能换 go-template 或 jq，下文有写法。

不支持的写法和对应报错

下面几条都是照着别的 JSONPath 实现或 jq 的习惯写出来的，kubectl 全部拒绝：

$ kubectl -n notes-lab get pods -o jsonpath='{.items[?(@.metadata.name=~/^api/)].metadata.name}{"\n"}'
error: error parsing jsonpath {.items[?(@.metadata.name=~/^api/)].metadata.name}{"\n"}, unrecognized character in action: U+007E '~'
$ kubectl -n notes-lab get pods -o jsonpath='{.items[?(@.status.phase=="Running" && @.metadata.labels.tier=="backend")].metadata.name}{"\n"}'
error: error parsing jsonpath {.items[?(@.status.phase=="Running" && @.metadata.labels.tier=="backend")].metadata.name}{"\n"}, unrecognized character in action: U+0026 '&'
$ kubectl -n notes-lab get pods -o jsonpath='{.items[?(@.status.phase=="Pending" || @.metadata.labels.tier=="backend")].metadata.name}{"\n"}'
error: error parsing jsonpath {.items[?(@.status.phase=="Pending" || @.metadata.labels.tier=="backend")].metadata.name}{"\n"}, unrecognized character in action: U+007C '|'
$ kubectl -n notes-lab get pods -o jsonpath='{.items[?(@.metadata.labels.tier in ["backend"])].metadata.name}{"\n"}'
error: error parsing jsonpath {.items[?(@.metadata.labels.tier in ["backend"])].metadata.name}{"\n"}, invalid array index "backend"
$ kubectl -n notes-lab get pods -o jsonpath='{.items[?(@.spec.containers[*].name=="sidecar")].metadata.name}{"\n"}'
error: error executing jsonpath "{.items[?(@.spec.containers[*].name==\"sidecar\")].metadata.name}{\"\\n\"}": Error executing template: can only compare one element at a time. Printing more information for debugging the template:
$ kubectl -n notes-lab get pods -o jsonpath='{length(.items)}{"\n"}'
error: error executing jsonpath "{length(.items)}{\"\\n\"}": Error executing template: unrecognized identifier length(. Printing more information for debugging the template:

归纳一下：

想做的事写法结果
正则匹配=~解析错误 '~'
取反!@.x解析错误 '!'
与 / 或&&、||解析错误 '&'、'|'
集合包含in [...]当成数组下标，invalid array index
过滤里用通配@.a[*].b==can only compare one element at a time
求长度length(...)unrecognized identifier
求长度.items.length不报错，输出空

最后一行最危险：.length 被当成一个叫 length 的字段，找不到就静默返回空。数值比较 >、== 是支持的，例如 ?(@.status.containerStatuses[0].restartCount==0) 能筛出 4 个已启动的 Pod（stuck-1 没有 containerStatuses，又一次被跳过）。

多个条件的「与」能不能靠连续两次过滤凑出来？不能。第一次过滤的结果被逐个当成单个对象，第二个 [?()] 拿到的是一个 map，不是数组：

$ kubectl -n notes-lab get pods -o jsonpath='{.items[?(@.metadata.labels.tier=="backend")][?(@.metadata.labels.team=="pay")].metadata.name}{"\n"}'
error: error executing jsonpath "{.items[?(@.metadata.labels.tier==\"backend\")][?(@.metadata.labels.team==\"pay\")].metadata.name}{\"\\n\"}": Error executing template: map[apiVersion:v1 kind:Pod metadata:map[…] … startTime:…]] is not array or slice and cannot be filtered. Printing more information for debugging the template:

（错误信息里内嵌了整个 Pod 对象，这里用 … 截掉了。）

键名里带点号：转义，方括号也救不了

注解和标签的键常常形如 example.com/owner、kubernetes.io/hostname，其中的点号会被当成路径分隔符：

$ kubectl -n notes-lab get pod api-1 -o jsonpath='{.metadata.annotations.example.com/owner}{"\n"}'; echo "<END>"

<END>
$ kubectl -n notes-lab get pod api-1 -o jsonpath='{.metadata.annotations.example\.com/owner}{"\n"}'
alice

不转义时 kubectl 去找 annotations.example 下面的 com/owner，找不到，又是静默输出空。用 \. 转义就对了，斜杠不用转义。ConfigMap 里 app.properties 这种键也是一样：

$ kubectl -n notes-lab get cm app-config -o jsonpath='{.data.app\.properties}'
log.level=info

用过 jq 或标准 JSONPath 的人会想到方括号写法 ['example.com/owner']。在 kubectl 里它不起作用：

$ kubectl -n notes-lab get pod api-1 -o jsonpath="{.metadata.annotations['example.com/owner']}" | od -c | head -3
0000000
$ kubectl -n notes-lab get pod api-1 -o jsonpath="{.metadata.annotations['example\.com/owner']}{\"\n\"}"
alice
$ kubectl -n notes-lab get pod api-1 -o jsonpath="{['metadata.name']}{\"\n\"}"
api-1

od 显示输出是 0 字节。最后一条说明了原因：kubectl 把方括号里的字符串仍然按点号切成路径，['metadata.name'] 等价于 .metadata.name。前面并集 ['metadata.name','status.phase'] 能取到嵌套字段，靠的也是这个。所以方括号里同样要写 \.，官方文档的函数表里给的例子正是 {['name\.type']}。这一行为在标准 JSONPath 里是不成立的，从别的工具搬模板过来时要留意。

方括号里还只能用单引号。kubectl 的解析器（k8s.io/client-go/util/jsonpath/parser.go）用正则 ^'([^']*)'$ 判断方括号里是不是键名，匹配上之后把引号里的内容重新当作 .key 路径解析，所以点号照样被切开；双引号不匹配这条正则，就被当成数组下标：

$ kubectl -n notes-lab get pod api-1 -o jsonpath="{.metadata.annotations[\"example.com/owner\"]}"
error: error parsing jsonpath {.metadata.annotations["example.com/owner"]}, invalid array index "example.com/owner"

前面过滤里写 in ["backend"] 报 invalid array index "backend"，也是同一个原因。

转义后的路径在 range 里照常工作，没有这个注解的 Pod 留空：

$ kubectl -n notes-lab get pods -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.metadata.annotations.example\.com/owner}{"\n"}{end}'
api-1	alice
api-2	bob
nginx-5b566885b5-7q6z6	
stuck-1	
web-1

字段缺失：–allow-missing-template-keys

前面多次出现「找不到就输出空」，来源是这个参数。kubectl get --help 的说明：

   --allow-missing-template-keys=true:
If true, ignore any errors in templates when a field or map key is missing in the template. Only applies to golang and jsonpath output formats.

改成 false，拼错的字段终于会报错，适合脚本里做防御：

$ kubectl -n notes-lab get pod api-1 -o jsonpath='{.spec.nodeNmae}{"\n"}' --allow-missing-template-keys=false
error: error executing jsonpath "{.spec.nodeNmae}{\"\\n\"}": Error executing template: nodeNmae is not found. Printing more information for debugging the template:

但它是全有或全无的。对列表来说，只要有一个对象缺这个字段，整条命令就失败，一行也不输出：

$ kubectl -n notes-lab get pods -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.spec.nodeName}{"\n"}{end}' --allow-missing-template-keys=false
error: error executing jsonpath "{range .items[*]}{.metadata.name}{\"\\t\"}{.spec.nodeName}{\"\\n\"}{end}": Error executing template: nodeName is not found. Printing more information for debugging the template:

过滤条件同样受它影响。前面说「缺字段的元素不参与比较」，那是默认值 true 下的行为；改成 false 后，过滤里引用的字段只要有一个对象缺失，整条命令就报错，只写存在判断的过滤不受影响：

$ kubectl -n notes-lab get pods -o jsonpath='{.items[?(@.metadata.labels.team!="pay")].metadata.name}{"\n"}' --allow-missing-template-keys=false
error: error executing jsonpath "{.items[?(@.metadata.labels.team!=\"pay\")].metadata.name}{\"\\n\"}": Error executing template: team is not found. Printing more information for debugging the template:
$ kubectl -n notes-lab get pods -o jsonpath='{.items[?(@.metadata.labels.nosuch!="x")].metadata.name}{"\n"}' --allow-missing-template-keys=false
error: error executing jsonpath "{.items[?(@.metadata.labels.nosuch!=\"x\")].metadata.name}{\"\\n\"}": Error executing template: nosuch is not found. Printing more information for debugging the template:
$ kubectl -n notes-lab get pods -o jsonpath='{.items[?(@.metadata.labels.team)].metadata.name}{"\n"}' --allow-missing-template-keys=false
api-1 web-1

所以它能区分「路径写错了」和「有值」，却没法给你「哪些对象缺字段」的清单。按帮助说明，它只作用于 go-template 和 jsonpath；实测 custom-columns 加上这个参数照样把缺失显示成 <none>。

一个真实的脚本坑：readyReplicas 消失

Deployment 缩到 0 后，status.readyReplicas 不是变成 0，而是整个字段消失：

$ kubectl -n notes-lab get deploy nginx -o jsonpath='replicas={.spec.replicas} ready={.status.readyReplicas} available={.status.availableReplicas}{"\n"}'
replicas=0 ready= available=
$ kubectl -n notes-lab get deploy nginx -o jsonpath='{.status}{"\n"}' | jq -c 'del(.conditions)'
{"observedGeneration":4}

拿这个值直接做数值比较，shell 会报错（下面是中文 locale 下 bash 的提示）：

$ R=$(kubectl -n notes-lab get deploy nginx -o jsonpath='{.status.readyReplicas}'); if [ "$R" -ge 1 ]; then echo up; else echo down; fi
bash: 第 1 行： [: : 需要整数
down

这里碰巧走进了 else，结果「看起来是对的」，写成 -lt 1 就会走错分支。要么在 shell 里给默认值，要么在模板里处理：

$ R=$(kubectl -n notes-lab get deploy nginx -o jsonpath='{.status.readyReplicas}'); echo "ready=${R:-0}"
ready=0
$ kubectl -n notes-lab get deploy nginx -o go-template='ready={{or .status.readyReplicas 0}}{{"\n"}}'
ready=0

另外，缩容命令刚返回、rollout status 也报告完成时，紧接着查到的仍是 ready=1 available=1，等 Pod 删掉后再查才变成空。jsonpath 读到的只是那一刻 API 里的状态，等待某个条件请用 kubectl wait，不要用一次查询代替。

几种输出格式怎么选

jsonpath-file：文件里的换行会原样输出

模板长了可以放进文件，用 -o jsonpath-file=。把模板按习惯分行写：

$ cat pods.jsonpath; kubectl -n notes-lab get pods -o jsonpath-file=pods.jsonpath | cat -A
{range .items[*]}
{.metadata.name}{"\t"}{.status.phase}{"\t"}{.metadata.labels.tier}
{end}
$
api-1^IRunning^Ibackend$
$
api-2^IRunning^Ibackend$
$
nginx-5b566885b5-7q6z6^IRunning^Ifrontend$
$
stuck-1^IPending^Ifrontend$
$
web-1^IRunning^Ifrontend$
$

花括号之外的文字都是要输出的文本，文件里的换行也算，于是每行前面多出一个空行。文件里同样只写一行、用 {"\n"} 换行，输出才和命令行一致。

custom-columns：给人看的表格

$ kubectl -n notes-lab get pods -o custom-columns='NAME:.metadata.name,NODE:.spec.nodeName,TEAM:.metadata.labels.team,OWNER:.metadata.annotations.example\.com/owner'
NAME                     NODE                         TEAM     OWNER
api-1                    worker                       pay      alice
api-2                    worker                       <none>   bob
nginx-5b566885b5-7q6z6   worker                       <none>   <none>
stuck-1                  <none>                       <none>   <none>
web-1                    worker2                      shop     <none>

和 jsonpath 比，它有两个好处：自动对齐，缺字段显示 <none> 而不是空。每列的表达式相对单个对象来写，不带 .items，过滤和 [*] 都能用，多个值用逗号连接：

$ kubectl -n notes-lab get pods -o custom-columns='NAME:.metadata.name,CONTAINERS:.spec.containers[*].name,IMAGES:.spec.containers[*].image'
NAME                     CONTAINERS    IMAGES
api-1                    app,sidecar   busybox:1.36,busybox:1.36
api-2                    app           busybox:1.36
nginx-5b566885b5-7q6z6   nginx         nginx:alpine
stuck-1                  app           busybox:1.36
web-1                    app           busybox:1.36
$ kubectl -n notes-lab get pods -o custom-columns='NAME:.metadata.name,READY:.status.conditions[?(@.type=="Ready")].status'
NAME                     READY
api-1                    True
api-2                    True
nginx-5b566885b5-7q6z6   True
stuck-1                  <none>
web-1                    True

stuck-1 显示 <none>，说明它的 conditions 里没有 Ready 这一项，过滤结果为空。列表达式里不能写 range：

$ kubectl -n notes-lab get pods -o custom-columns='NAME:.metadata.name,NODE:{range .items[*]}{.spec.nodeName}{end}'
error: unexpected path string, expected a 'name1.name2' or '.name1.name2' or '{name1.name2}' or '{.name1.name2}'

需要喂给脚本时加 --no-headers。不过 <none> 是个字面字符串，下游要把它当空值处理；列宽靠空格对齐，值里如果有空格（比如注解内容）就没法按列切分了，这种情况还是用 jsonpath 的 {"\t"}。

go-template：jsonpath 做不到的条件和计数

go-template 是 Go 的 text/template，有 if、not、and、or、eq、len、index 和变量。前面 jsonpath 卡住的几件事，它都能做。

找出未调度（没有 spec.nodeName）的 Pod，模板放进文件比较好读：

$ cat nonode.tmpl; kubectl -n notes-lab get pods -o go-template-file=nonode.tmpl
{{- range .items -}}
{{- if not .spec.nodeName -}}
{{ .metadata.name }} 未调度
{{ end -}}
{{- end -}}
stuck-1 未调度

{{- 和 -}} 吃掉两侧的空白，否则模板文件里的换行也会被输出。没有 team 标签的 Pod、计数、两个条件同时成立：

$ kubectl -n notes-lab get pods -o go-template='{{range .items}}{{if not .metadata.labels.team}}{{.metadata.name}}{{"\n"}}{{end}}{{end}}'
api-2
nginx-5b566885b5-7q6z6
stuck-1
$ kubectl -n notes-lab get pods -o go-template='{{len .items}}{{"\n"}}'
5
$ kubectl -n notes-lab get pods -o go-template='{{range .items}}{{if and (eq .status.phase "Running") (eq .metadata.labels.tier "frontend")}}{{.metadata.name}}{{"\n"}}{{end}}{{end}}'
nginx-5b566885b5-7q6z6
web-1

带点号的键用 index 取，不需要转义；内层 range 会改变 .，要先把外层的值存进变量：

$ kubectl -n notes-lab get pods -o go-template='{{range .items}}{{if eq .metadata.labels.tier "backend"}}{{.metadata.name}} {{index .metadata.annotations "example.com/owner"}}{{"\n"}}{{end}}{{end}}'
api-1 alice
api-2 bob
$ kubectl -n notes-lab get pods -o go-template='{{range .items}}{{$p := .metadata.name}}{{range .spec.containers}}{{if eq .name "sidecar"}}{{$p}}{{"\n"}}{{end}}{{end}}{{end}}'
api-1

第二条就是 jsonpath 报 can only compare one element at a time 的那个需求：「有名为 sidecar 的容器的 Pod」。

缺失字段在 go-template 里默认打印 <no value>，用 or 给默认值：

$ kubectl -n notes-lab get pods -o go-template='{{range .items}}{{.metadata.name}} team={{.metadata.labels.team}}{{"\n"}}{{end}}'
api-1 team=pay
api-2 team=<no value>
nginx-5b566885b5-7q6z6 team=<no value>
stuck-1 team=<no value>
web-1 team=shop
$ kubectl -n notes-lab get pods -o go-template='{{range .items}}{{.metadata.name}} team={{or .metadata.labels.team "-"}}{{"\n"}}{{end}}'
api-1 team=pay
api-2 team=-
nginx-5b566885b5-7q6z6 team=-
stuck-1 team=-
web-1 team=shop

除了 Go 模板自带的函数，kubectl 还额外注册了两个（k8s.io/cli-runtime/pkg/printers/template.go）：exists 判断嵌套字段是否存在，base64decode 解码 Secret 的值：

$ kubectl -n notes-lab get pods -o go-template='{{range .items}}{{.metadata.name}} {{if exists . "spec" "nodeName"}}scheduled{{else}}pending{{end}}{{"\n"}}{{end}}'
api-1 scheduled
api-2 scheduled
nginx-5b566885b5-tzt6k scheduled
stuck-1 pending
web-1 scheduled
$ kubectl -n notes-lab create secret generic demo --from-literal=password=s3cr3t >/dev/null
$ kubectl -n notes-lab get secret demo -o go-template='{{.data.password | base64decode}}{{"\n"}}'
s3cr3t

（本文部分输出来自复查时重建的 namespace，所以个别 Pod 名字和时间与前文不同。）

还有一个较少人用的 -o jsonpath-as-json，把 jsonpath 的结果包成 JSON 数组输出，方便接 jq：

$ kubectl -n notes-lab get pods -o jsonpath-as-json='{.items[*].metadata.name}'
[
    "api-1",
    "api-2",
    "nginx-5b566885b5-7hkg9",
    "stuck-1",
    "web-1"
]
$ kubectl -n notes-lab get pods -o jsonpath-as-json='{.items[*].spec.nodeName}' | jq length
4

它和 [*] 一样跳过缺字段的元素，依旧是 4 个。（nginx Pod 名字变了，是因为中间做过一次缩容再扩容。）

–sort-by：先排序，再交给模板

--sort-by 也用 JSONPath 写，但它相对单个对象，不带 .items。它在输出前对 List 排序，后面用 jsonpath 还是 custom-columns 都可以：

$ kubectl -n notes-lab get pods --sort-by=.metadata.creationTimestamp -o custom-columns=NAME:.metadata.name,CREATED:.metadata.creationTimestamp
NAME                     CREATED
api-1                    2026-10-13T03:22:06Z
api-2                    2026-10-13T03:22:07Z
stuck-1                  2026-10-13T03:22:07Z
web-1                    2026-10-13T03:22:07Z
nginx-5b566885b5-7q6z6   2026-10-13T03:22:08Z
$ kubectl -n notes-lab get pods --sort-by=.spec.nodeName -o custom-columns=NAME:.metadata.name,NODE:.spec.nodeName
NAME                     NODE
stuck-1                  <none>
api-1                    worker
api-2                    worker
nginx-5b566885b5-7q6z6   worker
web-1                    worker2

缺字段的对象排在最前面。有了排序，{.items[-1].metadata.name} 才真正是「最新创建的那个」。

字段写错时的表现取决于输出格式，这是本次实验里最意外的一点：

$ kubectl -n notes-lab get pods --sort-by=.metadata.nosuch
No resources found in notes-lab namespace.
$ kubectl -n notes-lab get pods --sort-by=.metadata.nosuch -o name
error: couldn't find any field with path "{.metadata.nosuch}" in the list of objects
$ kubectl -n notes-lab get pods --sort-by=.items[*].metadata.name
No resources found in notes-lab namespace.

默认的表格输出遇到不存在的排序字段，打印的是 No resources found，退出码 0，看上去就像 namespace 是空的，实际上里面有 5 个 Pod。换成 -o name、-o jsonpath 才会给出真正的错误。把 .items[*] 写进 --sort-by 是常见的手误，结果也是这句误导人的提示。原因在 kubectl 源码 staging/src/k8s.io/kubectl/pkg/cmd/get/get.go：默认表格和 -o wide 会向 API Server 请求 as=Table 格式，打印时经 SortingPrinter 调用 NewTableSorter，后者返回 couldn't find any field… 错误；但 Run 里的 printer.PrintObj(info.Object, w) 没有检查返回值，什么都没写出，错误列表也是空的，于是走到在 stderr 打印 No resources found 的分支，退出码 0。-o name、-o jsonpath 这类非表格输出走 printGeneric，会把错误返回出来。-o wide 实测也一样：

$ kubectl -n notes-lab get pods --sort-by=.metadata.nosuch -o wide
No resources found in notes-lab namespace.

以后看到 --sort-by 配 No resources found，先去掉 --sort-by 再跑一次。

排序字段必须是字符串或数字，指向一个对象会直接退出：

$ kubectl -n notes-lab get pods --sort-by=.metadata -o name
F1013 11:24:13.509359 2278553 sorter.go:331] Field {.metadata} in *unstructured.Unstructured is an unsortable type: interface, err: unsortable type: map[string]interface {}

引号：bash 和 zsh 各有各的坑

JSONPath 里有 {}、[]、*、?、"，全是 shell 的特殊字符。最省心的规则是整个模板用单引号包起来，模板里的字面量用双引号。几种不这么做的后果：

zsh 把不加引号的 [*] 当通配符，找不到匹配文件就报错，命令根本没执行；bash 找不到匹配时会把原样传下去，所以「在 bash 里好好的」：

$ zsh -c 'kubectl -n notes-lab get pods -o jsonpath={.items[*].metadata.name}'
zsh:1: no matches found: jsonpath={.items[*].metadata.name}
$ bash -c 'kubectl -n notes-lab get pods -o jsonpath={.items[*].metadata.name}; echo'
api-1 api-2 nginx-5b566885b5-7q6z6 stuck-1 web-1

两种 shell 都会对含逗号的花括号做展开。不加引号的 {.items[0,2].metadata.name} 在 bash 里被拆成两个参数，kubectl 把第二段当成了 Pod 名；zsh 展开后又把 [0 当成通配模式，报 bad pattern：

$ bash -c 'echo kubectl get pods -o jsonpath={.items[0,2].metadata.name}'
kubectl get pods -o jsonpath=.items[0 jsonpath=2].metadata.name
$ bash -c 'kubectl -n notes-lab get pods -o jsonpath={.items[0,2].metadata.name}'
Error from server (NotFound): pods "jsonpath=2].metadata.name" not found
$ zsh -c 'echo kubectl get pods -o jsonpath={.items[0,2].metadata.name}'
zsh:1: bad pattern: jsonpath=.items[0

外层用双引号时，内层的 "\n" 会和外层引号配对，kubectl 收到的是 {n}：

$ bash -c 'kubectl -n notes-lab get pods -o jsonpath="{.items[*].metadata.name}{"\n"}"; echo "<END>"'
error: error executing jsonpath "{.items[*].metadata.name}{n}": Error executing template: unrecognized identifier n. Printing more information for debugging the template:

外层必须用双引号的场合（比如模板里要插 shell 变量，或者 Windows 上），内层写成 {\"\n\"} 或者 {'\n'}，两种都实测可用。字面量的引号不能省，{\n} 是解析错误：

$ bash -c 'kubectl -n notes-lab get pods -o jsonpath='"'"'{range .items[*]}{.metadata.name}{\n}{end}'"'"' | head -2'
error: error parsing jsonpath {range .items[*]}{.metadata.name}{\n}{end}, unrecognized character in action: U+005C '\'

顺带一提，漏写 {end} kubectl 并不报错，{range .items[*]}{.metadata.name}{"\n"} 照样输出了 5 行。看到别人的模板少了 {end} 还能用，不代表写法是对的。

报错会把整个对象打出来

执行期的错误（length( 不认识、下标越界、--allow-missing-template-keys=false 找不到字段）后面都跟着一句 Printing more information for debugging the template，接着把模板和整个输入对象打到 stderr。5 个 Pod 的列表就是 4 万多字节：

$ kubectl -n notes-lab get pods -o jsonpath='{length(.items)}' 2>&1 | wc -c; kubectl -n notes-lab get pods -o json | wc -c
42746
43283
$ kubectl get nodes -o jsonpath='{length(.items)}' 2>/dev/null; echo "<stdout END exit=$?>"
<stdout END exit=1>

（最后一条是复查时对节点列表的只读查询。）jsonpath 的转储包在错误信息里，走 stderr，stdout 是干净的，退出码是 1。go-template 不一样：kubectl 依赖的 k8s.io/cli-runtime/pkg/printers/template.go 用 fmt.Fprintf(w, …) 把转储写进输出流，也就是 stdout，真正的错误行才在 stderr：

$ kubectl -n notes-lab get pod api-1 -o go-template='{{.spec.nodeNmae}}' --allow-missing-template-keys=false 2>/dev/null | wc -c; echo "exit=${PIPESTATUS[0]}"
13861
exit=1
$ kubectl -n notes-lab get pod api-1 -o go-template='{{.spec.nodeNmae}}' --allow-missing-template-keys=false 2>/dev/null | head -c 200; echo
Error executing template: template: output:1:7: executing "output" at <.spec.nodeNmae>: map has no entry for key "nodeNmae". Printing more information for debugging the template:
	template was:
$ kubectl -n notes-lab get pod api-1 -o go-template='{{.spec.nodeNmae}}' --allow-missing-template-keys=false 2>&1 >/dev/null
error: error executing template "{{.spec.nodeNmae}}": template: output:1:7: executing "output" at <.spec.nodeNmae>: map has no entry for key "nodeNmae"
$ kubectl -n notes-lab get pod api-1 -o jsonpath='{.spec.nodeNmae}' --allow-missing-template-keys=false 2>/dev/null | wc -c
0

同样把 stderr 丢掉，go-template 往 stdout 写了 1.3 万多字节，jsonpath 是 0 字节。脚本里用 $(kubectl ... -o go-template=...) 取值时，出错后变量里装的是这段调试文本，一定要先检查退出码（这里用 PIPESTATUS 是因为有管道，它是 bash 专有的；zsh 用 $pipestatus[1]，或者先 set -o pipefail）。在 CI 日志里，这一大段转储很容易把真正的错误行顶出屏幕；排查时看第一行就够了，2>&1 | head -1。如果对象里有 Secret，这段转储也会把内容带进日志，推测在 get secret -o jsonpath 出错时同样如此，本次没有拿 Secret 测。

什么时候换 jq

规则可以很简单：取字段、按 type 挑数组项、简单等值过滤，用 jsonpath；要判断字段缺失、正则、与或、计数、分组、CSV，先 -o json 再交给 jq。 本机的 jq 是 1.8.1，前面 jsonpath 做不到的几件事对应的写法：

$ kubectl -n notes-lab get pods -o json | jq -r '.items[] | select(.spec.nodeName == null) | .metadata.name'
stuck-1
$ kubectl -n notes-lab get pods -o json | jq -r '.items[] | select(.metadata.labels.team | not) | .metadata.name'
api-2
nginx-5b566885b5-7q6z6
stuck-1
$ kubectl -n notes-lab get pods -o json | jq -r '.items[] | select(.metadata.name | test("^(api|web)-")) | .metadata.name'
api-1
api-2
web-1
$ kubectl -n notes-lab get pods -o json | jq '.items | length'
5
$ kubectl -n notes-lab get pods -o json | jq -r '.items[] | select(.status.phase=="Running" and .metadata.labels.tier=="frontend") | .metadata.name'
nginx-5b566885b5-7q6z6
web-1
$ kubectl -n notes-lab get pods -o json | jq -r '.items[] | select(any(.spec.containers[]; .name=="sidecar")) | .metadata.name'
api-1

jq 的 // 给缺失字段默认值，["example.com/owner"] 取带点号的键不用转义，@tsv、@csv 负责转义输出：

$ kubectl -n notes-lab get pods -o json | jq -r '.items[] | [.metadata.name, (.spec.nodeName // "-"), (.metadata.labels.team // "-"), (.metadata.annotations["example.com/owner"] // "-")] | @tsv'
api-1	worker	pay	alice
api-2	worker	-	bob
nginx-5b566885b5-7q6z6	worker	-	-
stuck-1	-	-	-
web-1	worker2	shop	-
$ kubectl -n notes-lab get pods -o json | jq -r '.items | group_by(.metadata.labels.tier)[] | "\(.[0].metadata.labels.tier)\t\(length)"'
backend	2
frontend	3

注意 jq 的 // 把 false 和 null 一视同仁，布尔字段（比如 ready）不要用它给默认值。go-template 的 or 也一样，0、""、false 都会被替换。

如果机器上没有 jq（比如精简的容器镜像里），go-template 是不需要额外依赖的退路；能用标签表达的条件，优先交给 -l，让 API Server 去筛，比拉回全量再在客户端过滤省流量。

清理

kubectl delete namespace notes-lab

本篇只创建了 namespace 内的对象，节点只做了只读查询。字段选择器能筛哪些字段、标签选择器的完整语法，见 标签与注解；排查时常用的查询组合见 故障排查。

参考：JSONPath Support、kubectl Quick Reference、kubectl get。
