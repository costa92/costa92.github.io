Gemini 4 Argon 全面开放后的 API 接入与价格

 2026-10-15  AI Gemini Google AI Gemini API 大模型
Gemini Google AI Gemini API 大模型
AI
文章字数:   1.3k
阅读次数:  
   阅读模式

Google 于 2026 年 10 月 13 日宣布 Gemini 4 Argon 全球开放。开发者可以通过 Google AI Studio 使用付费版 Gemini API，模型标识为 gemini-4-argon。它面向复杂编程、Agent、数学和科学等需要持续推理的任务。Google 官方发布文章介绍了这次开放及其应用场景。

开发者最需要关注三个变化：1M 的输入输出共享窗口、可以超过 64K 的长生成，以及持续到 11 月底的优惠定价。接入时，窗口如何分配、长任务如何续接，会直接影响结果完整性和账单。

Google 官方发布页截图，截取于 2026 年 10 月 15 日。查看原文。

付费 Gemini API 的开放范围

在应用中调用时，选择的模型名是 gemini-4-argon，需要开通 Gemini API 的付费层。官方价格页列明，该模型不提供 API 免费层额度。

Google 把 Argon 定位为处理复杂工作任务的模型。发布文章中的例子包括 Chromium 的跨文件重构，以及 ADK Python 框架的性能优化。这些案例适合帮助理解模型的目标场景；实际接入自己的项目时，仍应检查改动能否通过测试、是否满足任务要求。

1M 是输入和输出共享的窗口

Argon 的总额度为 1,048,576 token，输入、思考、工具调用和最终回答共同占用这部分空间。Google Cloud 开发指南明确说明了这一计算口径。

假设一次任务输入了 800,000 token，留给后续思考和生成的理论空间就是：

1,048,576 - 800,000 = 248,576 token

整理大仓库或长文档时，要同时给回答预留空间。比如要求模型阅读大量源码后生成补丁，输入侧就应优先保留相关模块、接口约束和测试信息，避免无关材料占满窗口。

超过 64K 的回答如何生成

在 Gemini API 的 Interactions API 中，普通交互默认最多生成 65,536 token。要超过这个上限，需要开启后台执行，并把总生成上限设得更高。按官方Argon 接入说明，关键配置可以写成：

{
  "model": "gemini-4-argon",
  "background": true,
  "generation_config": {
    "max_output_tokens": 131072,
    "thinking_level": "medium"
  }
}

这是请求的配置片段，调用时还需要提供任务输入与认证信息。仅设置 background: true 而不提高 max_output_tokens，仍会停在默认的 64K 上限。这个上限同时包含思考与输出，不能直接当成最终正文的长度。

官方长生成限制说明，截取于 2026 年 10 月 15 日。查看文档。

根据官方长生成指南，后台会按最多 64K token 一段持续生成。客户端通过轮询或流式连接获取结果，完成后需要合并 interaction.steps 中各个 model_output 的文本。后台交互要求启用存储；需要自行管理续接流程的应用，可以使用 GenerateContent API。

因此，一次交互可以返回超过 64K 的完整结果，底层可能经过多段生成。把上限调大，是给困难任务更多推理空间，最终正文长度仍由模型决定。

11 月 30 日前后的价格

以下是 Gemini API Standard 档的美元价格，单位均为每百万 token。优惠持续至 2026 年 11 月 30 日（含当日），从 12 月 1 日起恢复常规定价。官方价格页同时列出了其他服务档位。

官方 Standard 档价格截图，截取于 2026 年 10 月 15 日。查看当前价格。

计费项目优惠期价格2026 年 12 月 1 日起
普通输入$2$4
输出，包含思考 token$10$20
隐式缓存命中的输入$0.10$0.20

举一个按上述单价计算的例子：某次普通调用计费输入为 100,000 token，计费输出为 20,000 token，思考已包含在输出数字内，且没有缓存命中或额外工具费用。

优惠期：0.1 × $2 + 0.02 × $10 = $0.40
优惠后：0.1 × $4 + 0.02 × $20 = $0.80

长生成还要考虑续接的输入费用。每一段都可能把原始提示和此前生成内容重新作为输入，重复输入可享受隐式缓存折扣；实际费用应按最终 usage 核算。只用最初的输入量和最终可见正文长度估算，容易漏掉思考和续接消耗。长生成计费说明解释了这部分统计方式。

现有应用接入时检查什么

官方迁移说明列出了几项容易影响旧应用的变化：模型名换成 gemini-4-argon；思考强度使用 low、medium 或 high，默认 medium；显式上下文缓存不受支持；temperature、top_p 和 top_k 会被忽略。

接入后可以先用一组已有任务做对照，记录完成率、等待时间和总费用，再决定哪些任务需要长生成。准备长期使用的应用，应同时按 12 月恢复后的价格核算预算，让优惠期内的试用结果能反映之后的实际成本。
