Grok Bot Skill 跨 Bot 实测：独立会话能否找到私有技能

 2026-10-10  AI AI Agent Grok Bot 自动化 Skill
AI Agent Grok Bot 自动化 Skill

阅读次数:  
   阅读模式

本文的测试已整理进Grok Bot 进阶实测的“换一个 Bot 再调用”一节，建议直接阅读那篇。

前两篇分别验证了私有 Skill 的保存，以及在原 Bot 对话里用它处理另一份公开文档。这里继续验证它能否在新建的另一个 Bot中找到。

我们新建“跨 Bot 复用验证员”，只提供 Grok Bot 官方审批、隐私与安全文档，要求使用账号里保存的“公开文档阅读笔记” Skill，并交付 Markdown 笔记。Bot 在新会话中回复找到了技能，显示可点击的技能标签，随后返回了文件卡片和摘要。

测试日期：2026 年 10 月 10 日。客户端为 Linux Grok Bot 0.68.1。这次换了 Bot 和对话，跨 Bot 找到技能的证据是新会话中的回复与技能标签。它不是完整的后台调用日志，也不能单独证明 Bot 的每一步都由 Skill 指令驱动。

新 Bot 中调用已有 Skill

任务要求 Bot 使用已有私有 Skill，不重新创建或修改；如果找不到，要先报告。输入范围仅限一篇公开文档，并明确禁止访问私人连接器、本地文件，或发送、发布、创建 Routine 与修改设置。

新 Bot 先回复会改名并检查技能。随后它确认找到“公开文档阅读笔记”，返回可点击的技能标签，并表示正在按该 Skill 的流程整理页面。

官方Skills 文档说明，私有 Skill 存放在账户共享的技能库中，所有 Bot 都可以使用；桌面端可在输入框键入 / 引用技能。此处的实测路径是在新 Bot 的任务消息中点名 Skill，Bot 返回技能标签。我们没有成功完成 / 菜单选择，所以不能据此验证该菜单在新 Bot 中的表现。

审核交付卡片与摘要

Bot 返回了 grok-bot-approvals-note.md 文件卡片，界面显示约 8.7 kB；对话摘要称文件已按 Skill 完成，并给出页面更新日期为 2026 年 10 月 6 日。摘要涉及自动审查（Auto Review）规则和人工接管步骤。

我们对照官方页面核对了摘要中的要点：

报告要点官方文档说明核对结果
页面更新日期页脚标注 October 6, 2026一致
Ask first匹配时始终暂停并等待用户处理一致
Allow automatically匹配操作可在自动审查没有其他停止理由时继续一致
同时匹配两类规则Ask first 优先一致
密码和验证码通过 Agent Computer 接管，在页面自行输入，再交还控制权一致

这里审核的是对话中的文件卡片与摘要，并直接对照官方页面核验事实。这次没有下载并逐行检查 Markdown 文件本身，因此对文件内部的完整性、引用是否逐项可点击，不作保证。

“跨 Bot”不等于环境隔离

这次结果支持一个有限结论：同一账户中新建的 Bot，在新对话中能够找到该账户保存的私有 Skill，并在引用它后交付了新页面的笔记。它补上了上一篇同一对话复用测试的缺口。

Bot 之间共享云电脑，所以换一个 Bot 只改变任务角色与会话，不会隔离云端文件、浏览器登录状态或命令行凭据。官方文档也明确提醒，不要把单独创建的 Bot 当作安全边界。测试中选择公开、只读资料，不能替代敏感工作所需的权限管理。

本次没有执行 Routine，没有访问连接器或本地文件，也没有修改 Auto Review 设置。访问范围来自请求限制和 Bot 对话中的说明；我们没有独立审计后台的全部工具调用。

这次验证到哪里

  • 验证成功： 新 Bot 的对话里出现了已保存 Skill 的可点击标签；它返回了指定文件名的交付卡片与总结。
  • 独立核对： 页面日期与 Auto Review、人工接管及共享电脑规则和官方文档一致。
  • 仍未验证： 下载文件正文、每个链接的有效性、/ 菜单选择路径、来源不可访问时的失败处理，以及多次运行的稳定性。

接下来可以下载并审核文件正文，再用公开的失效网址测试 Skill 是否按要求报告失败。Routine 仍应等任务流程和验收方式稳定后再启用。
