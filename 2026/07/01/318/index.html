zweite-tools 源码核对：Claude Code 数据库插件的风险闸门拦在哪

 2026-07-01  AI Claude Code 插件市场 数据库运维 钉钉文档

zweite/claude-plugins 是一个 Claude Code 插件市场，市场名叫 zweite-tools，里面五个插件：mysql、starrocks、mongodb、zeppelin 四个连数据，alidocs 同步钉钉文档。README 的卖点是”带风险控制”：高危语句先问你一句再动手。

能直接碰生产库的工具，我不想只看 README 就装。这次把仓库 clone 下来，读了全部脚本，在不连任何数据库的前提下，把能离线跑的部分都跑了一遍。结论先放前面：风险分级是一段正则，真正的”刹车”写在给 Claude 看的 SKILL.md 里，脚本本身不拦任何东西。这不算缺陷，但你得知道闸门在哪。

核对环境和仓库状态

2026-10-30 在 Ubuntu 26.04 + Python 3.14.4 + Claude Code 2.1.314 上实测，仓库 HEAD 是 03a1b74（2026-05-25，”alidocs: bump to v1.1.0”）。各插件版本：

alidocs    1.1.0
mongodb    1.0.0
mysql      1.0.0
starrocks  1.1.0
zeppelin   1.4.0

plugins/ 下全部文件加起来 6875 行，每个插件是 .claude-plugin/plugin.json + skills/<tool>/SKILL.md + scripts/*.py + README。没有二进制、没有编译步骤。

先用 Claude Code 自带的校验命令过一遍市场清单：

claude plugin validate .
Validating marketplace manifest: .../.claude-plugin/marketplace.json

⚠ Found 5 warnings:

  ❯ plugins[0] plugin.json → author: No author information provided. ...
  ...
✔ Validation passed with warnings

五条警告都是 plugin.json 没写 author，不影响安装。mysql 自带的单元测试也能离线跑：

cd plugins/mysql/scripts && python3 -m unittest test_mysql
Ran 22 tests in 0.035s

OK

测试覆盖的是密码 scramble、profile 合并、缓存新鲜度、表名校验这些纯逻辑，不需要数据库。

安装走 Claude Code 的 /plugin 机制：

/plugin marketplace add zweite/claude-plugins
/plugin install mysql@zweite-tools

风险分级：一份共用的正则分类器

mysql、starrocks、zeppelin 三个插件的 scripts/risk.py 是同一个文件，diff 结果完全一致，文件头注释写的还是”classify a Zeppelin paragraph”，可见是从 zeppelin 插件复制过去的。它是纯标准库的正则匹配，先剥掉注释和字符串字面量，再按模式表打分，取最高档：

档位规则
highDROP / TRUNCATE / ALTER / CREATE / REPLACE / GRANT / REVOKE、INSERT OVERWRITE、不带 WHERE 的 UPDATE / DELETE；Spark 的 .write / saveAsTable / .save()、shell 的 rm -rf、hdfs dfs -rm
mediumINSERT INTO、MERGE INTO；shell 里的 curl -X POST/PUT/DELETE
low带 WHERE 的 UPDATE / DELETE；识别不出的 SQL
safeSELECT、SHOW、DESCRIBE、EXPLAIN、USE

拿一组语句喂给它（echo "<SQL>" | python3 risk.py --magic '%sql'）：

SELECT count(*) FROM orders WHERE dt = CURDATE() -> safe ['read_select']
DROP TABLE foo                                -> high ['ddl_drop']
DELETE FROM orders WHERE status = 'pending'   -> low ['dml_delete']
DELETE FROM orders                            -> high ['dml_delete_no_where']
DELETE FROM orders WHERE 1=1                  -> low ['dml_delete']
DELETE FROM orders -- WHERE id = 1            -> high ['dml_delete_no_where']
UPDATE users SET vip = 1                      -> high ['dml_update_no_where']
INSERT INTO t VALUES (1)                      -> medium ['dml_insert']
SELECT 1; TRUNCATE TABLE logs                 -> high ['ddl_truncate', 'read_select']
CALL purge_all()                              -> low ['unrecognized_sql']

几个值得注意的结果：

  • 带 WHERE 的 DELETE 只判 low。我原以为”清掉 pending 订单”这种语句会判 high，实际不会。
  • WHERE 1=1 骗得过它。判断”有没有 WHERE”只看 DELETE 后 400 个字符内有没有这个关键字，不看条件内容。
  • 注释里的 WHERE 骗不过它，因为先剥了注释。多语句里藏一条 TRUNCATE 也能被抓出来。
  • 存储过程 CALL 认不出来，按 low 处理，可过程里可能什么都干。

PySpark 段落也有个怪现象：

df = spark.table("events"); df.groupBy("dt").count().show()          -> safe ['read_show']
df = spark.table("events"); print(df.groupBy("dt").count().collect()) -> medium ['unrecognized_code']
df = spark.table("events"); df.show(); df.write.parquet("/tmp/x")    -> high ['read_show', 'spark_write']

第一条判 safe，是因为 .show() 被 SQL 规则里的 \bSHOW\b 当成了 SHOW 语句；去掉 .show() 换成 collect()，同样是只读，反而变成 medium。好在写操作的规则单独匹配，第三条依然是 high。

脚本作者自己在注释里说得很清楚：这个分类器”intentionally conservative”，而且 “the classifier is a floor, not a ceiling”。所以 SKILL.md 要求 Claude 在它之上再判断一层：表名没有 dev_ / test_ / tmp_ / stg_ 前缀、像是事实表、涉及财务或 PII 字段时，往上调档，”Never downgrade”。这条”只升不降”是写给模型的指令，不是代码逻辑。

自动批准阈值：没有一行代码在执行它

阈值用环境变量控制，四个数据插件各有一个：MYSQL_AUTO_APPROVE_LEVEL、STARROCKS_AUTO_APPROVE_LEVEL、MONGODB_AUTO_APPROVE_LEVEL、ZEPPELIN_AUTO_APPROVE_LEVEL，默认都是 safe。

我在整个 plugins/ 下搜这几个变量名，只出现在 SKILL.md 和 README 里，没有任何一个 .py 读取它。执行逻辑在 SKILL.md：

If the final risk level is above the threshold, you MUST call AskUserQuestion
with the verbatim SQL, the operations found, your rationale, and the affected
tables before running it. Do not paraphrase the SQL when asking.

这带来两个推论：

  1. 闸门靠的是 Claude 遵守 SKILL.md。它要求原样贴出 SQL、列出操作和受影响的表再问你，设计得挺克制，但它和 CLAUDE.md 一样只能引导，没有强制力。
  2. 你自己在终端里跑 mysql.py query --sql 'DROP TABLE ...'，脚本会直接执行，没有确认。手动调脚本时，风险判断只能靠你自己，或者先用 risk.py 过一遍。

回到前面那条带 WHERE 的 DELETE：它判 low，而默认阈值是 safe，low 高于 safe，所以 Claude 仍然应该停下来问你。默认配置下，除了 SELECT 这类只读语句，其他都要你点头。阈值千万别开到 high，那等于让 Claude 对 DROP TABLE 也不问。

想要一道真正的硬闸，可以在 Claude Code 的 settings 里用 permissions 规则让这类 Bash 调用每次都要你批准，或者干脆给 AI 用的数据库账号只授只读权限。后者最可靠：账号没有写权限，什么分类器都不重要了。

配置：一个目录、环境变量优先

配置统一放在 ~/.taku/<tool>.json，TAKU_DIR 可以换目录。代码里确实保留了旧路径回退，mysql.py 里是 _config_path("mysql", "~/.mysql/config.json")：新路径不存在时读旧文件。

多环境用 profiles，顶层键作为公共默认值合并进每个 profile：

{
  "default_profile": "prod",
  "profiles": {
    "prod":    { "host": "db-prod",    "user": "you", "password": "…" },
    "staging": { "host": "db-staging", "user": "you", "password": "…", "ssl": true }
  },
  "cache_ttl_days": 30
}

mysql.py 文件头列出的完整配置项，比 README 多两项（MYSQL_PROFILE、MYSQL_SSL_VERIFY）：

环境变量配置键默认
MYSQL_HOST / MYSQL_USER / MYSQL_PASSWORDhost / user / password必填
MYSQL_PORTport3306
MYSQL_DATABASEdatabase可选
MYSQL_PROFILE—选 profile，也可以用 --profile
MYSQL_SSLsslfalse，一开始就走 TLS
MYSQL_SSL_VERIFYssl_verifytrue，校验服务器证书
MYSQL_TIMEOUT_SECONDStimeout_seconds30
MYSQL_CACHE_DIRcache_dir~/.mysql/cache
MYSQL_CACHE_TTL_DAYScache_ttl_days30

环境变量优先于配置文件，CI 里注入敏感值就靠这个。凭据是明文 JSON，chmod 600 ~/.taku/*.json 一条命令收紧权限。

mysql 和 starrocks：纯 Python 实现的 MySQL 协议

两个插件都不依赖驱动，starrocks.py 的 import 只有 socket、struct、hashlib 这些标准库，mysql.py 也一样，直接在 socket 上讲 MySQL 协议。支持两种认证：mysql_native_password 和 MySQL 8.0 默认的 caching_sha2_password。

caching_sha2 有个限制写在文件头里：服务器已缓存密码时走 fast path，普通 socket 就行；某个账号第一次登录要走 full auth，必须在安全通道上发密码。脚本会自动升级到 TLS；没实现 RSA 公钥那条路（标准库没有 RSA），所以服务器不支持 TLS 时，冷缓存的 caching_sha2 登录会直接报错。新建的只读账号第一次连不上，先查这个。

命令只有这几个：

test-conn                       — connect + SELECT 1
query   --sql 'SELECT ...'      — run one statement, print JSON result
cache get   --table db.t [--max-age-days N]
cache put   --table db.t [--force] [--limit N]
cache list
cache clear --table db.t | --all

元数据缓存存表结构加样本数据，DEFAULT_SAMPLE_ROWS = 10，TTL 默认 30 天，按 profile 分开存，prod 和 staging 的同名表不会串。SKILL.md 里脚本路径写作 ${CLAUDE_PLUGIN_ROOT}/scripts/mysql.py，Claude 调用时会替换成插件的安装目录。

mongodb：JSON spec 必须带 op

mongodb 插件不用 risk.py，mongodb.py 里有自己的分类函数，规则按操作类型来。它有个 classify 子命令，不连库就能看判档，正好拿来试。完整命令是：

python3 plugins/mongodb/scripts/mongodb.py classify --spec '{"op":"find","collection":"orders","filter":{"status":"paid"},"limit":20}'

输出是一段 JSON（level、factors、operations），下面把几条 spec 的结果压成一行一条：

{"collection":"orders","filter":{"status":"paid"},"limit":20}                -> high ['missing_op']
{"op":"find","collection":"orders","filter":{"status":"paid"},"limit":20}    -> safe ['bounded_read']
{"op":"find","collection":"orders","filter":{"status":"paid"}}               -> low ['no_limit']
{"op":"deleteMany","collection":"orders","filter":{}}                        -> high ['bulk_write_no_filter']
{"op":"deleteMany","collection":"orders","filter":{"status":"pending"}}      -> medium ['bulk_write_with_filter']
{"op":"runCommand","command":{"dropDatabase":1}}                             -> high ['admin:dropDatabase']

有一个坑：classify 虽然不连库，配置却是在脚本导入时就解析的。配置文件（~/.taku/mongodb.json）里定义了多个 profile、又没写 default_profile 时，连 classify 也直接退出。2026-10-30 我用 TAKU_DIR 把配置目录指到实验目录复现了一遍：

$ TAKU_DIR=./taku-multi python3 mongodb.py classify --spec '...'   # prod、staging 两个 profile，无 default_profile
multiple profiles defined; pass --profile or set default_profile. Available: prod, staging
exit=1
$ TAKU_DIR=./taku-multi python3 mongodb.py --profile prod classify --spec '...'
{"level": "safe", "factors": ["bounded_read"], "operations": ["find"]}
$ TAKU_DIR=./taku-empty python3 mongodb.py classify --spec '...'   # 空目录，没有配置文件
{"level": "safe", "factors": ["bounded_read"], "operations": ["find"]}

所以要么加 --profile（注意它写在子命令前面），要么像上面最后一条那样用 TAKU_DIR 指向一个空目录，绕开本机的真实配置，只做判档。

第一条是我照着记忆写的 spec，漏了 op，直接判 high。spec 必须写明 op（find / aggregate / count / distinct / runCommand 和各种写操作）。读操作不带 limit 或 limit 超过 1000 判 low，带合理 limit 才是 safe。比 SQL 那套细的地方是：同样是 deleteMany，空 filter 是 high，有 filter 是 medium。

依赖写在 requirements.txt 里：pymongo>=4.0,<5.0，以及 mongodb+srv://（Atlas）连接串需要的 dnspython。缓存按集合存，DEFAULT_SAMPLE_DOCS = 10，README 说它会记 estimatedDocumentCount、索引列表、10 条样本和推断出的字段类型。Mongo 没有固定 schema，采样是让 AI 知道文档长什么样的唯一办法。

zeppelin：跑段落的子命令叫 exec

zeppelin 插件走 Zeppelin 的 REST API，只用标准库的 urllib 和 http.cookiejar。我一开始照着印象写了 zeppelin.py run --sql '...'，脚本直接报错：

zeppelin.py: error: argument cmd: invalid choice: 'run' (choose from login, test-conn,
submit, fetch, poll, list-notes, delete-note, exec, cache)

正确写法是用 --magic 指定解释器、--code 传段落内容：

python3 zeppelin.py --profile prod exec --magic '%spark.sql' --code 'SELECT count(*) FROM events'
python3 zeppelin.py --profile prod exec --magic '%pyspark' \
    --code 'df = spark.table("events"); df.groupBy("dt").count().show()'

exec 是 submit + poll 的组合，跑完默认删掉临时创建的 note，加 --keep-note 保留。长作业可以拆开用 submit 提交、poll 轮询。它能跑 %sh，口子开得最大，上面那张规则表里 shell 相关的几条就是为它准备的。

alidocs：同步是单向的，–prune 是进回收站

alidocs 不碰数据库，用浏览器登录态的 Cookie 访问钉钉文档，配置在 ~/.taku/alidocs.json（也可以用 ALIDOCS_COOKIE 环境变量）：

{
  "cookie": "<full Cookie header from a logged-in browser>",
  "default_out_dir": "~/Downloads/alidocs",
  "use_playwright": true
}

子命令是 fetch、check、push、sync。check 只验证 cookie 和解析链接，不下载，换了 cookie 先跑它。依赖分层：requests 必装，上传要 oss2，把在线文档导出成文件要 playwright 加 Chromium；fetch --no-playwright 时只保存 .url 快捷方式。

示意图画成了双向同步，但读代码后要纠正两点。第一，sync 的帮助写的是 “one-way sync local → alidocs (same as push, see –prune)”，只从本地推到云端。第二，--on-conflict 处理的是重名冲突，可选值是 skip-if-same（默认）、overwrite、rename、error，并不比较两边谁更新。

python3 alidocs.py sync --src ./my-project --dest '<文件夹链接>' --dry-run
python3 alidocs.py sync --src ./my-project --dest '<文件夹链接>' --on-conflict overwrite --prune

--prune 处理云端多出来、本地没有的文件，代码里调用的是 recycle_dentry，文件进的是回收站。--dry-run（-n）只打印计划；不加 --yes 时，真正执行前会停下来问 “apply?”。

装之前的建议

  • 给 AI 用的数据库账号只授只读权限，这是唯一不依赖模型自觉的闸门。
  • *_AUTO_APPROVE_LEVEL 保持默认 safe。
  • 手动跑脚本前先用 risk.py 或 mongodb.py classify 看判档，脚本本身不会拦你。
  • 知道分类器的盲区：带 WHERE 的写操作只判 low/medium，WHERE 1=1 和 CALL 骗得过它。
  • 凭据明文落盘，chmod 600 ~/.taku/*.json，敏感环境用环境变量注入。
插件连什么分类器额外依赖
mysqlMySQL共用 risk.py无
starrocksStarRocks共用 risk.py无
zeppelinApache Zeppelin共用 risk.py（含 Spark / shell 规则）无
mongodbMongoDB / Atlas自带 classifypymongo、dnspython
alidocs钉钉 / 阿里文档无，靠 dry-run 和确认提示requests（+oss2 / playwright）

源码一共不到七千行，每个插件的脚本几百行，装之前花半小时读一遍，值得。
