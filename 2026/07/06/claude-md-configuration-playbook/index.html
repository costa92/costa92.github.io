CLAUDE.md 写到 1500 行，规则照样守：真正让规则失效的是放错位置

 costalong  2026-07-06  更新于 2026-11-24  Coding-Agent Claude Code AI 工程实践

这篇文章的旧版本叫「200 行是红线」。那个 200 是官方 memory 文档里的建议值（”target under 200 lines per CLAUDE.md file”，理由是文件越长越占上下文、遵守率越低），我当时原样搬了过来，自己一次也没量过。这次我把它当成一个可以测的说法：同样几条规则，CLAUDE.md 从 50 行涨到 1500 行，Claude 到底还守不守。

结果和我原来写的不一样。在我这个设置里，长度几乎不影响遵守率，影响很大的是规则放在哪、长什么样。长度的代价是实打实的 token。

怎么测的

我写了一个很小的 Go 模块 gw：一个内存 KV 存储、一个配置包、一个时钟包、一个 main.go，没有测试。然后定了 8 条规则，每条都故意选模型自己猜不到、但能用脚本判定的写法：

编号规则怎么判
R1提交信息以 [gw] 开头新提交的标题
R2错误包成 fmt.Errorf("gw: <函数名>: %w", err)新增代码里每个带 %w 的 fmt.Errorf
R3新测试文件命名为 <name>_internal_test.go新增测试文件名
R4只用 log/slog，每次调用带 "component"不出现 log 包和 fmt.Print
R5新增导出函数的注释以 (owner: core) 结尾每个新增导出 func 的注释
R6表驱动测试切片叫 cases、循环变量叫 tc测试里有 for _, tc := range cases
R7CHANGELOG.md 的 ## Unreleased 下加一行文件内容
R8不直接调 time.Now()，用 clock.Now()新增非测试代码

任务是 10 个小改动，比如「给 config 加 LoadConfig，写表驱动测试」「给 Store 加带过期时间的 Set」「写一个 HTTP handler，每个请求打日志」，每个任务末尾都要求 go build 和 go test 通过后提交。提示词里不提任何规则，每个任务只检查它会碰到的那几条，比如没让写测试的任务不查 R3。

CLAUDE.md 做了这几版：

  • 50、200、500、1500 行四个长度。规则原文完全一样，每条自成一个二级标题小节（## Git、## Test files 之类），按从 6% 到 95% 的八个固定相对深度插进去，有的在开头，有的在文件末尾。其余是脚本生成的项目说明，命令、目录、28 个子系统的说明、环境变量表、决策日志，读起来像真项目文件，不和任何规则冲突。
  • import：50 行主文件放全部规则，再用 @docs/subsystems.md 导入 472 行填充。
  • buried：同一份 500 行填充，规则不加标题，直接当成一个列表项塞进某个子系统小节中间。
  • hook：500 行版本删掉 R1 那一行，改用 PreToolUse hook 拦截提交信息不合规的 git commit。
  • none：没有 CLAUDE.md，做对照。

每次运行复制一份干净的模块，git init 后在里面执行：

claude -p "<任务>" --model haiku --output-format stream-json --verbose \
  --max-budget-usd 1 --no-session-persistence \
  --setting-sources project --strict-mcp-config --dangerously-skip-permissions

我这台机器上有一份用户级 ~/.claude/CLAUDE.md，它不能混进实验。Claude Code 2.1.331 的 --setting-sources project 能把它挡掉：我让模型「列出上下文里所有 CLAUDE.md 的路径」，不带这个参数它报出用户级那份文件，带上之后回答 NONE。另外子进程去掉了父会话里以 CLAUDE 开头的环境变量。

搭环境时踩到一个坑：最开始我把实验项目放在 /tmp 下，跑了 48 次才发现项目里的 CLAUDE.md 根本没被自动加载，模型是自己用 cat CLAUDE.md 读到的。同一个目录拷到 $HOME 下面就正常加载了。原因我没有深究，那批数据全部作废重跑。

haiku 每个版本跑 30 到 40 次（10 个任务 × 3 到 4 轮），一共 300 次；sonnet 对 50、500、1500 行各跑 10 次。实验期间撞上一次订阅的 5 小时用量上限，被打断的运行都删掉重跑了。全部按标价估算约 7.5 美元，脚本、各版本 CLAUDE.md 和逐次结果在 blog-go-example/claude-md-length。

从 50 行到 1500 行，遵守率几乎没动

haiku 的结果，分母是该规则适用的次数：

版本R1R2R3R4R5R6R7R8合计
无 CLAUDE.md0/400/160/200/120/320/209/4012/1211%
50 行40/4016/1620/2012/1228/3220/2040/4012/1298%
200 行40/4016/1620/2012/1227/3220/2040/4012/1297%
500 行40/4016/1620/2012/1228/3220/2040/4012/1298%
1500 行30/3012/1215/159/920/2415/1528/309/996%
500 行，@import40/4016/1620/2012/1228/3220/2040/4012/1298%

sonnet 在 50、500、1500 行上都是 47/48。

对照组先说明这 8 条规则确实只能从 CLAUDE.md 学到：没有文件时 R1 到 R6 全是 0。R8 是例外，12 次全对，因为 internal/clock 包就摆在代码里，注释写着测试会替换它，模型看了代码就会用。R7 也有 9 次碰巧更新了 CHANGELOG。代码里已经看得出来的约定，写进 CLAUDE.md 几乎没有增量。

50、200、500 行三档的漏分完全一样，都出在 R5 和同一个任务上：写 HTTP handler 时，模型会定义一个未导出的 statusRecorder 类型，给它实现 WriteHeader 和 Write 两个方法来记录状态码。这两个方法名首字母大写，按规则字面算「导出方法」，模型没给它们加 (owner: core)，但 NewHandler 每次都加了。这是规则本身有歧义，和文件长度无关，三档长度和 sonnet 上都一样。

1500 行多出了 3 次别的漏分：两次 CHANGELOG 没写、一次 Stats() 方法漏了注释后缀。50 到 500 行的 120 次运行里，这类 T05 之外的漏分合计只有 1 次。这可能是长度开始起作用的迹象，但 30 次里多出 3 次，样本太小，我不敢下结论。

同样 500 行，把规则塞进列表就漏了

buried 版本和 500 行版本用的是同一份填充、同样的规则原文，唯一区别是规则没有自己的标题，混在子系统说明的列表里：

规则被放在哪个小节下500 行（独立标题）500 行（埋在列表里）
R1 提交前缀### routing40/4030/30
R2 错误包装### auth16/1612/12
R3 测试文件名### cli20/203/15
R4 slog### featureflags12/129/9
R5 注释后缀### security28/321/24
R6 cases / tc### compaction20/2015/15
R7 CHANGELOG## Decision log40/4030/30
R8 clock.Now()## Decision log12/129/9

R3 和 R5 几乎全军覆没。R3 那 12 次失败里，模型老老实实写了 config_test.go、store_test.go；R5 在 24 次里只对了 1 次，写 handler 的任务里连 NewHandler 都没加后缀。另外六条照样守得很好。

我的猜测是：一条规则落在 ### cli 下面，看起来像是 cli 子系统自己的约定，改 config 和 store 时模型就不把它当回事；同样落在别的小节下的 R1、R2，因为「提交信息」「返回错误」本身就是全局动作，不太会被误读成局部规则。这只是推测，我没有再做把 R3 换到别的小节的对照。能确定的是，在这个实验里，「500 行」不是问题，「500 行里规则看起来像属于某个子系统」才是问题。

长度花掉的是 token

规则守不守跟长度关系不大，钱和上下文却跟长度直接挂钩。每个版本跑一次 Reply OK，看第一次请求的上下文 token（input_tokens 加两项 cache token），两次测量相差不到 10：

写法首轮上下文比没有 CLAUDE.md 多
无 CLAUDE.md22,2120
50 行22,810598
200 行25,6953,483
500 行31,9359,723
1500 行61,69739,485
50 行 + @import 472 行32,0209,808
50 行 + .claude/rules/ 472 行，不带 paths32,0109,798
50 行 + .claude/rules/ 472 行，paths: internal/routing/**22,814602
50 行 + 472 行包在块级 HTML 注释里22,814602

@import 和不带 paths 的 rules 文件一个 token 都不省，内容照样在开场全量展开；带 paths 的 rules 文件在没碰到匹配文件时完全不进上下文；块级 HTML 注释在注入前被剥掉，这和官方文档的说法一致，现在有了数字。

这些 token 每轮都会重新发送，靠缓存打折。落到每次运行的估算费用上，haiku 50 行平均 0.0065 美元，500 行 0.0095，1500 行 0.0165；sonnet 是 0.071、0.114、0.238，1500 行是 50 行的 3.4 倍，而遵守率一样。

行数也不是好的度量单位。我这个博客仓库自己的 CLAUDE.md 现在是 124 行、12.8 KB，放进同一个测试项目里量，开场多了 4,806 token，比上面 200 行的合成文件还多，因为它每行都长。想控制成本，该看 token，不是行数。

一条规则改成 hook：每次都拦，每次都改对

hook 版本把 R1 从 CLAUDE.md 里删掉，在项目的 .claude/settings.json 里配了一个 PreToolUse hook：匹配 Bash，用 if: "Bash(git commit *)" 限定到提交命令（脚本里也再判断了一次），检查提交信息不以 [gw] 开头就往 stderr 写一句「commit message must start with ‘[gw] ‘」，然后 exit 2。

40 次运行，40 次都至少被拦了一次（共 59 次拦截），模型读到 stderr 后全部改成了正确前缀，最终 R1 是 40/40。代价是平均多 1.1 轮（9.2 对 8.1），估算费用多 12%（0.0106 对 0.0095 美元）。

这和文字规则的对比要看清楚：在 500 行文件里写 R1，haiku 也是 40/40，而且不用多花那一轮。hook 的价值不在把 98% 提到 100%，而在它不依赖模型有没有读到、有没有把规则当成全局规则。上一节 R3 从 100% 掉到 20% 的那种情况，hook 不会发生。退出码 2 才会阻断、其他非零码只算非阻塞错误，这些细节以官方 hooks 文档为准。

这个实验没测到的

  • 任务都很短，haiku 平均 7 到 9 轮就结束，单会话，没有触发上下文压缩。官方说的「越长遵守率越低」可能主要出现在长会话里，我这里看不到。
  • 规则只有 8 条，措辞清楚，互不冲突。真实文件里常见的模糊规则、跨文件互相打架的规则，没测。
  • 填充是脚本生成的，重复度比真实文件高。
  • 模型是 2026-11 的 haiku 和 sonnet，Claude Code 2.1.331。换版本数字会变。

我现在怎么写 CLAUDE.md

量完之后我对自己那份文件的处理方式变了：

  1. 每条硬规则单独放在一个看得出是全局约定的位置（独立标题，或者开头一个「项目约定」小节），不再夹在某个模块的说明里。
  2. 只对某类文件有用的说明，比如 scripts/ 下每个脚本做什么，挪进带 paths 的 .claude/rules/ 文件，省的是实打实的 token。用 @import 拆文件只是为了好维护，不省钱。
  3. 代码里已经看得出来的约定不写，测出来写了也几乎没增量。
  4. 一条规则如果违反了会造成实际麻烦（提交格式、禁用某个命令），写成 hook 或 permissions.deny，不指望文字。
  5. 看长度时看 token，用 /memory 确认文件真的被加载了。我在 /tmp 里白跑的那 48 次就是没确认加载的代价。

官方 200 行的建议我还是会参考，理由换了：200 行的 CLAUDE.md 每次请求要多带三四千 token，不是因为过了 200 行模型就不听话。
