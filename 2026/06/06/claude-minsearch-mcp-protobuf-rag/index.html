Claude 想看最新 protobuf 文档？用 minsearch + MCP 搭一个 100 行的迷你 RAG

 2026-06-06  Coding-Agent Claude Code MCP RAG minsearch
Claude Code MCP RAG minsearch protobuf
Coding-Agent
文章字数:   2.3k
阅读次数:  
   阅读模式

上周一个朋友发我一段他们团队 Claude Code 的接入 alias：

alias claude-otel='\
  CLAUDE_CODE_ENABLE_TELEMETRY=1 \
  OTEL_METRICS_EXPORTER=otlp \
  OTEL_LOGS_EXPORTER=otlp \
  OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf \
  OTEL_EXPORTER_OTLP_ENDPOINT=https://usage.example.com \
  claude'

注意中间那行：OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf。Claude Code 的 OpenTelemetry 导出支持 grpc、http/json、http/protobuf 几种协议，这个团队选的是 protobuf 二进制编码——对接可观测性后端的人，迟早要和 protobuf 打交道。

问题来了：你问 Claude “protobuf editions 怎么处理向后兼容”，它的答案取决于训练数据截到哪天。Editions 在 2024 年 5 月的 protobuf 27.0 才正式发布（edition 2023），2025 年 protobuf 32 起又陆续加入 edition 2024 的新特性，模型很可能没见过最新的写法。

重的方案是一整套 RAG（LangChain + 向量库 + embedding API）。轻的方案，是把 minsearch 包成一个 MCP server。下面是约 100 行能跑起来的版本。

为什么是 minsearch 不是 LangChain

minsearch 是 Alexey Grigorev（DataTalksClub 创始人）写的极小搜索引擎，截至 2026-10 在 GitHub 上不到 100 颗星。星少不是问题，它的优势正在于小：核心就几个 Python 文件，依赖只有 numpy、pandas、scikit-learn 和一个分词用的 stemlite，不需要任何服务进程或外部 API。

三种 Index 模式，覆盖绝大多数本地 RAG 场景：

from minsearch import Index, AppendableIndex, VectorSearch

# 1. 基础 TF-IDF 全文检索（90% 文档场景够用）
text_index = Index(
    text_fields=["title", "content"],
    keyword_fields=["section"],
)

# 2. 可追加索引（边爬边索引）
appendable = AppendableIndex(text_fields=["title", "content"])

# 3. 向量检索（你已经有 embedding 的话）
vector_index = VectorSearch(keyword_fields=["section"])

对比一下常见的几种方案：

方案依赖何时该用
minsearch Indexnumpy + pandas + scikit-learn文档量小、单机、关键词检索够用
FAISS / Chroma向量库 + embedding 模型需要语义检索、文档规模大
LangChain RAG框架 + 向量库 + 模型 API要做成产品，而不是个人工具

下面要索引的 4 个 protobuf 页面，抓下来的纯文本合计约 240KB，正好落在 minsearch 的舒适区。

# minsearch 与 mcp 都要求 Python 3.10+
pip install minsearch
# 或者 uv add minsearch

把 protobuf 文档喂给 minsearch

protobuf.dev 上四个核心 Programming Guide 页面覆盖了大部分日常问题——proto3、encoding、editions、proto2。先把它们抓下来（需要 pip install httpx）：

# download_docs.py
import httpx
from pathlib import Path
from html.parser import HTMLParser

DOC_URLS = [
    "https://protobuf.dev/programming-guides/proto3/",
    "https://protobuf.dev/programming-guides/encoding/",
    "https://protobuf.dev/programming-guides/editions/",
    "https://protobuf.dev/programming-guides/proto2/",
]

class TextOnly(HTMLParser):
    def __init__(self):
        super().__init__()
        self.skip = False
        self.parts = []
    def handle_starttag(self, tag, attrs):
        if tag in ("script", "style", "nav", "header", "footer"):
            self.skip = True
    def handle_endtag(self, tag):
        if tag in ("script", "style", "nav", "header", "footer"):
            self.skip = False
    def handle_data(self, data):
        if not self.skip and data.strip():
            self.parts.append(data)

Path("data/protobuf").mkdir(parents=True, exist_ok=True)
for url in DOC_URLS:
    slug = url.rstrip("/").rsplit("/", 1)[-1]
    parser = TextOnly()
    parser.feed(httpx.get(url, timeout=20).text)
    Path(f"data/protobuf/{slug}.md").write_text("\n".join(parser.parts))
    print(f"saved {slug}")

跑一遍，本地就有 data/protobuf/proto3.md 这样的纯文本文件。下一步切片 + 索引。切片别太复杂，按空行分段够用：

# build_index.py
import pickle
from pathlib import Path
from minsearch import Index

DOC_BASE = "https://protobuf.dev/programming-guides"
docs = []

for path in Path("data/protobuf").glob("*.md"):
    text = path.read_text()
    # 按段落切片，每片 ≥ 100 字才算有效
    for i, chunk in enumerate(text.split("\n\n")):
        chunk = chunk.strip()
        if len(chunk) < 100:
            continue
        docs.append({
            "id": f"{path.stem}#{i}",
            "source": path.stem,             # proto3 / encoding / ...
            "url": f"{DOC_BASE}/{path.stem}/",
            "content": chunk,
        })

index = Index(
    text_fields=["content"],
    keyword_fields=["source"],
)
index.fit(docs)
Path("index.pkl").write_bytes(pickle.dumps(index))
print(f"indexed {len(docs)} chunks → index.pkl")

我在 Python 3.12 + minsearch 0.2.0 上跑这一步，4 个页面切出 402 个片段，建索引不到 1 秒。试一下检索：

>>> import pickle
>>> idx = pickle.loads(open("index.pkl", "rb").read())
>>> for hit in idx.search("editions backward compatible", num_results=3):
...     print(hit["source"], hit["content"][:80])
encoding [packed=true]  to existing fields in a forward- and backward-compatible way. One
proto3 compatible with the other integer types. If the value written was between INT_MI
proto2 compatible with the other integer types. If the value written was between INT_MI

具体命中哪几段取决于抓取当天的页面内容，能返回含查询词的片段，就说明 TF-IDF 索引建对了。

写一个 100 行的 MCP server

MCP（Model Context Protocol）是 Anthropic 发起的 LLM 工具协议，Claude Code 原生支持。官方 Python SDK 把样板代码压到了一个装饰器。注意 SDK 在 2.x 把 FastMCP 改名成了 MCPServer（截至 2026-10 最新是 2.3.0），网上大量 from mcp.server.fastmcp import FastMCP 的示例在 2.x 下会直接报 ModuleNotFoundError：

# server.py
import pickle
from pathlib import Path
from mcp.server.mcpserver import MCPServer  # mcp 1.x 写法：from mcp.server.fastmcp import FastMCP

mcp = MCPServer("protobuf-docs")  # mcp 1.x：FastMCP("protobuf-docs")

# 进程启动时加载一次索引；按脚本所在目录找文件，因为 Claude Code 启动它时的工作目录不一定是这里
_INDEX = pickle.loads(Path(__file__).with_name("index.pkl").read_bytes())

@mcp.tool()
def search_protobuf_docs(query: str, num_results: int = 5) -> list[dict]:
    """检索 protobuf 官方文档。

    Args:
        query: 自然语言查询，例如 "editions backward compatible"
        num_results: 返回结果数，默认 5

    Returns:
        命中片段列表，每项含 source（页面）、url（原文链接）、content（正文）
    """
    hits = _INDEX.search(query, num_results=num_results)
    return [
        {"source": h["source"], "url": h["url"], "content": h["content"]}
        for h in hits
    ]

if __name__ == "__main__":
    mcp.run(transport="stdio")

有四个细节值得注意：

第一，索引在模块级加载——MCP server 是常驻进程，启动时反序列化一次就够，没必要每次 query 都重新读文件。

第二，索引路径用 Path(__file__) 定位——如果写成相对路径 Path("index.pkl")，Claude Code 在别的项目目录里拉起这个进程时就会找不到文件，server 启动即退出。

第三，工具的 docstring 不是写给人看的——它会作为工具描述发给 Claude，决定它什么时候、用什么参数调用。描述越具体（查什么、返回什么），被正确调用的概率越高；一句含糊的”搜索文档”很容易被忽略。

第四，transport=stdio——Claude Code 把 stdio 类型的 MCP server 作为子进程启动，通过标准输入输出通信，不需要起 HTTP 服务、不需要管端口。本地个人工具先用 stdio 跑通，有多人共享的需求再考虑 HTTP。

装一下 MCP 包：

pip install mcp          # 装到的是 2.x
# 想继续用 FastMCP 的 1.x 写法：pip install "mcp<2"
# 或者 uv add mcp

这份 server 我分别用 mcp 2.3.0（MCPServer）和 1.30.0（FastMCP）起过，用 SDK 自带的 stdio 客户端都能列出 search_protobuf_docs 并正常返回结果。

本地先单独跑一下确认没报错：

python server.py
# 它会卡在 stdio 等输入——正常。Ctrl-C 退出。

接到 Claude Code 里

Claude Code 注册 MCP server 有两种姿势：CLI 一行命令，或者写 .mcp.json。先讲 CLI——快：

# `--` 之后的部分会作为 stdio 子进程启动；python 要用装了 minsearch 和 mcp 的那个解释器
claude mcp add protobuf-docs -- /abs/path/to/.venv/bin/python /abs/path/to/server.py

注册完用 claude mcp list 检查，应该能看到 protobuf-docs 在列。不带 --scope 时默认只对当前项目、当前用户生效。

如果你想把这个配置提交到 git（团队共享），改写成项目级 .mcp.json：

{
  "mcpServers": {
    "protobuf-docs": {
      "command": "/abs/path/to/.venv/bin/python",
      "args": ["/abs/path/to/server.py"],
      "env": {
        "PYTHONUNBUFFERED": "1"
      }
    }
  }
}

放在项目根目录，下次在这个项目里启动 claude 时会读取它；项目级 server 第一次使用前，Claude Code 会让你确认是否信任。

验证它真的能用——打开 Claude Code，问一句：

editions 模式下 proto2 的 required 字段会怎样？

理想情况下 Claude 会主动调一次 search_protobuf_docs，查询词类似 “editions proto2 required”，再把命中片段当 context 回答（editions 里 proto2 的 required 对应 features.field_presence = LEGACY_REQUIRED）。如果它没调，多半是工具描述不够具体——给 docstring 补一句”用于查询 protobuf 语法、editions、编码相关问题”这类说明，或者在提问时直接点名让它先查文档。

通用化：换个文档源就能复用

这套结构最实用的地方是只有 download_docs.py 和 DOC_BASE 那一行跟 protobuf 绑定，其余代码都能直接复用。

想换成索引 OTLP 规范文档？改 URL 列表，再把 build_index.py 里拼 url 的那行改成对应站点：

# download_docs.py 的 DOC_URLS 改成：
DOC_URLS = [
    "https://opentelemetry.io/docs/specs/otlp/",
    "https://opentelemetry.io/docs/specs/semconv/",
    # ...
]

想换成语义检索（embedding）而不是 TF-IDF？把 Index 换成 VectorSearch，加一步 embedding。代价是查询时也得先把 query 转成向量，server 里的 search 调用要跟着改：

# build_index.py 的索引部分换成
from minsearch import VectorSearch
from openai import OpenAI

client = OpenAI()
embeddings = [
    client.embeddings.create(model="text-embedding-3-small", input=d["content"]).data[0].embedding
    for d in docs
]
index = VectorSearch(keyword_fields=["source"])
index.fit(embeddings, docs)

什么时候该升级到 FAISS / Chroma / Qdrant？文档量大到每次全量重建索引、或者整个索引放进内存都开始吃力，或者需要多个进程共享同一份索引的时候。minsearch 作者另外写了个 sqlitesearch，定位就是 minsearch 的持久化替代，适合介于两者之间的规模。

约 100 行 Python 让 Claude 查到最新文档，比微调模型便宜得多，也比每次在 prompt 里塞几百 KB 文档省 token。

下次 Claude 答非所问的时候，先想想是不是它训练数据里压根没有那个新版本特性，再决定要不要给它配一个本地索引。
