用 Docker 自建 SearXNG，给 Claude 当搜索后端

 2026-06-06  Tool MCP Docker SearXNG 元搜索引擎

阅读次数:  
   阅读模式

搜个技术问题，Google 第一页常常是 SEO 农场；换 Bing，广告比结果还多；DuckDuckGo 不错，但结果质量不稳定。自己跑一个 SearXNG 之后，”自己掌控搜索入口”这件事的门槛其实很低：一条 Docker 命令起服务，聚合多个搜索源，无 cookie、无画像，搜索记录留在自己机器上。

更实际的用途是给 AI 当搜索后端。SearXNG 有标准的 JSON 接口，接进 Claude Desktop、Claude Code 或者自己写的 Claude API 应用，就有了一个不按次计费的搜索工具。本文覆盖：Docker / Compose 部署、settings.yml 关键项、反向代理、常见坑，以及三种接入 Claude 的方式。

SearXNG 是什么

SearXNG 是一个元搜索引擎（metasearch engine）：自己不抓网页，而是把你的查询同时发给 Google、Bing、Brave、DuckDuckGo、Startpage、Wikipedia 等搜索源，把结果去重、排序、合并后展示。

它和 DuckDuckGo 的区别在于：DuckDuckGo 是别人运营的服务，你只能相信它的隐私承诺；SearXNG 是你自己部署的服务端，请求从浏览器到你的实例，再由实例代你去问各个上游，中间没有需要信任的第三方。

几个基本事实（来自官方仓库和文档）：

  • 许可证：AGPL-3.0；
  • 技术栈：Python，容器镜像里用 Granian 作为应用服务器，相关参数通过 $GRANIAN_* 环境变量配置；
  • 缓存：可选接 Valkey（Redis 的分支），主要用于限流（limiter）等功能，单纯搜索不依赖它；
  • 镜像：docker.io/searxng/searxng，版本号是日期格式，比如 2026.6.5-xxxxxxx。

适合谁：有自托管习惯的人，不想被单一搜索源绑定的人，想给团队或家人提供统一搜索入口的人，以及需要一个免费搜索 API 喂给 LLM 的人。
不适合谁：完全不想运维的人（直接用 DuckDuckGo 或 Kagi）；高 QPS、对延迟敏感的生产场景（单实例扛不住，而且上游会限流）。

Docker 一行启动

先说部署方式的变化：以前流行的 searxng/searxng-docker 仓库已经归档，官方现在的容器方案放在主仓库的 container/ 目录下，文档见 Installation container。最快的方式是文档里这条 docker run：

docker run --name searxng -d \
    -p 8888:8080 \
    -v "./config/:/etc/searxng/" \
    -v "./data/:/var/cache/searxng/" \
    docker.io/searxng/searxng:latest

逐项说明：

  • -p 8888:8080：宿主机 8888 映射到容器内的 8080（容器默认监听 8080）；
  • -v "./config/:/etc/searxng/"：配置目录，settings.yml 在这里；
  • -v "./data/:/var/cache/searxng/"：数据目录，持久化缓存；
  • 镜像支持 amd64 和 arm64。

容器启动时如果发现 /etc/searxng/settings.yml 不存在，会从模板复制一份，并把里面的 secret_key 占位值替换成随机串。所以第一次不用准备任何配置文件，跑起来后去 ./config/settings.yml 改就行。

浏览器打开 http://localhost:8888 就是上面那张首页。命令行验证一下：

curl -s -o /dev/null -w "HTTP %{http_code}\n" http://localhost:8888/
# HTTP 200

Compose 部署

长期使用建议用 Compose，把 SearXNG 和 Valkey 编排在一起。官方模板在主仓库的 container/ 下：

mkdir -p ./searxng/core-config/
cd ./searxng/
curl -fsSL \
    -O https://raw.githubusercontent.com/searxng/searxng/master/container/docker-compose.yml \
    -O https://raw.githubusercontent.com/searxng/searxng/master/container/.env.example
cp .env.example .env
docker compose up -d

docker-compose.yml 定义了两个服务：core（容器名 searxng-core）和 valkey（容器名 searxng-valkey，只在内部网络暴露 6379）。.env 里可以设置：

# 固定镜像版本，默认 latest
#SEARXNG_VERSION=latest
# 监听地址和端口，默认 8080
#SEARXNG_HOST=127.0.0.1
#SEARXNG_PORT=8080

注意两点：

  1. Compose 模式默认端口是 8080，不是 8888，而且容器内外用的是同一个 SEARXNG_PORT。8080 被占了就改 .env，不用动 yaml。只给本机或反代用的话，把 SEARXNG_HOST 设成 127.0.0.1，避免直接暴露到公网。
  2. Valkey 起来了不等于 SearXNG 在用它。 默认 settings.yml 里 valkey.url 是 false。要启用限流（server.limiter: true）等依赖 Valkey 的功能时，把地址指向 Compose 里的服务名：
valkey:
  url: valkey://valkey:6379/0

升级按官方文档的三步：

docker compose down
docker compose pull
docker compose up -d

下文的例子沿用 docker run 的 8888 端口，Compose 用户自行换成 8080。

settings.yml 关键项

配置文件在容器内是 /etc/searxng/settings.yml，对应宿主机的 ./config/settings.yml（docker run）或 ./searxng/core-config/settings.yml（Compose）。改完需要重启容器才生效：docker restart searxng 或 docker compose restart core。

打开 JSON 输出（接 API 和 MCP 必改）

默认配置只开了 HTML 输出：

search:
  formats:
    - html

这时请求 format=json 会直接返回 403 Forbidden。后面所有 API、MCP 接入都依赖 JSON，所以先把它加上：

search:
  formats:
    - html
    - json

重启后验证：

curl -s "http://localhost:8888/search?q=docker+pull&format=json" \
    | jq '.results[0:2][] | {title, url, engine}'

每条结果包含 title、url、content（摘要）、engine（来自哪个上游）等字段，结构自描述，RAG 管道可以直接消费。注意：实例一旦暴露到公网，开放 JSON 接口就等于开放了一个免费搜索 API，务必配合下文的限流。

secret_key

容器首次启动会自动生成随机的 secret_key。如果你是从别处拷来的 settings.yml，确认它不是默认的 ultrasecretkey，否则自己换一个：

openssl rand -hex 32

也可以不改文件，用环境变量 SEARXNG_SECRET 覆盖。

启用和禁用引擎

引擎列表在 engines: 段，每个引擎用 disabled: true 关掉，不写这一项就是启用：

engines:
  - name: google
    engine: google
    shortcut: go
    disabled: true     # 关掉 Google
  - name: duckduckgo
    engine: duckduckgo
    shortcut: ddg

哪些引擎默认启用，不同版本会调整，以你自己 settings.yml 里的实际值为准。经常超时的引擎可以单独加 timeout: 5.0（秒）覆盖全局的 outgoing.request_timeout（默认 3 秒）。

普通用户也可以在浏览器里改：/preferences 的”搜索引擎”标签页，每行一个引擎，可以开关，并能看到权重、响应时间、可靠性等信息。这里的修改存在浏览器 cookie 里，只影响当前浏览器：

出站代理

如果你的服务器访问不了部分上游（国内网络环境下很常见），所有引擎都会超时。SearXNG 支持给出站请求配代理：

outgoing:
  proxies:
    all://:
      - http://127.0.0.1:7890

代理地址换成你自己的。容器里的 127.0.0.1 指容器本身，代理跑在宿主机上的话，要用宿主机在 Docker 网络里的地址。

反向代理 + HTTPS

要给家人或团队用，或者想绑域名，就加一层反向代理并上 HTTPS。Caddy 最省事，证书自动申请、自动续期。域名是 search.example.com 的话：

search.example.com {
    reverse_proxy 127.0.0.1:8888
}

Nginx 思路一样，只是证书要自己用 certbot 或 acme.sh 管：

server {
    listen 443 ssl;
    http2 on;
    server_name search.example.com;

    ssl_certificate     /etc/letsencrypt/live/search.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/search.example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8888;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

公网实例建议：在反代上做限流，同时开启 SearXNG 自带的 server.limiter（需要 Valkey，见上文），否则很快会被人当免费搜索 API 刷，上游也会因此封你的出口 IP。

常见的坑

访问 8888 超时或 connection refused：先看容器是否在跑、端口是否绑定：

docker ps --filter "name=searxng" --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}"

端口没列出来，或者容器反复重启，就看 docker logs searxng。宿主机 8888 被别的程序占用时，换成 -p 8889:8080。

页面能打开，但搜索结果全空、右侧全是”超时”：

这几乎都是出站网络问题：实例访问不到上游搜索引擎。容器默认和宿主机走同一个出口，先在宿主机上测一下连通性，不通就按上文配 outgoing.proxies：

curl -sI -m 5 https://duckduckgo.com | head -1

另外检查是不是把引擎全禁用了，这种情况下 SearXNG 不报错，只是搜不出东西。

format=json 返回 403：search.formats 里没有 json，见上文。

改了 settings.yml 后容器起不来：多半是 YAML 缩进或语法错误。看 docker logs searxng（Compose 用 docker compose logs core），报错会指出出错位置。改之前先备份一份能用的配置。

接入 Claude

SearXNG 的 JSON 接口可以通过 MCP 或者自定义工具接给 Claude。下面三种方式按上手成本从低到高排列。前提都是上文已经打开了 JSON 输出。

Claude Desktop：mcp-searxng

社区维护的 mcp-searxng 把 SearXNG 包装成 MCP server，提供 searxng_web_search（搜索）和 web_url_read（读取网页正文）两个工具。它是 npm 包，需要 Node.js 22 或更高版本。

macOS 上编辑 ~/Library/Application Support/Claude/claude_desktop_config.json：

{
  "mcpServers": {
    "searxng": {
      "command": "npx",
      "args": ["-y", "mcp-searxng"],
      "env": {
        "SEARXNG_URL": "http://localhost:8888"
      }
    }
  }
}

改完彻底退出 Claude Desktop 再打开（菜单栏 Quit，不是关窗口），在工具列表里看到 searxng 的两个工具就说明接通了。

隐私上要分清：SearXNG 这一侧不留记录，但对话内容（包括搜索关键词）仍然会发给 Claude。

Claude Code

项目级配置写在仓库根目录的 .mcp.json：

{
  "mcpServers": {
    "searxng": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "mcp-searxng"],
      "env": {
        "SEARXNG_URL": "http://localhost:8888"
      }
    }
  }
}

或者用 CLI 添加（默认只对当前项目、当前用户生效，加 -s project 会写进 .mcp.json）：

claude mcp add -e SEARXNG_URL=http://localhost:8888 searxng -- npx -y mcp-searxng

之后 Claude Code 里会出现 mcp__searxng__searxng_web_search 这样的工具（命名规则是 mcp__<server>__<tool>），需要查资料时它会自己调用，你也可以在提示里直接说”用 searxng 查一下”。

团队协作时，各人的 SearXNG 地址往往不同（端口不同，或者用的是反代域名）。可以在 .mcp.json 里写 "SEARXNG_URL": "${SEARXNG_URL}"，让每个人在自己的环境变量里设置，而不是把某个人的地址提交进仓库。

Claude API：自定义 web_search 工具

自己写应用时，把 SearXNG 包成一个工具交给 Claude 即可。下面是完整的多轮 tool_use 循环：Claude 可能连续调用多次搜索，每一轮都要把 assistant 的完整回复和所有 tool_result 追加进对话历史，直到它不再请求工具。

import anthropic
import requests

client = anthropic.Anthropic()
SEARXNG = "http://localhost:8888"
MODEL = "claude-sonnet-5-5"


def web_search(query: str, max_results: int = 5) -> str:
    r = requests.get(
        f"{SEARXNG}/search",
        params={"q": query, "format": "json"},
        timeout=15,
    )
    r.raise_for_status()
    results = r.json()["results"][:max_results]
    return "\n".join(
        f"- [{x['title']}]({x['url']}): {x.get('content', '')}" for x in results
    )


tools = [{
    "name": "web_search",
    "description": (
        "Search the web via a self-hosted SearXNG instance. "
        "Use for information that may be newer than your training data."
    ),
    "input_schema": {
        "type": "object",
        "properties": {
            "query": {"type": "string", "description": "搜索关键词"},
            "max_results": {"type": "integer", "description": "返回条数，默认 5"},
        },
        "required": ["query"],
    },
}]


def ask(question: str) -> str:
    messages = [{"role": "user", "content": question}]
    while True:
        resp = client.messages.create(
            model=MODEL, max_tokens=4096, tools=tools, messages=messages,
        )
        if resp.stop_reason != "tool_use":
            return "".join(b.text for b in resp.content if b.type == "text")

        # 原样追加 assistant 回复，再把本轮所有工具结果放进同一条 user 消息
        messages.append({"role": "assistant", "content": resp.content})
        results = []
        for block in resp.content:
            if block.type != "tool_use":
                continue
            try:
                content, is_error = web_search(**block.input), False
            except Exception as e:
                content, is_error = f"search failed: {e}", True
            results.append({
                "type": "tool_result",
                "tool_use_id": block.id,
                "content": content,
                "is_error": is_error,
            })
        messages.append({"role": "user", "content": results})


print(ask("SearXNG 的引擎权重（weight）是怎么影响排序的？"))

几个要点：

  • 历史要累积：每轮都把 resp.content 原样追加回去，不要只拼第一轮的消息，否则多轮搜索时 Claude 会丢掉前面的上下文；
  • 同一轮的多个 tool_use 一起回：Claude 可能一次并行发起多个搜索，所有 tool_result 放进同一条 user 消息；
  • 失败也要回结果：搜索出错时返回 is_error: True 的 tool_result，让 Claude 自己决定换关键词还是放弃，而不是让循环直接崩掉；
  • 控制返回体积：搜索结果会进入上下文，max_results 不宜太大，摘要过长可以截断。

和商业搜索 API 相比，自建 SearXNG 没有按次计费和月度额度，代价是要自己运维、延迟更高（多源聚合要等最慢的上游或超时），而且上游引擎可能因请求过多临时封禁你的出口 IP。重复查询多的场景，在 web_search 外面加一层短时缓存会有明显收益。

如果你已经有一个自己的搜索聚合服务（比如把 SearXNG 和其他搜索 API、网页抓取服务组合成一个 MCP server），接入方式也一样：在服务的配置里把 SearXNG 地址设成 SEARXNG_URL=http://localhost:8888，它就成了一个免费、可控的聚合底座。我自己的做法正是这样，搜索请求优先走本地 SearXNG，失败再降级到其他搜索源。

下一步可以研究的是引擎权重（weight）调优，以及公网实例的限流和防刷配置。
