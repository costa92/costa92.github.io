我用Cloudflare Workers跑了一个24小时在线的AI助手，月费不到35刀

 2026-02-04  Coding-Agent Cloudflare OpenClaw 云端部署 Workers
Cloudflare OpenClaw 云端部署 Workers AI助手
Coding-Agent
文章字数:   6.1k
阅读次数:  
   阅读模式

最近折腾了一件事：把 OpenClaw 扔到 Cloudflare 上跑，让它变成一个随时可用的私人 AI 助手。过程中踩了不少坑，但最终的效果出乎意料地好——它可以直接访问外网，24 小时待命，还能接入 Discord 当聊天机器人用。

整件事的核心是 Cloudflare 开源的 Moltworker 项目（https://github.com/cloudflare/moltworker ），它帮你把容器化的 OpenClaw 跑在 Workers 上。不过这东西绝不只是帮你起了个容器那么简单——它集成了浏览器自动化能力（网页截图、数据抓取），通过 R2 对象存储实现了数据持久化（容器重启也不丢数据），甚至给你搭好了管理后台，可以审批设备、查看备份、重启进程。安全方面直接接入了 Cloudflare Access 做身份认证。

项目状态提醒
Moltworker 是实验性项目，Cloudflare 官方并未提供正式的技术支持，后续更新可能引入破坏性变更。截至 2026-10，仓库最后一次提交是 2026-03-29，之后没有新的更新。建议做好数据备份，不要把它当作唯一的关键基础设施。

我现在把聊天渠道接到了 Discord，实测体验比 Telegram 和 Slack 都要好，响应速度快，消息格式支持也好。

这个方案到底解决了什么问题

说白了就是：不买服务器，不装 Docker，不搞运维，让 AI 助手跑在别人的基础设施上。

我之前用 VPS 部署过类似服务，系统更新、安全补丁、进程守护一堆事情要操心。现在换成 Workers Sandbox 容器，这些全不用管了——它自己扩缩容，冷启动后常驻内存，入门门槛就是一个 $5/月的 Workers Paid 订阅。

安全层面做了什么

这套方案的认证不是随便设个密码就完事。它分了三道关卡：

第一道是 Cloudflare Access 登录，你得先通过 Zero Trust 的邮箱验证。第二道是 Gateway Token 校验，URL 里必须带正确的 Token 才能进入。第三道是设备配对审批，新设备首次连接需要管理员在后台手动放行。

三层认证叠在一起，基本不用担心被人白嫖。

数据怎么不丢

Workers 本身是无状态的，容器一重启什么都没了。Moltworker 的解决方案是每 5 分钟把数据备份到 R2（Cloudflare 的对象存储），下次启动的时候自动从 R2 恢复。这种方式比较粗暴，但确实管用——对话记录和设备配对信息都能保住。

从零开始搭建

环境准备

开始之前确认三件事情都到位：

  • Cloudflare Workers Paid 订阅已开通（$5/月，免费版不支持 Sandbox 容器）
  • 本地装好了 Node.js 和 Docker（部署脚本需要在本地打包容器镜像；截至 2026-10，最新版 Wrangler 要求 Node.js 22+）
  • 准备好你要用的 AI 模型密钥（DeepSeek、OpenRouter、Google AI Studio 都行）

安装 Wrangler 命令行工具

Wrangler 是 Cloudflare Workers 的 CLI 管理工具，后续所有操作——部署代码、注入密钥、查看日志——都得通过它。

Moltworker 的配置里有大量敏感信息（API Key、Bot Token、存储密钥等），这些不能明文写在代码里。Wrangler 提供了 secret put 命令，以加密方式把这些值注入到 Worker 运行环境中。

npm i -D wrangler@latest

装完之后登录你的 Cloudflare 账号：

npx wrangler login

浏览器会弹出授权页面，点允许就行。

拉取代码并安装依赖

git clone git@github.com:cloudflare/moltworker.git
cd moltworker
npm install

配置 AI 模型接入

这里有两条路可以走。

如果你有 Anthropic 的 API Key，最省事的做法是直接注入：

npx wrangler secret put ANTHROPIC_API_KEY

但我手上没有 Anthropic 的 Key，所以选了 Cloudflare AI Gateway 做中转。这玩意儿的好处是能在后台看到每次调用的 Token 消耗明细，对控制成本很有帮助。

AI Gateway 的两种配置方式
本文用的是 AI_GATEWAY_API_KEY + AI_GATEWAY_BASE_URL 直接拼完整地址的方式。截至 2026-10，Moltworker README 已把这种写法标为旧方式（仍兼容但不推荐），推荐改用三个变量：CLOUDFLARE_AI_GATEWAY_API_KEY（上游模型提供商的 Key，经网关转发）、CF_AI_GATEWAY_ACCOUNT_ID、CF_AI_GATEWAY_GATEWAY_ID，可选 CF_AI_GATEWAY_MODEL 指定模型（格式 provider/model-id）。新方式一次只能走一个提供商；需要多个提供商并存时，可以继续用下文在 OpenClaw 配置里写多个 provider 的办法。

创建 AI Gateway

在 Cloudflare 控制台找到「计算和AI」菜单下的 AI Gateway 入口。

新建一个网关，名字随意取（建议用纯英文小写加连字符，比如 openclaw-gateway，因为这个名字会出现在 URL 路径里）。

我接入了 DeepSeek 和 Google AI Studio 两个提供商。

添加模型提供商的密钥

在 Gateway 页面点 Add，把你自己的 DeepSeek API Key 或 Google AI Studio API Key 填进去。注意，Gateway 只是个代理层，实际调用的还是上游模型服务，所以这里必须填你自己的 Key。

生成 Gateway 的访问令牌

在 Gateway 页面右侧找到 Create a token，创建一个专用于这个 Gateway 的 API 令牌。

复制生成的 Token——这是 Gateway 级别的认证凭据，跟上面的 DeepSeek Key 是两回事。

把 Gateway 信息注入 Worker

回到终端，依次执行：

# 注入 Gateway 令牌
npx wrangler secret put AI_GATEWAY_API_KEY

执行这条命令时，Wrangler 会在 Cloudflare 上自动创建一个叫 moltbot-sandbox 的 Worker 实例。

接下来设置 Gateway 的地址，格式是 https://gateway.ai.cloudflare.com/v1/{你的账户ID}/{网关名}/{提供商}：

npx wrangler secret put AI_GATEWAY_BASE_URL
# 填入类似: https://gateway.ai.cloudflare.com/v1/<账户ID>/openclaw-gateway/deepseek

URL 末尾不要加斜杠，提供商名称区分大小写（deepseek 而不是 DeepSeek）。

生成管理后台的登录凭证

这个 Token 是你访问 AI 助手管理界面的钥匙，泄露了等于把控制权拱手让人。

# 生成 64 位随机字符串作为凭证
export MOLTBOT_GATEWAY_TOKEN=$(openssl rand -hex 32)

# 先看一眼，复制保存好
echo "你的 Token: $MOLTBOT_GATEWAY_TOKEN"

# 注入到 Worker 环境
echo "$MOLTBOT_GATEWAY_TOKEN" | npx wrangler secret put MOLTBOT_GATEWAY_TOKEN

部署完成后，访问地址格式为：

https://你的worker名.workers.dev/?token=你的64位Token

两个 Token 别搞混了：

名称干什么用
MOLTBOT_GATEWAY_TOKEN登录管理后台和聊天界面
AI_GATEWAY_API_KEYWorker 连接 AI Gateway 用

接入 Cloudflare Access 身份认证

开启 Access 保护

进入 Workers & Pages，找到 moltbot-sandbox 这个 Worker，在「设置 → 域和路由」里找到 workers.dev 域名，点右侧三个点，启用 Cloudflare Access。

获取认证所需的两个参数

Worker 在收到请求时需要验证用户身份——它得知道去哪个认证服务器校验、校验的是哪个应用。这就需要两个值：

# 你的 Zero Trust 团队域名（格式：xxx.cloudflareaccess.com，不带 https://）
npx wrangler secret put CF_ACCESS_TEAM_DOMAIN

# Access 应用的受众标签（64 位十六进制字符串）
npx wrangler secret put CF_ACCESS_AUD

打个比方，CF_ACCESS_TEAM_DOMAIN 就像公安局的地址——Worker 要去那里验证身份证的真伪。CF_ACCESS_AUD 就像你的身份证号——确认这张证确实是发给你的，不是别人的。

在哪找这两个值？

CF_ACCESS_TEAM_DOMAIN：进入 Zero Trust Dashboard，首页就能看到 Team domain。

CF_ACCESS_AUD：在 Zero Trust Dashboard → Access → Applications 里，点进你的应用，复制那串 Application Audience (AUD) Tag。

配置 R2 存储实现数据持久化

Workers 天生无状态，如果不额外配置存储，容器每次重启都会”失忆”。

部署时系统一般会自动创建 moltbot-data 存储桶，我们要做的是给 Worker 授权去读写它。

创建存储访问凭证

在 Cloudflare 控制台进入 R2 页面，点击 Manage R2 API Tokens。

创建新的 User API 令牌，权限选 Object Read & Write，范围建议锁定到 moltbot-data 这一个桶。

创建完毕后会显示 Access Key ID 和 Secret Access Key，这两个值只出现一次，务必保存。

注入存储相关密钥

npx wrangler secret put R2_ACCESS_KEY_ID
# 粘贴 Access Key ID

npx wrangler secret put R2_SECRET_ACCESS_KEY
# 粘贴 Secret Access Key

npx wrangler secret put CF_ACCOUNT_ID
# 粘贴你的 Cloudflare 账户 ID（在控制台首页右侧可以复制）

执行部署

所有密钥都配好了，运行部署命令：

npm run deploy

终端会输出你的 Worker 访问地址。

首次访问

用浏览器打开拼接好的地址：

https://your-worker.workers.dev/?token=YOUR_GATEWAY_TOKEN

Access 会要求你输入邮箱验证——这个邮箱必须在你的 Access 策略允许列表里。

验证通过后会进入 OpenClaw 界面。首次访问通常要等 1-2 分钟，这是 Sandbox 容器冷启动的时间。

进入后先别急着聊天，按照页面提示跳转到 Admin 后台，把当前设备审批通过。

审批完就可以正常对话了。

绑定自定义域名

默认的 xxx.workers.dev 域名在国内访问体验不太好，建议绑一个自己的域名。

在 Cloudflare Dashboard 里进入 Workers & Pages → 找到 moltbot-sandbox → 设置 → 域和路由，点击「添加」→「自定义域」，输入你想绑定的域名（比如 ai.yourdomain.com）。前提是这个域名的 DNS 已经托管在 Cloudflare 上。

绑定完成后，系统会自动配置 SSL 证书和 DNS 记录，通常几分钟内生效。之后你可以通过 https://ai.yourdomain.com/?token=你的Token 访问。

Access 策略同步
如果你之前配置了 Cloudflare Access，记得在 Zero Trust → Access → Applications 里把新域名也加进去，否则自定义域名可能会绕过认证直接访问。

接入 AI 模型的具体配置

部署好之后，默认的模型配置大概率是不对的。因为我们没法 SSH 到容器里改文件，所以直接在 OpenClaw 的 Web 界面操作：点击左侧 Config，切换到 Raw 模式，手动编辑 JSON 配置。

DeepSeek 配置

需要同时配两块内容——先定义模型提供商，再指定默认使用的模型：

{
  "models": {
    "providers": {
      "deepseek": {
        "baseUrl": "https://gateway.ai.cloudflare.com/v1/你的账户ID/openclaw-gateway/deepseek",
        "apiKey": "你的Gateway_Token",
        "api": "openai-completions",
        "models": [
          {
            "id": "deepseek-chat",
            "name": "DeepSeek Chat",
            "reasoning": false,
            "input": ["text"],
            "cost": {
              "input": 0,
              "output": 0,
              "cacheRead": 0,
              "cacheWrite": 0
            },
            "contextWindow": 128000,
            "maxTokens": 8192
          }
        ]
      }
    }
  }
}

这里的 apiKey 填的是 Cloudflare AI Gateway 的 Token，不是 DeepSeek 自己的 Key（DeepSeek 的 Key 已经在 Gateway 的 Provider 里配过了）。

然后设置默认模型：

{
  "agents": {
    "defaults": {
      "model": {
        "primary": "deepseek/deepseek-chat"
      }
    }
  }
}

primary 的格式是 provider名/模型id，两者必须和上面的定义完全对应。改完点 Apply 即可生效。DeepSeek API 的上下文窗口是 128K，contextWindow 不要填得比实际大，否则上下文压缩会来不及触发。cost 全填 0 只是为了不在 OpenClaw 里统计费用，实际花费以 DeepSeek 和 AI Gateway 后台为准。

走 AI Gateway 的好处是，在 Cloudflare 后台可以看到每一条请求的 Token 消耗详情。

OpenRouter 配置（零成本方案）

OpenRouter 提供一个 openrouter/free 路由，会把请求转发到当时可用的某个免费模型，适合不想花钱的场景。注意它背后的模型不固定，有些免费模型的工具调用格式 OpenClaw 解析不了，具体现象和处理办法见 OpenClaw 进阶实战 里的常见问题。

首先在 Gateway 页面添加 OpenRouter 的提供商密钥：

然后在 OpenClaw 配置里追加：

{
  "models": {
    "providers": {
      "openrouter": {
        "baseUrl": "https://gateway.ai.cloudflare.com/v1/你的账户ID/openclaw-gateway/openrouter/v1",
        "apiKey": "你的Gateway_Token",
        "api": "openai-completions",
        "models": [
          {
            "id": "openrouter/free",
            "name": "Openrouter free",
            "reasoning": false,
            "input": ["text", "image"],
            "cost": {
              "input": 0,
              "output": 0,
              "cacheRead": 0,
              "cacheWrite": 0
            },
            "contextWindow": 200000,
            "maxTokens": 8192
          }
        ]
      }
    }
  }
}

apiKey 依然是 Gateway Token，不是 OpenRouter 的 Key。baseUrl 末尾要带 /v1：Cloudflare 文档里 OpenRouter 的完整调用路径是 .../openrouter/v1/chat/completions，OpenClaw 会在 baseUrl 后面自己拼 /chat/completions。

Google AI Studio（Gemini）配置

Google AI Studio 对开发者有免费额度，不绑卡也能用，具体的速率和每日限额经常调整，以 Gemini API 速率限制页面 为准。

先去 https://aistudio.google.com/apikey 获取 API Key，然后在 Gateway 页面添加 Google AI Studio 提供商并填入 Key。

这里有个坑：AI Gateway 的 /google-ai-studio 路径转发的是 Gemini 原生接口（/v1/models/{model}:generateContent），不是 OpenAI 格式，而 OpenClaw 这里用的是 openai-completions。所以要走 AI Gateway 的 OpenAI 兼容入口 /compat，模型名写成 google-ai-studio/<模型名>（截至 2026-10 的 Cloudflare 文档）。写作时我用的是 gemini-2.0-flash，这个型号已经过时，下面换成了 gemini-2.5-flash。

OpenClaw 配置中追加：

{
  "models": {
    "providers": {
      "google": {
        "baseUrl": "https://gateway.ai.cloudflare.com/v1/你的账户ID/openclaw-gateway/compat",
        "apiKey": "你的Gateway_Token",
        "api": "openai-completions",
        "models": [
          {
            "id": "google-ai-studio/gemini-2.5-flash",
            "name": "Gemini 2.5 Flash",
            "reasoning": false,
            "input": ["text", "image"],
            "cost": {
              "input": 0,
              "output": 0,
              "cacheRead": 0,
              "cacheWrite": 0
            },
            "contextWindow": 1000000,
            "maxTokens": 8192
          }
        ]
      }
    }
  }
}

要切换为主模型的话：

{
  "agents": {
    "defaults": {
      "model": {
        "primary": "google/google-ai-studio/gemini-2.5-flash"
      }
    }
  }
}

多模型共存
三个提供商可以同时配置在 providers 里，切换主模型只需改 primary 字段。

Cloudflare Workers AI（免费额度方案）

如果你连第三方的 API Key 都不想申请，Cloudflare 自家的 Workers AI 也是一个选择。它直接跑在 Cloudflare 的网络上，截至 2026-10 免费额度是每天 10,000 Neurons，轻度使用够用。

Workers AI 不需要第三方模型的 Key，但需要一个有 Workers AI 权限的 Cloudflare API Token（在「我的个人资料 → API 令牌」里创建）。同样走 AI Gateway 的 /compat 入口，模型名写成 workers-ai/@cf/...。

OpenClaw 配置：

{
  "models": {
    "providers": {
      "workersai": {
        "baseUrl": "https://gateway.ai.cloudflare.com/v1/你的账户ID/openclaw-gateway/compat",
        "apiKey": "你的Cloudflare_API_Token",
        "api": "openai-completions",
        "models": [
          {
            "id": "workers-ai/@cf/meta/llama-3.3-70b-instruct-fp8-fast",
            "name": "Llama 3.3 70B",
            "reasoning": false,
            "input": ["text"],
            "cost": { "input": 0, "output": 0, "cacheRead": 0, "cacheWrite": 0 },
            "contextWindow": 24000,
            "maxTokens": 4096
          }
        ]
      }
    }
  }
}

这个模型（Moltworker README 里的示例）支持函数调用，上下文窗口 24K。Workers AI 的完整模型列表在 Cloudflare 控制台的 Workers AI 页面，Llama、Mistral、Qwen 等开源模型都有。效果比不上一线商业模型，但作为免费备用够用。

自定义 AI 人设

光配好模型还不够，你可能还想让 AI 有特定的性格或专业方向。OpenClaw 的人设不在 openclaw.json 里配，而是放在 workspace 下的 Markdown 文件里：SOUL.md 写人设、边界和语气，IDENTITY.md 写名字和形象，AGENTS.md 写工作约定。注意 OpenClaw 的配置 schema 里没有 agents.defaults.systemPrompt 这样的字段，人设只能通过上面这些文件配置。

容器里没法直接改文件，最省事的办法是在对话里让 AI 自己改，比如：

请把 SOUL.md 改成：你是一个专业的技术助手，擅长编程、系统运维和云原生技术。回答简洁直接，给出可操作的建议，使用中文回复。

这些文件会在每次会话开始时注入给模型。只要配好了 R2，改动会随备份保存下来，容器重启后不会丢。

接入聊天渠道

OpenClaw 支持 Discord、Telegram、Slack 三种聊天渠道。我实测 Discord 体验最好，响应速度和消息格式都比其他两个强。

Discord 接入

创建 Bot 应用

打开 Discord Developer Portal（https://discord.com/developers/applications ），新建一个 Application。

获取 Bot Token

在应用左侧菜单点 Bot，Reset Token 后复制。这个凭证必须妥善保管，泄露了别人就能控制你的 Bot。


配置必要权限

在 Bot 页面的 Privileged Gateway Intents 区域，开启 MESSAGE CONTENT INTENT（必须），SERVER MEMBERS INTENT 可选。

生成邀请链接并添加到服务器

OAuth2 → URL Generator 里勾选 Scopes（bot、applications.commands）和 Bot Permissions（Send Messages、Read Message History、Embed Links、Use Slash Commands），用生成的链接把 Bot 拉进你的 Discord 服务器。

部署并配对

npx wrangler secret put DISCORD_BOT_TOKEN
npm run deploy

在 Discord 里给 Bot 发一条消息，它会返回配对码。去 Admin 后台审批通过后就能正常对话了。

偷懒的办法
如果基础聊天功能已经跑通，你可以直接在 OpenClaw 对话框里让 AI 帮你配置 Discord 渠道——给它 Bot Token 就行。

Telegram 接入

在 Telegram 找 @BotFather，发 /newbot 创建机器人，拿到 Token 后：

npx wrangler secret put TELEGRAM_BOT_TOKEN
npm run deploy

配对流程同上。

Slack 接入

Slack 需要两个凭证：

npx wrangler secret put SLACK_BOT_TOKEN    # xoxb- 开头
npx wrangler secret put SLACK_APP_TOKEN    # xapp- 开头
npm run deploy

设备准入策略
所有渠道默认启用 pairing 模式（新设备需管理员审批）。如果想开放给所有人直接用，可以改为 open 模式，但会降低安全性。

浏览器自动化能力

Moltworker 内置了 Chrome DevTools Protocol 代理，可以驱动无头浏览器执行自动化操作。这是它跟普通 AI 聊天工具最大的区别之一——你的 AI 助手可以真的”上网”干活。

开启方法

npx wrangler secret put CDP_SECRET     # 认证密钥，随机字符串
npx wrangler secret put WORKER_URL     # 填你的 Worker 公开地址
npm run deploy

能做什么

配置完成后 OpenClaw 会获得 cloudflare-browser 技能，包含网页截图（screenshot.js）、视频生成（video.js）、通用 CDP 客户端（cdp-client.js）。你可以直接在对话里说”帮我截个图”之类的指令。

底层提供了标准的 CDP 端点，如果你懂前端开发，可以用这些接口做更复杂的自动化：

  • GET /cdp/json/version — 浏览器版本信息
  • GET /cdp/json/list — 当前打开的页面列表
  • GET /cdp/json/new — 新开一个浏览器标签页
  • WebSocket /cdp/devtools/browser/{id} — 通过 WebSocket 控制浏览器

前提条件
所有 CDP 调用都需要 CDP_SECRET 认证，不配置就用不了。

OpenClaw 的技能扩展体系

除了浏览器自动化，OpenClaw 本身有一套可扩展的技能（Skills）架构。你在对话中让 AI 做一些复杂操作时（比如搜索网页、分析数据），它实际上是在调用后台的技能模块。

目前 Moltworker 内置的技能主要是 cloudflare-browser（截图、录屏、CDP 控制），但这套架构是开放的——如果你有 Node.js 开发能力，可以在 OpenClaw 的 workspace 目录下自定义新技能。

具体怎么写自定义技能，可以参考 OpenClaw 官方文档的 Skills 部分。对于大多数用户来说，内置的浏览器技能加上 AI 的自然语言理解就足够应付日常需求了。

管理后台功能

Admin 面板地址是 你的URL/_admin/，需要通过 Cloudflare Access 认证。

功能说明
R2 备份状态查看最后备份时间，可手动触发备份
重启网关进程改了配置不生效时用这个
设备配对管理查看、审批、批量操作已连接设备

需要更底层的调试信息可以开启 Debug 端点：

npx wrangler secret put DEBUG_ROUTES    # 输入 true
npm run deploy

开启后可访问：

  • GET /debug/processes — 容器内进程列表
  • GET /debug/logs?id=<pid> — 指定进程的日志
  • GET /debug/version — 版本信息

实际运行成本

很多人以为只要 $5/月的订阅费，但 Sandbox 容器持续运行是有额外计费的。Moltworker 用的是 standard-1 规格（1/2 vCPU、4 GiB 内存、8 GB 磁盘），按 24/7 运行算（按 2026-10 的 Cloudflare Containers 定价 复核：内存 $0.0000025/GiB·秒、CPU $0.000020/vCPU·秒、磁盘 $0.00000007/GB·秒，扣除 Workers Paid 每月包含的 25 GiB·小时内存、375 vCPU·分钟 CPU 和 200 GB·小时磁盘）：

计费项月费估算
Workers Paid 订阅$5
内存占用（4 GiB）~$26
CPU 使用（约 10% 利用率）~$2
磁盘空间（8 GB）~$1.50
总计~$34.50

内存和磁盘按分配量计费，只要容器在跑就一直计；CPU 按实际使用计费，10% 利用率是轻度个人使用的粗略估计。出网流量、Workers 请求和日志另计，个人使用通常可以忽略。

省钱方法
如果不需要全天候在线，设置容器休眠可以大幅降低内存计费。按 Moltworker README 的估算，每天只运行 4 小时的话，计算费用大约 $5–6/月，再加 $5 订阅费。

容器休眠与省钱策略

默认配置是永不休眠（SANDBOX_SLEEP_AFTER=never），意味着容器一直占着内存。对于使用频率不高的场景，可以设置空闲自动休眠：

npx wrangler secret put SANDBOX_SLEEP_AFTER
# 可选值：10m（10分钟）、1h（1小时）、never（永不）
npm run deploy

休眠后再次访问会触发冷启动（约 1-2 分钟），但只要 R2 存储配置正常，所有数据都会自动恢复。

版本更新与维护

Moltworker 还在持续开发中，隔三差五就会推新功能或修 Bug。更新流程很简单：

cd moltworker
git pull origin main
npm install          # 更新依赖
npm run deploy       # 重新部署

部署过程中你之前设置的 Secret 不会受影响，它们存在 Cloudflare 的加密存储里，跟代码是分开的。

如果更新后出了问题（比如新版本引入了 Bug），可以回退到之前的版本：

git log --oneline -5          # 看最近几次提交
git checkout <之前的commit>    # 切到稳定版本
npm run deploy                 # 重新部署旧版本

更新前备份
更新前建议在 Admin 后台手动触发一次 R2 备份。虽然自动备份每 5 分钟跑一次，但手动触发可以确保最新数据已经保存。如果更新后容器行为异常，至少数据不会丢。

现象排查方向

网关起不来npx wrangler secret list 检查密钥，npx wrangler tail 看日志
改了配置没效果修改 Dockerfile 里的 cache bust 注释后重新部署
R2 备份失效确认 R2_ACCESS_KEY_ID、R2_SECRET_ACCESS_KEY、CF_ACCOUNT_ID 三个值都设了
Admin 页面拒绝访问检查 CF_ACCESS_TEAM_DOMAIN 和 CF_ACCESS_AUD 是否正确

本地开发 WebSocket 不通wrangler dev 对 Sandbox WebSocket 支持有限，建议直接部署测试

本地调试
在项目根目录创建 .dev.vars：

DEV_MODE=true
DEBUG_ROUTES=true

DEV_MODE 会跳过 Access 认证和设备配对，仅限开发环境。
