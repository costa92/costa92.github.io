DeepSeek V4 来了：不只是一次开源发布，是中国 AI 栈独立的三重冲击

 2026-04-24  AI DeepSeek DeepSeek-V4 LLM 开源模型

一句话摘要
DeepSeek V4 于 2026 年 4 月 24 日发布，Pro 版 1.6T 参数 / 49B 激活、Flash 版 284B / 13B，原生支持 1M 上下文、MIT 协议，推理侧获得华为昇腾全面适配。它不是又一次”便宜了”——它同时改写了性能差距、长上下文定价、和算力自主三件事。

先把事实摆清楚

4 月 24 日，DeepSeek 发布了 V4 预览版系列：两个 MoE 模型，一个大参数旗舰，一个主打性价比，外加一份直接拿 Anthropic、OpenAI、Google 旗舰做对比的 benchmark 表。

DeepSeek 自己的定位
发布公告称 V4-Pro 在开源模型里知识能力领先、仅次于 Gemini-3.1-Pro，推理能力”rivaling top closed-source models”。
技术报告里则补了一句更克制的话：V4 的发展轨迹大约落后最前沿的闭源模型 3 到 6 个月。

一家公司在发布稿里主动给出”落后多少”的估计并不多见。而 3-6 个月大致相当于前沿闭源模型一次版本迭代的间隔——可以把它理解为：开源追到了”上一代闭源”。

冲击一：性能差距从”量级”变成”季度”

按我自己的粗略印象：2024 年的 Llama 3 和同期 GPT-4 之间差距以”年”计；2025 年初 V3/R1 把差距明显压缩；现在 DeepSeek 自己估计是 3-6 个月。差距的单位从”年”变成了”季度”。

对产业意味着什么？

  • 对 OpenAI / Anthropic 护城河： 最大的问题不是能力本身，而是用户愿意为几个月的性能差距多付数倍到数十倍价格的意愿在消退。SimpleQA-Verified 上 V4 比 Opus 4.6 高 11.7 分（57.9 vs 46.2），这项测的是短事实问答的准确率，和幻觉问题直接相关。
  • 对开源生态： Qwen、GLM、Mistral 等开放权重模型也被推到了同一张对比表上，”开源只是能用”的印象需要更新。
  • 对终端开发者： 新项目的默认选型可以从”便宜闭源小模型 + 偶尔升级旗舰”换成”V4-Flash + 偶尔升级 V4-Pro”，先在自己的任务上做对照再决定。

一个具体的算账
假设一个 Agent 任务一次调用平均输入 40K、输出 4K（不考虑缓存）。按发布时定价，Opus 4.6（$5/$25）一次约 $0.30，V4-Flash 一次约 $0.0067，差约 45 倍。即使 V4 的失败率高、要重试两三次，成本仍低一个数量级以上。

冲击二：1M 上下文 + 27% FLOPs，长上下文的成本结构变了

DeepSeek 模型卡里有一句看似炫技、实则影响定价的话：

“在 1M token 上下文下，DeepSeek-V4-Pro 只需要 V3.2 的 27% 单 token 推理 FLOPs 和 10% 的 KV 缓存。”

这背后是他们的混合注意力——压缩稀疏注意力（CSA）+ 高度压缩注意力（HCA）的组合，加上用 Manifold-Constrained Hyper-Connections（mHC）重新设计了残差连接，以及训练用的 Muon 优化器。技术细节可以单独写一篇，但从产业角度只需要理解一件事：

长上下文正在从”贵的奢侈品”变成”默认可用”。

受影响最直接的场景：

  1. Cursor / Windsurf / Cline 这类 IDE Agent： 之前因为成本不敢把整个仓库塞进上下文；按发布价，V4-Flash 输入 100 万 token 一次约 $0.14，缓存命中时约 $0.03。
  2. RAG 架构： 粗粒度检索 + 把窗口塞满的”简单做法”重新变得可行，精细切块和多级召回的必要性需要重新评估。
  3. 长文档分析（法律、医疗、财报）： 原本需要拆分 + 摘要 + 再分析三段式流水线的任务，有机会一次调用完成。

但有个前提没被充分讨论
模型卡建议 Think Max 模式下把上下文窗口设为至少 384K，因为推理过程本身也要占窗口。真正吃满 1M 的场景，thinking token 还会再烧一遍——你在输入侧省的钱，可能被多出来的 reasoning token 吃回去一部分。算总账时别只看 FLOPs。

冲击三：华为昇腾 950 PR 与 CUDA 依赖

这是我认为最被低估的一件事。

据 The Information 在 4 月初的报道（TrendForce 等媒体转引），DeepSeek 计划把 V4 部署在华为最新的 Ascend 950 PR 上，并为此和华为、寒武纪一起对模型底层做了大量适配和重写，这也是 V4 推迟发布的原因之一。发布当天，华为宣布旗下昇腾芯片和超节点系统”全面支持” V4 推理。据路透社报道，V4 发布后阿里、字节、腾讯纷纷向华为追加芯片订单；此前的报道称这几家的订单合计达数十万片。

V4 发布前，英伟达 CEO 黄仁勋在 Dwarkesh Podcast 上谈到这一可能性时说，如果 DeepSeek 的模型针对华为芯片而不是美国硬件优化，对美国将是”a horrible outcome”（SCMP 报道）。

为什么这件事比”又一个便宜模型”更值得关注？

  • 推理侧国产化有了标杆： 前沿级开放模型在发布当天就获得国产芯片的完整推理支持，”只能在 NVIDIA 上跑好”不再是默认前提。训练用了什么硬件，官方没有公开说明。
  • CANN 生态有了超级客户： 一个头部模型团队把自己的算子栈主动适配到华为的 CANN（Compute Architecture for Neural Networks），对一个新生态来说，这比任何宣传都管用。
  • 供应链信号： 互联网大厂的批量订单 + V4 的标杆效应意味着，国产 AI 芯片正从”备胎”走向”主力之一”。

冲击四：MIT + 双 API 兼容，迁移成本很低

这是一条看起来很”软”、实际很有杀伤力的产品策略。

V4 开放权重用 MIT 协议，可商用、可修改、可闭源再分发。API 同时兼容 OpenAI ChatCompletions 和 Anthropic 的消息格式。

翻译成开发者语言： 现有的 OpenAI SDK 或 Anthropic SDK 调用，改 base_url、api_key 和模型名，就能切到 DeepSeek V4。

迁移成本接近 0，意味着团队可以用一个下午做完对照实验，而不必先排期改代码。当然，”能跑通”不等于”效果一样”：提示词、工具调用格式、长输出的稳定性都要在自己的评测集上重新验一遍。

比”开源”更有杀伤力的是”低迁移成本”
过去开源模型推广慢，一部分原因是要重新适配工具链。V4 直接兼容两家闭源厂商的 API 格式，把这层门槛基本抹平了。

我的判断：V4 比 V3/R1 更重要

过去一年大家常说的 “DeepSeek 时刻”，指的是 2025 年 1 月那次——V3 技术报告称最终训练成本约 560 万美元，R1 展示了推理能力可以靠强化学习获得并蒸馏到小模型。那一轮主要冲击的是成本叙事。

V4 这次是三条线同时推进：

  1. 能力逼近： 开源落后闭源从”年”变成”季度”。
  2. 效率提升： 长上下文 + 混合注意力让长上下文定价需要重新计算。
  3. 算力自主： 推理侧不再只依赖 CUDA 生态。

每一条单独出现都值得关注；三条同时出现，而且有技术报告、benchmark 和硬件伙伴背书，这在开源模型里很少见。

开发者现在可以做什么

按优先级列三件事：

  • 先做： 把 V4-Flash 加到现有 API 调用的备选模型里（就算不是主力）。OpenRouter 已经上架，切换只需改配置。Simon Willison 发布当天的上手记录里有一个 5 分钟能跑完的”鹈鹕骑自行车”SVG 测试，可以当作快速的 sanity check。
  • 接着做： 把你最花钱的一条 Agent/批处理流水线用 V4-Flash 跑一遍对照实验，按任务类型（结构化生成、代码补全、摘要）分别记录质量和成本。
  • 再评估： 如果你在做长上下文产品（法律、代码审查、研报），把 chunking 策略拿出来重审。1M 窗口 + 10% KV cache 的组合，可能让原来的多级 RAG 架构变得过度设计。

一个反直觉的建议
不要急着换成 V4-Pro。按发布价它比 V4-Flash 贵约 12 倍，大多数场景 Flash 够用。Pro 留给真正复杂的那一小部分任务。

后续可能发生什么

以下是写作时（2026-04）对之后 90 天的预测，按置信度排序：

  1. 高置信度： OpenAI 和 Anthropic 会下调 API 价格或推出更便宜的小模型，低价档位正在被 V4-Flash 挤压。
  2. 中等置信度： Meta 会加快下一代 Llama 的发布节奏，因为 V4 的 MIT 协议 + API 兼容正打在 Llama 最核心的生态优势上。
  3. 低但不容忽视： 美国对华为昇腾相关供应链的限制会进一步收紧，反过来刺激华为加快下一代芯片的节奏。
  4. 更长期： 2026 年下半年，会有主流美国 AI 创业公司公开把中国开源模型作为推理后端选项之一。

DeepSeek V3 是一个便宜的产品，DeepSeek V4 是一个产业事件。

如果你还把”开源模型不够强”或”国产芯片只能做边缘推理”当作默认判断，是时候拿 V4 重新验证一遍了。
