用 mitmproxy 抓包 Claude Code：看清每一个网络请求

 2026-03-23  Coding-Agent Claude Code mitmproxy 网络抓包 调试
Claude Code mitmproxy 网络抓包 调试
Coding-Agent
文章字数:   2.7k
阅读次数:  
   阅读模式

Claude Code 是一个黑盒——你输入一条指令，它读文件、改代码、跑命令，但你看不到它和 Anthropic API 之间到底说了什么。想了解它的工作原理，最直接的方式就是抓包。

本文用 mitmproxy 搭建一个 HTTPS 中间人代理，拦截 Claude Code 的所有网络请求。覆盖 macOS 和 Windows 两个平台，最后逐条分析抓到的 7 类关键请求。

核心要点

  • mitmproxy 充当中间人代理，拦截并记录所有 HTTPS 请求
  • macOS 用 brew 安装，证书导入钥匙串；Windows 用 pip 安装，证书导入系统存储
  • 常见的 7 类请求：版本检查、MCP 连接、账号信息、托管设置、Fast mode 开关、对话、遥测
  • 对话请求使用 SSE 流式传输，需要在 mitmweb 中查看 Response 的原始数据

原理：中间人代理

抓包 HTTPS 请求的核心思路是在 Claude Code 和 Anthropic API 之间插入一个代理。Claude Code 不直接连 API，而是先经过 mitmproxy，mitmproxy 记录请求后再转发。

这能工作的前提是 Claude Code 信任 mitmproxy 的 CA 证书。HTTPS 加密依赖证书链——如果系统信任了 mitmproxy 的根证书，mitmproxy 就能在中间解密、记录、再加密，两端都不会报错。

第一步：安装 mitmproxy

macOS（推荐 brew）：

brew install mitmproxy

Windows（pip）：

pip install mitmproxy

验证安装：

mitmdump --version

如果用 pip 安装，建议用 pipx install mitmproxy 或独立的虚拟环境，避免和其他 Python 项目的依赖互相干扰。

第二步：启动代理

mitmweb --listen-port 8080

这条命令做两件事：

端口用途
8080HTTP/HTTPS 代理，后续所有设置了 HTTPS_PROXY 的程序都走这里
8081网页管理界面，用浏览器打开可以看到所有请求的详情

启动后打开 http://127.0.0.1:8081/#/flows，你会看到一个空的请求列表——等后面 Claude Code 跑起来就有数据了。

mitmweb vs mitmdump
mitmweb 提供网页界面，适合交互式分析。如果你想自动化处理请求（比如过滤特定 API），用 mitmdump 配合 Python 脚本更合适。

第三步：安装 CA 证书

这是最关键的一步。不让 Claude Code 信任 mitmproxy 的 CA，它会报 TLS 证书校验错误拒绝连接。

macOS

mitmproxy 首次启动后会在 ~/.mitmproxy/ 目录下生成证书文件。

# 将 mitmproxy CA 证书导入系统钥匙串并设为信任
sudo security add-trusted-cert -d -r trustRoot \
  -k /Library/Keychains/System.keychain \
  ~/.mitmproxy/mitmproxy-ca-cert.pem

执行后输入密码即可。你可以在「钥匙串访问」→「系统」里找到一个叫 mitmproxy 的证书，状态应该是「始终信任」。

Windows

证书路径：C:\Users\你的用户名\.mitmproxy\mitmproxy-ca-cert.pem

  1. 双击 .pem 文件
  2. 选择安装证书 → 本地计算机
  3. 将证书放入受信任的根证书颁发机构
  4. 如果要求输入密码，留空直接下一步

安全提醒
安装的 CA 证书让 mitmproxy 可以解密所有 HTTPS 流量。抓包结束后建议移除这个证书——macOS 在钥匙串访问中删除，Windows 在证书管理器中删除。不要在公共网络上长期保留这个信任配置。

第四步：设置代理并启动 Claude Code

关键动作：在同一个终端窗口设置环境变量，然后启动 Claude Code。环境变量只对当前终端生效。

macOS / Linux

export HTTPS_PROXY=http://127.0.0.1:8080
export NODE_EXTRA_CA_CERTS=~/.mitmproxy/mitmproxy-ca-cert.pem
claude

Windows (PowerShell)

$env:HTTPS_PROXY = "http://127.0.0.1:8080"
$env:NODE_EXTRA_CA_CERTS = "C:\Users\你的用户名\.mitmproxy\mitmproxy-ca-cert.pem"
claude

HTTPS_PROXY 让 Claude Code 把 HTTPS 请求发给代理（注意 Claude Code 不支持 SOCKS 代理）。NODE_EXTRA_CA_CERTS 把 mitmproxy 的 CA 追加到 Claude Code 信任的证书列表里。

关于证书，新旧版本有个差别（截至 2026-10）：按官方网络配置文档，Claude Code 默认同时信任自带的 Mozilla CA 和操作系统证书库（CLAUDE_CODE_CERT_STORE 默认是 bundled,system）。原生安装版总能读系统证书库，npm 安装需要 Node 22.15 及以上。所以如果你已经按第三步把证书导入了系统，较新的版本不设 NODE_EXTRA_CA_CERTS 也能工作；老版本 Node 只认自带证书和这个变量。显式设上它最稳妥，不依赖版本。

想确认证书真的加载了，可以用 claude --debug 启动，日志（~/.claude/debug/<session-id>.txt）里会有一行 CA certs: Appended extra certificates from NODE_EXTRA_CA_CERTS (...)；会话里跑 /status 也能看到 Proxy 一行显示的代理地址。

第五步：查看请求

在浏览器打开 http://127.0.0.1:8081，回到 Claude Code 里随便发一条消息，刷新 mitmweb 页面，所有请求就会出现在 Flow List 里。

点击任意一条请求，可以看到完整的 Request Headers、Body、Response Headers 和 Response Body。

查看流式响应
Claude Code 的对话请求（/v1/messages）使用 SSE（Server-Sent Events）流式传输。在 mitmweb 中，你需要查看 Response 的 Raw 标签页才能看到完整的流式数据。默认的 Pretty 视图可能显示不全。

Claude Code 的 7 类请求

下表是抓包时最常见的几类请求。它们大多是 Claude Code 的内部接口，路径会随版本变化；截至 v2.1.295（2026-10），这些路径仍能在 Claude Code 的程序里找到。具体会出现哪些，取决于安装方式和登录方式：

#请求地址说明发送时机
1版本检查：npm 安装查 registry.npmjs.org，原生安装查 downloads.claude.ai，Homebrew 安装查 formulae.brew.sh检查是否有新版本启动时
2MCP Server URL（如 mcp.slack.com/mcp）连接配置的远程 MCP 服务器启动时
3api.anthropic.com/api/claude_cli_profile 或 /api/oauth/profile获取账号基本信息启动时
4api.anthropic.com/api/claude_code/settings拉取组织下发的托管设置启动时
5api.anthropic.com/api/claude_code_penguin_mode查询组织是否允许 Fast mode启动时
6api.anthropic.com/v1/messages发送对话请求用户发消息时
7api.anthropic.com/api/event_logging/v2/batch上报使用遥测数据周期性

逐条看看每个请求在做什么。

版本检查

GET https://registry.npmjs.org/@anthropic-ai/claude-code   # npm 安装
GET https://downloads.claude.ai/...                        # 原生安装

Claude Code 启动时会检查最新版本号并和本地版本对比。去哪查取决于安装方式：npm / bun 安装查 npm registry，原生安装（现在官方推荐的方式）查 downloads.claude.ai（2.1.116 之前是 storage.googleapis.com），Homebrew 安装查 formulae.brew.sh。有新版本时，原生安装会自动更新，也可以手动跑 claude update。

MCP 服务器连接

如果你在 ~/.claude.json（用户 / 本地作用域）或项目的 .mcp.json 里配置了 MCP 服务器，Claude Code 会逐个连接它们。

POST https://mcp.slack.com/mcp         (HTTP 类型)
GET  https://your-server.example/sse   (SSE 类型)

HTTP / SSE 这类远程 MCP 服务器会发 HTTP 请求，在 mitmweb 里能看到；stdio 类型走本地进程通信，不经过网络，抓不到包（但它自己发出的网络请求是否走代理，取决于那个进程是否继承了 HTTPS_PROXY）。用 claude.ai 账号登录时，从 claude.ai 添加的连接器会经由 mcp-proxy.anthropic.com 转发。MCP 服务器连接失败时，在 mitmweb 里看 Response 状态码就能快速定位问题。

账号信息和设置

GET https://api.anthropic.com/api/claude_cli_profile
GET https://api.anthropic.com/api/oauth/profile
GET https://api.anthropic.com/api/claude_code/settings

前两个拉取账号资料：用 Console API key 登录时走 claude_cli_profile（请求头带 x-api-key），用 claude.ai 订阅账号登录时走 oauth/profile（带 OAuth 的 Authorization: Bearer）。claude_code/settings 拉的是组织管理员在后台配置的托管设置，个人账号通常返回空配置。

抓包截图或导出 curl 时注意：这些请求头里就是你的凭据，分享前务必打码。

功能开关

GET https://api.anthropic.com/api/claude_code_penguin_mode

penguin_mode 是 Fast mode 的内部代号。从程序里的调用方式看，这个请求查询的是你所在组织是否开启了 Fast mode；结果变化时 Claude Code 会切换 Fast mode 的可用状态。官方网络文档也提到，即便通过 ANTHROPIC_BASE_URL 走 LLM 网关，Fast mode 的可用性检查仍然会请求 api.anthropic.com。

真正的功能开关（feature flags）是另外的请求拉取的，同样发往 api.anthropic.com。

对话请求

POST https://api.anthropic.com/v1/messages
Content-Type: application/json

这是 Claude Code 的核心请求——把你的指令、系统提示、工具定义、对话历史全部打包发给 Anthropic API。在 mitmweb 里查看 Request Body，你能看到完整的 system prompt、tools 数组、和 messages 数组。

Response 是 SSE 格式（text/event-stream），每个 chunk 包含模型生成的一段文本或一次工具调用。

遥测数据

POST https://api.anthropic.com/api/event_logging/v2/batch

Claude Code 会批量上报使用事件，用于产品分析和质量改进；直连 Anthropic API 时还会向 Datadog（http-intake.logs.us5.datadoghq.com）发运维遥测。如果介意，可以设置环境变量 DISABLE_TELEMETRY=1，或用 CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1 一并关掉非必要流量，详见官方 Data usage 文档。关掉后再抓一次包，就能直观看到哪些请求消失了。

保存为脚本

每次抓包都手动设三个变量太麻烦，建议保存成脚本。

macOS / Linux — 创建 ~/.local/bin/claude-debug：

#!/bin/bash
export HTTPS_PROXY=http://127.0.0.1:8080
export NODE_EXTRA_CA_CERTS=~/.mitmproxy/mitmproxy-ca-cert.pem
claude "$@"
chmod +x ~/.local/bin/claude-debug

以后运行 claude-debug 就自动走代理。

Windows — 创建 start-claude-debug.ps1：

$env:HTTPS_PROXY = "http://127.0.0.1:8080"
$env:NODE_EXTRA_CA_CERTS = "C:\Users\你的用户名\.mitmproxy\mitmproxy-ca-cert.pem"
claude

实用技巧

只看 Anthropic API 请求：mitmweb 的 Flow List 会显示所有经过代理的流量。在搜索框输入 ~d api.anthropic.com 可以只显示 Anthropic 的请求，过滤掉 npm、MCP 等噪音。

导出请求用于调试：在 mitmweb 中选中一条请求，可以通过 Flow 菜单的 Export 把它复制为 curl 命令（mitmproxy 的终端界面里对应的快捷键是 e）。拿到 curl 命令后可以在终端里手动重放，方便调试和分析——记得先删掉里面的 API key 或 token。

mitmdump 过滤脚本：如果你想自动化分析，用 mitmdump 配合 Python 脚本：

# save as filter_anthropic.py
def response(flow):
    if "api.anthropic.com" in flow.request.pretty_host:
        print(f"{flow.request.method} {flow.request.path}")
        print(f"  Status: {flow.response.status_code}")
        print(f"  Size: {len(flow.response.content)} bytes")
mitmdump -s filter_anthropic.py -p 8080

抓包结束后，记得在系统设置中移除 mitmproxy 的 CA 证书，保持系统安全。下一步，你可以用这个方法对比不同 Claude Code 版本的请求差异，或者研究它在执行复杂任务时的工具调用链。
