ClawHub 技术解密：AI Agent Skill 注册中心的架构实现

npm 之于 JavaScript、PyPI 之于 Python，OpenClaw 的 Skill 也需要一个发布和分发的地方，这就是 ClawHub。它的源码是公开的，这篇对照仓库代码看看它是怎么实现的。

代码版本说明
文中代码片段摘自 openclaw/clawhub 在 2026-03-12 的 main 分支（commit b32a499），为便于阅读做了删减。2026-10 复核时主干已经有不少变化，涉及的地方在正文里单独标注。

ClawHub 是什么

ClawHub 是 OpenClaw（早期名为 Clawdbot，项目和 CLI 也因此曾叫 ClawdHub / clawdhub）的公共 Skill 注册中心。它的核心职责是：让开发者能发布、版本化、搜索和安装 AI Agent 的 skill——本质上是一个 SKILL.md 加上配套文件的 bundle。

项目概况

  • GitHub: openclaw/clawhub（写作时约 5.5k stars，截至 2026-10 约 9.5k）
  • 技术栈: TypeScript + Convex + TanStack Start + React 19
  • 许可证: MIT
  • 官网: clawhub.ai

和 npm 或 Homebrew 这类传统包管理器不同，ClawHub 分发的不是二进制文件或代码包，而是文本形式的 Agent 指令。这决定了它的架构在搜索、安全审查和版本管理上做了很多针对性设计。

技术栈全景

ClawHub 的技术选型可以概括为四层：

层级技术职责
前端TanStack Start + React 19 + Tailwind CSS 4SSR 渲染、路由、Skill 浏览 UI
后端Convex（实时数据库 + Serverless Functions）数据存储、业务逻辑、HTTP API
搜索OpenAI text-embedding-3-small + Convex 向量索引语义搜索
工具链Bun + Vite 7（2026-10 已升到 Vite 8）+ Vitest + oxlint构建、测试、代码质量

这个组合的核心思路是：用 Convex 同时承担数据库和后端逻辑，省掉独立的 API 服务器和 ORM 层。前端选 TanStack Start 而非 Next.js，与 Convex 的实时订阅模型配合更自然。

数据模型：Skill 的生命周期

ClawHub 的 Convex schema 定义了几个核心表。skills 表的结构揭示了一个 skill 从发布到展示的完整生命周期：

// convex/schema.ts（核心字段，省略部分）
const skills = defineTable({
  slug: v.string(),                    // URL 友好的唯一标识
  displayName: v.string(),             // 显示名称
  summary: v.optional(v.string()),     // 一句话描述
  ownerUserId: v.id('users'),          // 作者
  latestVersionId: v.optional(v.id('skillVersions')),
  tags: v.record(v.string(), v.id('skillVersions')),  // latest, v1.0.0 等
  badges: badgesValidator,             // 官方认证、高亮、弃用标记
  moderationVerdict: v.optional(       // 安全审查结论
    v.union(v.literal('clean'), v.literal('suspicious'), v.literal('malicious'))
  ),
  moderationEvidence: v.optional(v.array(v.object({
    code: v.string(),
    severity: v.union(v.literal('info'), v.literal('warn'), v.literal('critical')),
    file: v.string(),
    line: v.number(),
    message: v.string(),
    evidence: v.string(),
  }))),
  quality: v.optional(v.object({       // 质量评分
    score: v.number(),
    decision: v.union(v.literal('pass'), v.literal('quarantine'), v.literal('reject')),
    trustTier: v.union(v.literal('low'), v.literal('medium'), v.literal('trusted')),
    // ...
  })),
  stats: statsValidator,               // 下载数、star 数、评论数
})

几个设计要点：

标签即版本指针。tags 字段是一个 Record<string, Id<'skillVersions'>>，latest 指向最新稳定版，语义版本号指向具体版本。这比维护独立的 latest 字段更灵活——你可以有 beta、canary 等任意标签。

审查结论内嵌到 skill 记录。moderation 相关字段直接在 skills 表上，而不是独立表。这样查询 skill 列表时不需要 JOIN，Convex 的单表查询性能直接受益。

软删除 + 预留 slug。删除 skill 并不是物理删除，而是设置 softDeletedAt。同时有一套 slug 预留机制（90 天冷却期），防止有人抢注被删除的知名 skill 名称。

向量搜索：不只是关键词匹配

ClawHub 的搜索是这个项目最有技术含量的部分之一。它组合了向量相似度、词法匹配和流行度三个信号：

// convex/search.ts（评分逻辑）
const SLUG_EXACT_BOOST = 1.4      // slug 精确匹配加分
const SLUG_PREFIX_BOOST = 0.8     // slug 前缀匹配
const NAME_EXACT_BOOST = 1.1      // 名称精确匹配
const NAME_PREFIX_BOOST = 0.6     // 名称前缀匹配
const POPULARITY_WEIGHT = 0.08    // 流行度权重

function scoreSkillResult(queryTokens, vectorScore, displayName, slug, downloads) {
  const lexicalBoost = getLexicalBoost(queryTokens, displayName, slug)
  const popularityBoost = Math.log1p(Math.max(downloads, 0)) * POPULARITY_WEIGHT
  return vectorScore + lexicalBoost + popularityBoost
}

搜索流程分三步：

  1. 生成 embedding：用 OpenAI text-embedding-3-small（1536 维）对查询文本做嵌入，调用 Convex 的向量索引获取候选集
  2. 词法加权：对候选结果做 slug 和名称的 token 匹配，精确匹配加 1.4 分，前缀匹配加 0.6-0.8 分
  3. 流行度加成：用 log1p(downloads) 做对数平滑，避免下载量大的 skill 过度霸榜

这种混合排序策略解决了纯向量搜索的常见问题：用户搜「padel」时，名字就叫 padel 的 skill 应该排第一，而不是语义相似但名字不同的结果。

2026-10 的主干上，这段逻辑又调整过：slug 与查询完全一致时的加分提高到 EXACT_SLUG_BOOST = 2.5，原来的 1.4 变成了”slug 的每个 token 都精确匹配”时的 SLUG_TOKEN_BOOST；scoreSkillResult 里的下载量加成被去掉了，排序另外引入了按匹配程度分档（rankTier）的机制。

嵌入生成模块本身也做了工程化处理：

// convex/lib/embeddings.ts
export const EMBEDDING_MODEL = 'text-embedding-3-small'
export const EMBEDDING_DIMENSIONS = 1536
const MAX_ATTEMPTS = 3
const BASE_RETRY_DELAY_MS = 1_000

// 无 API Key 时降级为零向量，搜索功能不会完全不可用
if (!apiKey) {
  console.warn('OPENAI_API_KEY is not configured; using zero embeddings')
  return emptyEmbedding()  // Array(1536).fill(0)
}

没有 OpenAI API Key 时，搜索降级为纯词法匹配，不会崩溃。这种优雅降级思路贯穿整个项目。

安全审查引擎

作为一个接受社区上传 skill 的平台，安全是 ClawHub 的核心关注点。它内置了一个静态安全扫描引擎，在 skill 发布时自动运行：

// convex/lib/moderationEngine.ts
function scanCodeFile(path, content, findings) {
  // 检测 child_process 调用
  if (/child_process/.test(content) && execPattern.test(content)) {
    addFinding(findings, {
      code: REASON_CODES.DANGEROUS_EXEC,
      severity: 'critical',
      file: path,
      line: match.line,
      message: 'Shell command execution detected (child_process).',
      evidence: match.text,
    })
  }
  // 检测 eval/new Function
  if (/\beval\s*\(|new\s+Function\s*\(/.test(content)) {
    addFinding(findings, {
      code: REASON_CODES.DYNAMIC_CODE,
      severity: 'critical',
      // ...
    })
  }
}

审查引擎扫描的内容包括：

  • 代码文件（.js/.ts/.py/.sh 等）：检查 child_process、eval、new Function 等危险调用
  • 非标准端口的网络请求
  • Manifest 文件（JSON/YAML）中的可疑配置
  • Markdown 文件中的隐藏指令

扫描结果产生三级 verdict：clean（安全）、suspicious（可疑）、malicious（恶意）。可疑和恶意的 skill 会被标记或隐藏，管理员可以通过 manualOverride 字段手动覆盖自动判定（2026-10 的 schema 里这个字段已标为弃用、等待迁移移除）。

此外，ClawHub 还接入了 VirusTotal API 做恶意文件扫描（未配置 Key 时跳过），并把 VirusTotal 和 LLM 审查这两个外部扫描器的结论合入最终判定；另有一个质量评分系统，自动隔离过短、模板化的低质量提交。

这套机制的背景是 2026 年 2 月 Koi Security 在 ClawHub 上发现的 341 个恶意 Skill（代号 ClawHavoc），它们主要靠 SKILL.md 里诱导用户执行安装脚本，而不是靠代码文件本身，这也说明了只扫代码不够、Markdown 里的指令同样要审。

CLI 发布流程

开发者通过 clawhub CLI 与注册中心交互。发布一个 skill 的完整流程如下：

# 1. 登录
clawhub login

# 2. 准备 skill 目录
mkdir my-skill && cd my-skill
cat > SKILL.md << 'EOF'
---
name: my-skill
description: A useful skill for data analysis
metadata:
  openclaw:
    requires:
      env:
        - MY_API_KEY
      bins:
        - python3
    primaryEnv: MY_API_KEY
---

## Usage
...
EOF

# 3. 发布
clawhub publish . --slug my-skill --name "My Skill" --version 1.0.0

# 4. 验证
clawhub search "my-skill"

CLI 的 publish 命令在底层做了这些事：

// packages/clawdhub/src/cli/commands/publish.ts（简化；2026-10 该目录已改名为 packages/clawhub）
const filesOnDisk = await listTextFiles(folder)
// 强制要求 SKILL.md（也接受 skills.md）存在
if (!filesOnDisk.some(f => ['skill.md', 'skills.md'].includes(f.relPath.toLowerCase()))) {
  fail('SKILL.md required')
}
// 元数据放在 payload 字段，文件统一追加到 files 字段
const form = new FormData()
form.set('payload', JSON.stringify({ slug, displayName, version, changelog, acceptLicenseTerms: true, tags }))
for (const file of filesOnDisk) {
  const blob = new Blob([Buffer.from(file.bytes)], { type: file.contentType ?? 'text/plain' })
  form.append('files', blob, file.relPath)
}
// POST 到注册中心的 skills 接口（由 Convex HTTP Action 处理）
const result = await apiRequestForm(registry, { method: 'POST', path: ApiRoutes.skills, token, form }, ApiV1PublishResponseSchema)

服务端收到后依次处理：文件存储 → 版本记录创建 → embedding 生成 → 安全扫描 → 全局统计更新。需要注意的是，Convex 里只有 mutation 是事务性的，action 可以调外部服务（OpenAI、VirusTotal）但本身不具备回滚能力，所以这条流水线是”在 action 里编排、把每一步的数据库写入放进各自的 mutation”，而不是一个整体事务。

本地开发：跑起来看看

如果你想在本地跑 ClawHub 研究它的实现：

# 前置条件：安装 Bun（package.json 的 preinstall 会拒绝 npm / pnpm）
curl -fsSL https://bun.sh/install | bash

# 克隆并安装依赖
git clone https://github.com/openclaw/clawhub.git && cd clawhub
bun install
cp .env.local.example .env.local

# 终端 A：启动 Convex 本地后端
bunx convex dev --typecheck=disable

# 终端 B：启动前端（端口 3000）
bun run dev

# 填充示例数据
bunx convex run --no-push devSeed:seedNixSkills

本地开发不需要 OpenAI API Key（搜索降级为零向量），也不需要 VirusTotal Key（安全扫描跳过）。只有 GitHub OAuth 需要配置才能测试登录功能。

以上是 2026-03 时 README 里的步骤。截至 2026-10，完整流程移到了仓库的 CONTRIBUTING.md：多了一步 bunx @convex-dev/auth 生成 Convex Auth 的 JWT 密钥，示例数据改用 bun run seed:dev 填充，动手前以 CONTRIBUTING.md 为准。

架构决策复盘

ClawHub 的技术选型有几个值得关注的取舍：

选 Convex 不选 PostgreSQL + Express：Convex 把数据库、实时订阅、Serverless 函数、文件存储打包在一起，省掉了大量胶水代码。代价是强绑定 Convex 平台，迁移成本高。对于一个快速迭代的社区项目，这个取舍合理。

选 TanStack Start 不选 Next.js：TanStack Start 基于 Vite，与 Convex 的 React hooks 集成顺畅。写作时 TanStack Start 还在快速演进，选它需要承受 API 变动的风险。

选 Bun 不选 Node.js：package.json 里有 "preinstall": "bunx only-allow bun"，强制使用 Bun。Bun 的安装速度和 TypeScript 原生支持是主要动力。

安全扫描用正则不用 AST：ModerationEngine 用正则匹配危险模式，而非解析 AST。正则覆盖不了所有绕过手段，但对于文本为主的 skill bundle（大部分是 Markdown + 少量脚本），足够高效。

动手试试

如果你正在构建 AI Agent 工具，以下步骤可以立即开始：

  1. 浏览现有 skill：访问 clawhub.ai，看看社区都在发布什么类型的 skill
  2. 安装 CLI：npm install -g clawhub（旧包名 clawdhub），用 clawhub search 体验向量搜索；OpenClaw 2026.9.9 也内置了 openclaw skills search
  3. 发布你的第一个 skill：准备一个包含 SKILL.md 的目录，运行 clawhub publish
  4. 阅读源码：从 convex/schema.ts 开始，理解数据模型；再看 convex/search.ts 研究搜索实现

如果你在构建类似的 Agent 工具注册中心，ClawHub 的向量搜索混合排序和静态安全扫描引擎两个模块值得重点研究。
