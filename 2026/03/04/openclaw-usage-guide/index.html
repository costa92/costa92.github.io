OpenClaw 完整使用指南：从安装到多 Agent 与自动化

版本说明
本文最初基于 OpenClaw v2026.3.2（2026-03 发布）写成。截至 2026-10，npm 上的最新版是 2026.9.9，它要求 Node.js 24.16+（24.x）或 26.1+，Node 22 已无法运行。文中命令已用 2026.9.9 的 --help 逐条核对，行为有变化的地方单独标注。执行 openclaw -V 可确认本地版本。

OpenClaw 的定位可以用一句话概括：一个跑在你自己设备上的私人 AI 助手，通过你已经在用的聊天工具和你交互。 截至 2026-10，它在 GitHub 上的 Star 数已超过 39 万。

它不只是聊天机器人：能接管 WhatsApp、Telegram、Discord 等渠道的消息，执行 shell 命令、读写文件、抓网页，还能按计划自动跑任务，触发入口就是手机上已经装好的 IM。

我接入的是 Discord，在服务器频道里 @openclaw 就能让它执行命令、查文件、跑脚本。本文是一份偏参考手册的整理；更偏实战的技巧（安全加固、排障、Skill 选型、Agent 架构）放在了姊妹篇 OpenClaw 进阶实战：12 个使用技巧与必装 Skills 清单。

安装与升级

OpenClaw 通过 npm 全局安装：

# 检查 Node 版本：2026.9.9 需要 24.16+ 或 26.1+（v2026.3.x 时代 22 即可）
node -v

# 安装最新版
npm install -g openclaw@latest

# 验证安装
openclaw -V

# 查看配置文件位置，默认 ~/.openclaw/openclaw.json
openclaw config file

# 校验配置（不启动网关）
openclaw config validate --json
# {"valid":true,"path":"/home/user/.openclaw/openclaw.json"}

需要锁定版本（比如团队环境）时显式指定版本号，例如 npm install -g openclaw@2026.3.2。升级后建议跑一次 openclaw doctor 检查兼容性。

检查更新与切换通道：

# 查看当前安装方式、通道和可用版本
openclaw update status

# 升级到当前通道的最新版
openclaw update

# 切换通道：stable / extended-stable（按月支持）/ beta / dev
openclaw update --channel beta

# 只预览更新动作，不实际安装
openclaw update --dry-run

安装 Shell 补全（支持 zsh / bash / fish / powershell）：

openclaw completion --install
openclaw completion --shell bash --install

Onboard 向导：第一次配置

第一次使用从 openclaw onboard 开始。这个交互式向导依次完成模型认证、网关配置、渠道接入和 Skills 安装。

openclaw onboard

向导会问你：

  1. AI 模型提供商：Anthropic、OpenAI、Gemini、OpenRouter、DeepSeek、Moonshot、MiniMax 等几十个 Provider，也可以填自定义 Base URL（本地 Ollama 或其他 OpenAI 兼容服务）
  2. 网关绑定模式：loopback（仅本机）、lan（局域网）、tailnet（Tailscale 私有网络）、auto、custom
  3. 渠道接入：选择要接入的聊天平台
  4. 是否安装 Daemon：让网关作为系统服务常驻后台

Docker、CI 这类非交互场景，可以用参数跳过所有提示：

openclaw onboard \
  --non-interactive \
  --accept-risk \
  --auth-choice anthropic-api-key \
  --anthropic-api-key "$ANTHROPIC_API_KEY" \
  --gateway-bind loopback \
  --install-daemon

--accept-risk 是非交互模式的必填项，表示你知道 Agent 拥有较高的系统权限。

网关：OpenClaw 的核心进程

网关（Gateway）是一个 WebSocket 服务：接收各渠道的消息，调度模型，执行工具调用，再把结果送回去。

# 前台运行（调试用），默认端口 18789
openclaw gateway run

# 指定端口；--force 会先结束占用该端口的进程
openclaw gateway run --port 18789 --force

# 开发模式：状态隔离到 ~/.openclaw-dev，默认端口 19001
openclaw --dev gateway

# 通过 Tailscale 对外暴露
openclaw gateway run --tailscale funnel

作为系统服务运行（推荐长期使用）：

openclaw daemon install    # 安装并启动（launchd / systemd / schtasks）
openclaw daemon status
openclaw daemon restart
openclaw daemon stop

装成服务后网关随系统启动，不用再手动前台运行。确认状态用 openclaw health，它会列出渠道连通性、默认 Agent 和会话存储：

openclaw health
# Discord: ok (@openclaw) (915ms)
# Agents: main (default)
# Session store: ~/.openclaw/agents/main/sessions/... (3 entries)

渠道接入

OpenClaw 支持二十多个聊天平台，常用的有 Discord、Telegram、WhatsApp、Slack、飞书、Signal、iMessage。

Discord

openclaw channels add --channel discord --token <DISCORD_BOT_TOKEN>

openclaw channels list
# Chat channels:
# - Discord default: configured, token=config, enabled
openclaw channels status
# Discord: ok (@openclaw) (798ms)

Bot 本身要先在 Discord Developer Portal 创建：在 Bot 页拿到 Token，并打开 Message Content Intent（否则读不到消息内容）；用 OAuth2 URL Generator 勾选 bot、applications.commands 两个 scope 和发消息、读历史、建线程等权限，把 Bot 拉进服务器。

Telegram

openclaw channels add --channel telegram --token <YOUR_BOT_TOKEN>
openclaw channels logs --channel telegram

v2026.3.2 起，Telegram 的流式预览默认从 off 改为 partial，新接入的 Telegram 渠道会边生成边更新消息。

WhatsApp

WhatsApp 走 Web Session（扫码登录）：

openclaw channels login --channel whatsapp
# 终端展示二维码，用手机 WhatsApp 扫码

登录后 Session 会持久化，断网重连后自动恢复。

Discord 多频道配置模板

只接一个频道时，channels add 就够了。如果你在一个服务器里有多个频道，希望 #general 自动回复、#code-review 需要 @ 才回复、#onboarding 交给另一个 Agent，就需要理解 Discord 的层级如何映射到配置。

Discord 有四层：Guild（服务器）→ Category（分类）→ Channel（频道）→ Thread（线程）。OpenClaw 的配置只关心其中三层：Guild 是入口，Channel 决定是否响应，Thread 默认继承父频道。Category 只是视觉分组，配置里不用声明。所有 ID 都是 17–20 位的 Snowflake 数字，在 Discord 客户端打开「用户设置 → 高级 → 开发者模式」后，右键服务器、频道、用户即可复制。

下面是一个技术社区的配置骨架（JSON5，字段已对照 2026.9.9 的 openclaw config schema 核对），ID 全部是占位符：

{
  channels: {
    discord: {
      enabled: true,
      token: "${DISCORD_BOT_TOKEN}",
      groupPolicy: "allowlist",   // 只在 guilds 里声明的服务器响应（当前默认值）
      dmPolicy: "pairing",        // 陌生人私聊需要先配对验证（当前默认值）
      historyLimit: 20,           // 频道里每次携带的历史消息数
      streaming: { mode: "partial" },   // off | partial | block | progress

      guilds: {
        "123456789012345678": {           // Guild ID
          requireMention: true,           // 默认需要 @Bot 才回复
          channels: {
            "111111111111111111": { enabled: true, requireMention: false },  // #general：自动回复
            "222222222222222222": { enabled: true, requireMention: true },   // #code-review
            "333333333333333333": { enabled: true, requireMention: false }   // #onboarding
            // 未声明的频道（如 #announcements）不响应
          }
        }
      }
    }
  },

  // 线程绑定策略（Discord 和 Telegram 共用）
  session: {
    threadBindings: { enabled: true, idleHours: 24, maxAgeHours: 168 }
  },

  // 让特定频道交给特定 Agent；未匹配的走默认 Agent，规则按声明顺序匹配
  bindings: [
    {
      agentId: "code-reviewer",
      match: {
        channel: "discord",
        guildId: "123456789012345678",
        peer: { kind: "channel", id: "222222222222222222" }
      }
    },
    {
      agentId: "onboarding-guide",
      match: {
        channel: "discord",
        guildId: "123456789012345678",
        peer: { kind: "channel", id: "333333333333333333" }
      }
    }
  ]
}

几个容易踩的点：

  • 配置查找顺序是 Thread → Channel → Guild → 全局默认。频道级的 requireMention 会覆盖 Guild 级。
  • 线程默认继承父频道的配置。子 Agent 或 ACP 会话可以绑定到某个线程，之后该线程的消息持续路由到同一个会话；/agents 查看绑定状态，/session unbind 解除，session.threadBindings 控制绑定空闲多久后自动清理。
  • 旧版本里 streaming 是字符串（"partial"），2026.9.9 的 schema 里是对象 { mode: "partial" }；升级后配置报错时先跑 openclaw doctor --fix。
  • Bot 在线但不回复时，按顺序查：Guild ID 是否在 guilds 里、频道是否 enabled: true、requireMention 下是否真的 @ 了 Bot、Developer Portal 里 Message Content Intent 是否打开。

Bot 能执行的 Discord 操作按组开关（channels.discord.actions），角色管理、封禁踢人这类高风险操作组默认关闭，需要时再显式开启。

Skills：扩展 Agent 能力

工作区 Skill：一个 SKILL.md 就够

工作区 Skill 是你私有的轻量技能，只需要一个 SKILL.md：YAML front-matter 写元数据，正文写给模型看的指令。每个 Skill 是 skills/ 下的一个目录：

mkdir -p ~/.openclaw/workspace/skills/git-daily-report

~/.openclaw/workspace/skills/git-daily-report/SKILL.md：

---
name: git_daily_report
description: 生成今日工作日报，汇总 git commits、未关闭 Issues、明日计划
---

# Git Daily Report Skill

当用户说"生成日报"、"今天做了什么"、"写日报"时触发此 Skill。

## 执行步骤

1. 用 bash 工具获取今日 git log：
   git log --since=midnight --oneline --all

2. 获取未关闭的 GitHub Issues（如果 gh 已登录）：
   gh issue list --state open --limit 10
   如果 gh 未登录或不在 GitHub 仓库中，跳过此步骤，注明"无 GitHub 数据"。

3. 将以上信息整合为 Markdown 日报发送给用户。

## 输出格式

### 今日进展
{列出今日 git commits，按仓库分组}

### 待处理事项
{列出 open issues，附编号和标题}

### 明日计划
（请补充）

写完后 Skill 会被自动发现，不用重启网关。确认它已就绪：

openclaw skills list
# ✓ ready   📦 git_daily_report  生成今日工作日报...  openclaw-workspace

之后在 Discord 里发 @openclaw 生成日报，Agent 就会按这个 Skill 执行。也可以从命令行直接测试：

openclaw agent --agent main --message "使用 git_daily_report skill 生成今日摘要"

Skill 里不一定要定义自定义工具。多数时候给模型清晰的文字指令，告诉它怎么用已有的 bash / 浏览器工具，就足够了；需要严格参数校验时才值得写 JSON Schema 工具。

Skill 的加载位置

同名 Skill 出现在多个位置时，优先级高的生效（截至 2026.9.9 的文档）：

优先级来源路径
最高工作区 Skill<workspace>/skills
2项目 Agent Skill<workspace>/.agents/skills
3个人 Agent Skill~/.agents/skills
4本机共享 Skill~/.openclaw/skills
较低随安装附带的内置 Skill安装包内

多 Agent 时每个 Agent 有自己的 workspace，放在各自 workspace 下的 Skill 只对该 Agent 可见；放在 ~/.openclaw/skills 的对所有 Agent 可见。

查看依赖是否就绪

openclaw skills list      # 每个 Skill 的状态：ready / missing
openclaw skills check     # 汇总：多少就绪、多少缺依赖
openclaw skills info <name>

missing 通常是对应的命令行工具没装，比如内置的 1password 需要 op CLI、summarize 需要 summarize 命令。装好依赖后会自动变成 ready。

从 ClawHub 安装社区 Skill 与插件

公共 Skill 发布在 ClawHub（源码见 openclaw/clawhub）。2026.9.9 已经内置了安装命令，Skill 用 @作者/slug 引用：

openclaw skills search "github"
openclaw skills install @owner/skill-name
openclaw skills update

插件（npm 包或本地目录形式的扩展，可以注册工具、渠道、Hook）由 plugins 子命令管理：

openclaw plugins list
openclaw plugins install <npm 包名或本地路径>
openclaw plugins inspect <id>      # 旧名 plugins info 仍可用
openclaw plugins update --all
openclaw plugins disable <id>
openclaw plugins enable <id>
openclaw plugins uninstall <id>
openclaw plugins doctor            # 排查插件加载问题

任何第三方 Skill 都能调用你的 Agent 工具集。ClawHub 曾在 2026 年 2 月被发现上百个恶意 Skill，安装前务必看 ClawHub 页面上的安全审计结果，具体做法见进阶篇的安全部分。

模型配置

OpenClaw 支持几十个模型 Provider。我的配置是：默认模型 DeepSeek-V3.2（通过 SiliconFlow），失败时回退到本地 Ollama。

# 查看当前默认模型、fallback 和各 Provider 认证状态
openclaw models status
# Default: siliconflow/Pro/deepseek-ai/DeepSeek-V3.2
# Fallbacks: ollama/llama3.3, ollama/qwen2.5-coder:32b

# 列出模型、设置默认模型和图像模型
openclaw models list
openclaw models set siliconflow/Pro/deepseek-ai/DeepSeek-V3.2
openclaw models set-image <provider/model-id>

# 管理 fallback 链
openclaw models fallbacks list
openclaw models fallbacks add ollama/llama3.3

# 扫描 OpenRouter 免费模型，探测哪些支持工具调用
openclaw models scan

认证与别名：

openclaw models auth add        # 交互式添加 API Key 或 Token
openclaw models auth login      # OAuth / API Key 登录某个 Provider
openclaw models auth list

# 给长模型 ID 起短名
openclaw models aliases add ds siliconflow/Pro/deepseek-ai/DeepSeek-V3.2
openclaw models aliases list

配置管理

配置文件是 JSON5，默认在 ~/.openclaw/openclaw.json。日常改配置尽量走 CLI，它会做 schema 校验：

openclaw config get agents.defaults.compaction.mode
openclaw config set gateway.port 19001 --strict-json
openclaw config unset <path>

# 一次合并多处修改（对象递归合并、数组和标量直接替换）
openclaw config patch --file ./openclaw.patch.json5 --dry-run

# 不启动网关，只校验配置（v2026.3.2 新增）
openclaw config validate

# 打印完整 JSON Schema，查字段名最可靠的方式
openclaw config schema

config validate 值得养成习惯：改完配置、重启网关之前跑一次，避免网关一启动就因为字段写错崩掉。

主要顶层块：

块作用常用字段
models模型 Provider 注册providers.<id>.baseUrl / apiKey / api / models[]
agentsAgent 默认值与各 Agent 覆盖defaults.model.primary、defaults.workspace、defaults.compaction、entries
tools工具权限profile、allow、deny、byProvider
channels渠道连接discord.token、groupPolicy、dmPolicy、guilds
bindings消息路由到哪个 AgentagentId、match
session会话作用域dmScope 等
hooks自动化钩子internal.entries.<name>.enabled
memory记忆与语义检索search.provider
gateway网关监听参数port、bind、auth
plugins插件启用状态entries.<name>.enabled

meta、wizard 两个顶层字段由 OpenClaw 自己维护（版本号、向导运行时间），不用手动改。

Tools 配置：控制 Agent 能做什么

tools 决定 Agent 能调用哪些工具，核心逻辑是先用 profile 设基线，再用 allow / deny 精调，deny 优先于 allow。

Profile大致范围适用场景
minimal几乎只有会话状态查询只读、极简场景
messaging消息收发、会话管理聊天助手
coding文件系统、运行时（shell）、会话、记忆、图像等开发者场景
full不限制完全信任的环境

v2026.3.2 起，新安装的默认 profile 改成了 messaging，不再默认开放 shell 和文件工具。我的做法是保持 messaging，只额外放开 Discord、exec（shell）和 fs（文件系统）：

// ~/.openclaw/openclaw.json
{
  tools: {
    profile: "messaging",
    allow: ["discord", "exec", "fs"]
  }
}

反过来，想在 coding 的基础上禁掉某一类工具，可以按组 deny：

{
  tools: {
    profile: "coding",
    deny: ["group:runtime"]   // 禁掉 exec、process 等运行时工具
  }
}
openclaw config get tools.profile
openclaw config set tools.profile coding

tools.byProvider 还能针对某个 Provider 或模型单独收窄权限，比如给便宜的备用模型只开 minimal，用法见进阶篇第 6 条。

记忆系统

OpenClaw 的长期记忆是 workspace 下的 Markdown 文件（默认 ~/.openclaw/workspace/memory/），通过向量索引加全文检索做语义搜索。

openclaw memory status            # 索引状态、embedding provider、文件数
openclaw memory status --deep     # 额外探测 embedding provider 是否可用
openclaw memory search "deployment notes"
openclaw memory index --force     # 全量重建索引

我第一次跑 memory status 时提示 memory directory missing，因为目录还没创建。手动 mkdir -p ~/.openclaw/workspace/memory 后，Agent 会自动往里写记忆文件。

v2026.3.2 增加了 Ollama embedding 支持，可以完全在本地做语义检索。按 2026.9.9 的 schema，配置路径是 memory.search：

{
  memory: {
    search: {
      provider: "ollama"
    }
  }
}

多 Agent：独立 workspace 与路由

Agent 配置分两层：agents.defaults 是所有 Agent 的基线，每个 Agent 可以单独覆盖。

{
  agents: {
    defaults: {
      model: {
        primary: "siliconflow/Pro/deepseek-ai/DeepSeek-V3.2",
        fallbacks: ["ollama/llama3.3", "ollama/qwen2.5-coder:32b"]
      },
      workspace: "~/.openclaw/workspace",
      compaction: { mode: "safeguard" },   // 2026.9.9 可选 safeguard / default
      maxConcurrent: 4,
      subagents: { maxConcurrent: 8 }
    }
  }
}

用 CLI 管理 Agent

openclaw agents list

# 新建 Agent（非交互式需要 --workspace）
openclaw agents add work --workspace ~/.openclaw/workspace-work --non-interactive

# 把某个渠道的消息路由给它
openclaw agents bind --agent work --bind telegram

# 设置名字和 emoji
openclaw agents set-identity --agent work --name "工作助手" --emoji 💼

openclaw agents bindings
openclaw agents delete work      # 同时清理 workspace 和状态

建好之后用 openclaw agent --agent work --message "介绍一下你自己" 发一条消息，可以确认它和 main Agent 的上下文、Skills、记忆互不影响。

在配置文件里按 Agent 覆盖

{
  agents: {
    entries: {
      work: {
        workspace: "~/.openclaw/workspace-work",
        model: { primary: "anthropic/<模型 ID>" },
        tools: { profile: "coding" }
      },
      support: {
        // 支持类 Agent 只允许消息工具，不让它跑 shell
        tools: { profile: "messaging", allow: ["slack"] }
      }
    }
  }
}

v2026.3.x 的配置用的是数组 agents.list: [{ id: "work", ... }]。2026.9.9 的规范写法是以 ID 为键的 agents.entries，旧的 agents.list 写法在 config set / patch / unset 中仍被接受，写回时会转成新格式。

路径规则

  • 每个 Agent 的状态目录：~/.openclaw/agents/<agentId>/agent/
  • 每个 Agent 的会话记录：~/.openclaw/agents/<agentId>/sessions/
  • 认证信息按 Agent 隔离，不同 Agent 之间不会自动共享

ACP：让编辑器接入 OpenClaw

ACP 是 Agent Client Protocol（Zed 等编辑器在用的开放协议）。openclaw acp 是一个桥：一端通过 stdio 讲 ACP 给 IDE，另一端通过 WebSocket 把请求转发给 OpenClaw 网关。编辑器里配置它作为 ACP agent 后，就能直接把任务交给你的 OpenClaw 会话。

# 作为 IDE 的 ACP agent 启动（通常由编辑器拉起）
openclaw acp

# 绑定到已有会话，不存在就报错，避免意外新建会话
openclaw acp --session agent:main:main --require-existing

# 连接远端网关（Tailscale 或公网地址）
openclaw acp --url wss://gateway-host:18789 --token-file ~/.openclaw/gateway.token

openclaw acp client 是内置的调试客户端，它会拉起 ACP 桥并让你在终端里交互输入，用来在没有 IDE 的情况下验证链路：

openclaw acp client --cwd ~/projects/myapp

在提示符下输入问题即可对话，常用的斜杠命令有：

命令说明
/status当前会话状态
/usagetoken 用量
/model切换当前会话的模型
/compact压缩上下文
/think调整思考深度
/elevated临时提升工具权限
/bash <cmd>直接执行 shell 命令
/subagents查看活跃的子 Agent
/stop停止当前任务
exit退出客户端

v2026.3.2 起 acp.dispatch.enabled 默认为 true。安全敏感的环境可以关掉：

openclaw config set acp.dispatch.enabled false

想在脚本或 CI 里调用 Agent，更直接的方式是 openclaw agent，它跑一轮对话后退出：

openclaw agent --agent main --message "检查 /tmp 下最大的 5 个文件"
openclaw agent --agent main --message-file ./task.md --json

和 Claude Code 协作，2026.9.9 提供了 openclaw attach：它为 Claude Code 签发一个限定范围的 MCP 授权，让 Claude Code 绑定到某个网关会话里使用 OpenClaw 的工具。

定时任务

cron 子命令（2026.9.9 起也叫 automations）让 Agent 按计划自动执行任务。

openclaw cron list
openclaw cron rm <job-id>
openclaw cron runs              # 运行历史

每日日报 + 每周周报：

# 每天 8 点（上海时区）生成日报，并把结果发到 Discord 频道
openclaw cron add \
  --name "morning-report" \
  --cron "0 8 * * *" \
  --tz "Asia/Shanghai" \
  --message "使用 git_daily_report skill 生成今日工作摘要" \
  --channel discord \
  --to "channel:123456789012345678" \
  --announce

# 每周一 9 点生成周报
openclaw cron add \
  --name "weekly-summary" \
  --cron "0 9 * * 1" \
  --tz "Asia/Shanghai" \
  --message "汇总过去一周的 git 提交和完成情况，生成周报" \
  --channel discord \
  --to "channel:123456789012345678" \
  --announce

几个参数的含义：

  • --announce：任务完成后把最终结果投递到指定渠道，相当于让 Agent 主动给你汇报。旧的 --deliver 已标记为弃用。
  • --channel discord 只选平台，必须再用 --to 指定接收目标，否则会报 Discord recipient is required。频道写 channel:<频道ID>，私信写 user:<用户ID>；只写一串数字会被当作频道 ID。怎么拿到这些 ID，见进阶篇第 12 条。
  • 已创建的任务用 openclaw cron edit <job-id> --to "channel:<ID>" 补参数，不用删了重建。

其他常用写法：

# 每 30 分钟执行一次
openclaw cron add --name "health-check" \
  --every 30m \
  --message "检查网关状态，如有异常通知我" \
  --channel discord --to "user:123456789012345678" --announce

# 一次性任务：20 分钟后执行，成功后自动删除
# --at 支持时长（20m、1h）或 ISO 8601 时间
openclaw cron add --at "20m" \
  --message "提醒我：站会即将开始" \
  --channel discord --to "user:123456789012345678" --announce \
  --delete-after-run

Hooks：事件钩子

Hooks 在特定事件发生时自动执行：网关启动、Agent 初始化、用户执行 /new 等命令。v2026.3.2 内置 4 个，2026.9.9 又多了一个 compaction-notifier（上下文压缩开始和结束时在聊天里提示）。

openclaw hooks list
openclaw hooks check
openclaw hooks info session-memory
openclaw hooks enable session-memory
openclaw hooks disable command-logger

Hook触发事件作用
boot-mdgateway:startup网关启动时执行 workspace 下的 BOOT.md
bootstrap-extra-filesagent:bootstrapAgent 初始化时按 glob 注入额外文件
command-loggercommand把命令事件以 JSONL 写入 ~/.openclaw/logs/commands.log
session-memorycommand:new / command:reset执行 /new 或 /reset 时把会话上下文存成记忆文件

默认只启用 boot-md，其余需要手动 enable。session-memory 默认保存最近 15 条消息，可以调大：

openclaw config set hooks.internal.entries.session-memory.messages 20
# 提示 Restart the gateway to apply 后重启网关

boot-md：网关启动时自检。在 workspace 根目录放一个 BOOT.md，网关每次启动都会让 Agent 执行其中的指令：

cat > ~/.openclaw/workspace/BOOT.md << 'EOF'
# BOOT.md — 网关启动时执行

1. 检查本地 Ollama 是否在线：运行 `curl -s http://localhost:11434/api/version`
2. 报告当前时间、网关状态和活跃会话数
3. 向默认 Discord 频道发送一条启动通知
EOF

bootstrap-extra-files：多项目上下文注入。每个项目有自己的 AGENTS.md 时，可以在 Agent 初始化时一次性注入：

openclaw hooks enable bootstrap-extra-files
openclaw config set hooks.internal.entries.bootstrap-extra-files.paths '["projects/*/AGENTS.md","projects/*/TOOLS.md"]'

验证方法：执行一次 /new 后，~/.openclaw/logs/commands.log 应该多出一行 JSONL；memory/ 目录下会多一个以日期加对话主题命名的 Markdown 文件。

第三方 Hook 以插件包形式分发，2026.9.9 起 openclaw hooks install 已弃用，改用 openclaw plugins install。

调试与日常维护

出问题时按这个顺序查，详细的排障思路见进阶篇的调试部分：

openclaw doctor             # 全面健康检查
openclaw doctor --fix       # 应用推荐的修复
openclaw doctor --deep      # 额外扫描系统里是否有多余的网关安装

openclaw status             # 网关、渠道、Agent、会话的总览
openclaw status --all       # 只读的完整诊断报告，适合贴给别人看
openclaw status --deep      # 主动探测各渠道连通性

openclaw logs --follow      # 实时跟踪网关日志
openclaw channels logs --channel discord

会话列表能看出每个会话的上下文占用，回复变慢时先看这里：

openclaw sessions
openclaw sessions --all-agents

安全审计建议在新增渠道或修改工具权限后都跑一次：

openclaw security audit
openclaw security audit --deep   # 额外探测运行中的网关
openclaw security audit --fix    # 自动修复文件权限等安全问题

我第一次跑时有两条 CRITICAL：Discord 的 groupPolicy 是 open（任何人 @Bot 都能触发工具调用），以及 credentials 目录权限过宽。处理方法见进阶篇第 5 条。

终端 UI：openclaw tui 是在终端里运行的控制台，适合 SSH 环境；openclaw dashboard 则会用当前 token 打开浏览器里的 Control UI。

重置（不可逆，先备份 ~/.openclaw/openclaw.json）：

openclaw reset --dry-run --scope config --non-interactive --yes   # 预览
openclaw reset --scope config --yes --non-interactive             # 只清配置
openclaw reset --scope config+creds+sessions --yes --non-interactive
openclaw reset --scope full --yes --non-interactive               # 完全重置

版本变更要点

v2026.3.2 的三处 Breaking Change：

  1. tools.profile 默认值改为 messaging，不再默认开放编码和系统工具，需要时手动设成 coding。
  2. ACP dispatch 默认开启（acp.dispatch.enabled = true）。
  3. 插件 SDK 移除 registerHttpHandler，改用 registerHttpRoute({ path, auth, match, handler })，只影响自定义插件开发者。

升级到 2026.9.9 时要注意的（2026-10 复核）：

  1. Node.js 最低要求提到 24.16 / 26.1。
  2. agents.list 的规范写法变成 agents.entries，Discord 的 streaming 变成对象。
  3. ClawHub Skill 可以直接 openclaw skills install @owner/slug；hooks install 弃用，改走 plugins install。
  4. cron add 的 --deliver 弃用，用 --announce。

从哪里开始

不需要一次配齐所有功能。比较顺的上手路径是：openclaw onboard 完成基础配置，接入一个你最常用的渠道，发几条消息确认链路通了，再跑一次 openclaw security audit，然后根据实际需求逐步加 Skills、定时任务和第二个 Agent。
