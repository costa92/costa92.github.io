uv 实战教程：用 Rust 速度管理 Python 项目

 2026-03-02  Tool 开发工具 python uv 包管理
开发工具 python uv 包管理
Tool
文章字数:   2k
阅读次数:  
   阅读模式

pip 装包慢、venv 命令长、pyenv 配置烦，这三件事困扰 Python 开发者很多年。uv 用一个二进制文件把它们都接了过去。它由 Astral 团队（ruff 的作者）用 Rust 编写，官方给出的说法是比 pip 快 10–100 倍，并且内置了虚拟环境管理、Python 版本管理和项目脚手架。

环境说明
本文初稿基于 uv 0.6.10；截至 2026-10，uv 最新版本为 0.12.24，文中命令和输出已在 0.12.24 上重新跑过。uv 仍处于 0.x 阶段，小版本之间会有行为变化，涉及到的地方文中单独注明。

安装 uv

uv 是独立二进制文件，不依赖 Python 本身。推荐用官方脚本安装：

# Linux / macOS
curl -LsSf https://astral.sh/uv/install.sh | sh

# macOS (Homebrew)
brew install uv

# Windows
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

# 验证安装
uv --version
# uv 0.12.24 (x86_64-unknown-linux-gnu)

# 已经装过的，用自带命令升级（独立安装方式适用）
uv self update

已有 pip 的环境
也可以 pip install uv，但更推荐独立安装：这样 uv 不依赖任何 Python 环境，反过来可以管理 Python 本身。

从零创建项目

# 在当前目录下新建 my-api 目录并初始化
uv init my-api
cd my-api

注意 uv init 的位置参数是目录：uv init my-api 会新建目录；而 uv init --name my-api 只是给项目起名，会直接在当前目录初始化，不会创建 my-api/。

从 0.12 开始，uv init 默认生成的是可打包的 src 布局：

my-api/
├── .git/
├── .gitignore
├── .python-version         # 固定 Python 版本
├── README.md
├── pyproject.toml          # 项目配置（PEP 621）
└── src/
    └── my_api/
        └── __init__.py     # 带一个 main() 入口

pyproject.toml 里多了脚本入口和构建后端：

[project]
name = "my-api"
version = "0.1.0"
description = "Add your description here"
readme = "README.md"
requires-python = ">=3.12"
dependencies = []

[project.scripts]
my-api = "my_api:main"

[build-system]
requires = ["uv_build>=0.12.24,<0.13.0"]
build-backend = "uv_build"

requires-python 取的是 uv 找到的 Python 版本。另外 uv 会从 git 配置里读出姓名和邮箱写进 authors 字段，上面省略了，发布前记得检查。

如果只是写个脚本型应用、不打算打包，加 --no-package，得到的是旧版那种扁平结构：根目录一个 main.py，没有 [build-system]：

uv init --no-package my-script

标准兼容
pyproject.toml 遵循 PEP 621，pip、poetry、hatch 等工具都能读。

依赖管理

添加和移除依赖

# 添加依赖
uv add requests
# Resolved 6 packages in ...
#  + requests==2.34.2
#  ...

# 添加开发依赖（写入 [dependency-groups] 的 dev 组）
uv add --dev pytest ruff

# 指定版本约束
uv add "fastapi>=0.115.0"

# 移除依赖
uv remove requests

每次 uv add 会：

  1. 解析依赖树；
  2. 更新 pyproject.toml；
  3. 生成或更新 uv.lock 锁文件；
  4. 把依赖装进项目下的 .venv。

查看依赖树

uv tree
# my-api v0.1.0
# └── requests v2.34.2
#     ├── certifi v2026.7.22
#     ├── charset-normalizer v3.5.2
#     ├── idna v3.20
#     └── urllib3 v2.8.0

requests 的 4 个传递依赖一目了然。版本号会随时间变化，以你本地的输出为准。

运行代码

uv 不需要手动激活虚拟环境，用 uv run 直接在项目环境中执行：

# 运行 [project.scripts] 里定义的入口
uv run my-api
# Hello from my-api!

# 运行任意命令
uv run python -c "import requests; print(requests.__version__)"
uv run pytest tests/

uv run 每次执行前都会检查锁文件和 .venv 是否与 pyproject.toml 一致，不一致就先同步，所以改完依赖不用手动 uv sync。

别直接用 python
没激活虚拟环境时直接 python main.py，用的是系统 Python，不会加载项目依赖。统一用 uv run。

0.12 的变化
uv run script.py 现在从脚本所在目录开始查找项目，而不是当前工作目录。想沿用旧行为，加 --project .。

PEP 723 内联脚本：零配置运行

uv 支持 PEP 723 内联元数据：把依赖声明写在 Python 文件的注释块里，不需要 pyproject.toml 或 requirements.txt。

# fetch_ip.py
# /// script
# dependencies = ["httpx"]
# requires-python = ">=3.10"
# ///

import httpx

resp = httpx.get("https://httpbin.org/get")
print(f"Status: {resp.status_code}")
print(f"IP: {resp.json()['origin']}")
uv run fetch_ip.py
# 首次运行会在隔离环境里装好 httpx，之后走缓存
# Status: 200
# IP: 203.0.113.10

元数据块不用手写，可以让 uv 加：

uv add --script fetch_ip.py httpx

适用场景
一次性工具、数据处理脚本、CI 辅助脚本这类不值得建项目的场景。把脚本发给别人，对方只要 uv run script.py，依赖自动处理。

Python 版本管理

uv 内置 Python 版本管理，可以替代 pyenv：

# 查看已安装和可下载的版本
uv python list

# 安装指定版本
uv python install 3.12

# 固定项目 Python 版本（写入 .python-version）
uv python pin 3.12

# 查看当前会用哪个解释器
uv python find

与 pyenv 的区别
pyenv 通过 shims 拦截 python 命令，容易和系统 Python 打架。uv 默认不改全局 python，版本按项目的 .python-version 走。

全局工具管理（替代 pipx）

uv tool 是 pipx 的替代品，把 CLI 工具装进各自独立的环境，不污染项目依赖：

# 临时运行（不安装），uvx 是 uv tool run 的简写
uvx ruff --version
# ruff 0.16.10

# 全局安装
uv tool install ruff

# 查看已安装的工具
uv tool list

# 升级和卸载
uv tool upgrade ruff
uv tool uninstall ruff

uvx 的思路和 npx 一样：需要某个 CLI 工具时不必全局安装，uvx black . 用完即走。

构建和发布包

# 构建 sdist + wheel
uv build
# Successfully built dist/my_api-0.1.0.tar.gz
# Successfully built dist/my_api-0.1.0-py3-none-any.whl

# 发布到 PyPI
uv publish --token pypi-xxxx

只要 sdist 用 uv build --sdist，只要 wheel 用 uv build --wheel。不用再单独装 build 和 twine。用 --no-package 建的项目没有构建后端，需要先在 pyproject.toml 里补上 [build-system] 才能 build。

性能

uv 快在两点：Rust 实现的并行依赖解析和下载，以及全局缓存（同一个包在多个项目间用硬链接或写时复制共享，不重复下载）。具体倍数和场景有关，官方仓库的 BENCHMARKS.md 给出了冷/热缓存下与 pip、poetry 等工具的对比方法和结果，想要自己环境的数字，可以拿手头的 requirements.txt 分别用 pip install 和 uv pip install 各跑一次。

与 pip 兼容的命令

如果团队还没准备好切到 uv add/remove，uv 提供了兼容 pip 的接口：

uv pip install requests
uv pip install -r requirements.txt
uv pip freeze > requirements.txt
uv pip uninstall requests

# 创建虚拟环境
uv venv
source .venv/bin/activate  # Linux/macOS

把现有的 pip install 换成 uv pip install，工作流不变，速度先提上来。0.12 起 uv pip install 会真正执行 requirements.txt 里的 --require-hashes 校验，以前被忽略的哈希不匹配现在会直接报错。

迁移现有项目

只有 requirements.txt 的项目：

cd existing-project

# 只生成 pyproject.toml，不创建示例代码
uv init --bare

# 直接从 requirements.txt 导入依赖
uv add -r requirements.txt

# 生成锁文件并同步环境
uv lock
uv sync

uv add -r 能正确处理注释、空行和版本约束，不需要自己用 grep/tr 拼参数。

已经有 pyproject.toml 的项目（setuptools、hatch 等）： 不要再跑 uv init，它会报 Project is already initialized 退出。直接 uv lock && uv sync 即可，uv 会按已有的 [project] 依赖生成 uv.lock。poetry 项目如果依赖还写在 [tool.poetry] 里，需要先转成标准的 [project] 写法。

渐进式迁移
不必一次切完。先用 uv pip install -r requirements.txt 拿到速度提升，再逐步切到 uv add/remove 工作流。
