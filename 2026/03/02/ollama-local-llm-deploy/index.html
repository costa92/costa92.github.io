Ollama 本地部署大模型实战：从安装到 API 调用全流程

 2026-03-02  AI Claude Code Ollama LLM 本地部署
Claude Code Ollama LLM 本地部署 大模型
AI
文章字数:   2.8k
阅读次数:  
   阅读模式

把大模型跑在自己机器上、不经过任何第三方服务器，这件事几年前还需要折腾 CUDA、编译 llama.cpp、手动转换模型权重。Ollama 把这些封装成了一条命令：

ollama run qwen2.5-coder:7b

Ollama 会自动下载模型、加载到显存（或内存）、进入交互式对话。没有 API Key，数据不出本机。

版本说明
本文命令在 Ollama 0.35.0（Linux）上核对过；截至 2026-10，最新版本是 0.40.x。Ollama 迭代很快，个别输出格式可能略有差异。

如果你在纠结 Ollama、vLLM、llama.cpp 该选哪个，可以先看《vLLM vs Ollama vs llama.cpp：DevOps 怎么选》；本文只讲 Ollama 本身怎么用。

安装 Ollama

# Linux
curl -fsSL https://ollama.com/install.sh | sh

# macOS（也可以去官网下载桌面版）
brew install ollama

# 验证安装
ollama --version
# ollama version is 0.35.0

Linux 安装脚本会顺带创建一个 ollama 的 systemd 服务，开机自启，监听 127.0.0.1:11434。升级也是重跑同一条安装命令。

GPU 自动检测
有 NVIDIA 显卡时 Ollama 自动用 CUDA，Apple Silicon 用 Metal。纯 CPU 也能跑，只是生成速度明显慢，7B 级别模型在 CPU 上更适合偶尔用用。

模型管理

下载和查看模型

# 直接运行（本地没有会先下载）
ollama run qwen2.5-coder:7b

# 只下载不运行
ollama pull deepseek-r1:7b

# 查看已下载的模型
ollama list

我这台机器上 ollama list 的部分输出：

NAME                ID              SIZE      MODIFIED
qwen2.5-coder:7b    dae161e27b0e    4.7 GB    3 months ago
llama3.1:8b         46e0c10c039e    4.9 GB    4 months ago
deepseek-r1:7b      755ced02ce7b    4.7 GB    9 months ago

可用的模型和标签在 Ollama 模型库 查：

查看模型详情

ollama show qwen2.5-coder:7b
Model
  architecture        qwen2
  parameters          7.6B
  context length      32768
  embedding length    3584
  quantization        Q4_K_M

Capabilities
  completion
  tools
  insert

关键信息一目了然：7.6B 参数，模型本身支持 32K 上下文，Q4_K_M 量化（4-bit，K_M 是兼顾速度和质量的量化方案）。FP16 原始权重约 15GB，量化后 4.7GB。tools 表示支持工具调用，接 Agent 类工具时要看这一项。

注意”模型支持 32K”不等于”Ollama 默认给它 32K”，这一点在后面的上下文配置里会讲。

删除模型

ollama rm llama3.1:8b

磁盘空间
Q4 量化下，7B 模型约 4–5GB，13B 约 8GB，70B 需要 40GB 以上。下载前确认磁盘空间，定期用 ollama list 清理不用的模型。

对话和运行状态

交互式对话

ollama run qwen2.5-coder:7b
>>> 用一句话解释什么是 Kubernetes
Kubernetes 是一个开源的容器编排平台，用于自动化应用程序的部署、扩展和管理。

>>> /bye

/bye 退出。退出后模型默认还会在内存里保留 5 分钟，期间再次调用不需要重新加载。

查看当前加载的模型

ollama ps
NAME                ID              SIZE      PROCESSOR    CONTEXT    UNTIL
qwen2.5-coder:7b    dae161e27b0e    8.2 GB    100% CPU     4096       4 minutes from now

几列的含义：

  • SIZE：加载后的实际占用，包含 KV 缓存等，比 ollama list 里的文件大小大；
  • PROCESSOR：跑在哪里。上面这次是我在显卡驱动不可用时跑的，所以是 100% CPU；正常有 GPU 时是 100% GPU，显存不够时会出现 48%/52% CPU/GPU 这样的混合分配，速度介于两者之间；
  • CONTEXT：本次加载实际使用的上下文长度，这里是默认的 4096；
  • UNTIL：多久后自动卸载。

REST API 集成

Ollama 服务默认监听 localhost:11434，同时提供三套接口：

  • 原生 API：/api/generate、/api/chat 等；
  • OpenAI 兼容接口：/v1/chat/completions 等；
  • Anthropic 兼容接口：/v1/messages，Claude Code 接本地模型靠的就是它。

原生 API

curl -s http://localhost:11434/api/generate \
  -d '{
    "model": "qwen2.5-coder:7b",
    "prompt": "用一句话解释什么是 Docker",
    "stream": false
  }' | jq -r '.response'

非流式返回的 JSON 里除了 response，还有 eval_count（生成的 token 数）、eval_duration（生成耗时，纳秒）、load_duration（加载耗时）等字段，用 eval_count / eval_duration 就能算出自己机器上的生成速度。

Python 集成

只用标准库即可：

import json
import urllib.request


def ollama_generate(
    prompt: str,
    model: str = "qwen2.5-coder:7b",
    base_url: str = "http://localhost:11434",
) -> str:
    req = urllib.request.Request(
        f"{base_url}/api/generate",
        data=json.dumps({"model": model, "prompt": prompt, "stream": False}).encode(),
        headers={"Content-Type": "application/json"},
    )
    # 首次调用包含模型加载时间，CPU 上可能要几十秒
    with urllib.request.urlopen(req, timeout=120) as resp:
        data = json.loads(resp.read())
    return data["response"]


print(ollama_generate("用一句话解释什么是 Docker"))

OpenAI 兼容接口

项目里已经在用 openai 库的话，改 base_url 就能切到本地模型，api_key 随便填但不能为空：

from openai import OpenAI

client = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")
resp = client.chat.completions.create(
    model="qwen2.5-coder:7b",
    messages=[{"role": "user", "content": "你好"}],
)
print(resp.choices[0].message.content)

自定义模型（Modelfile）

Modelfile 是类似 Dockerfile 的声明式配置，可以把系统提示词和参数固化成一个新模型：

# Modelfile
FROM qwen2.5-coder:7b

PARAMETER temperature 0.3
PARAMETER num_ctx 32768

SYSTEM """
你是一个 Linux 运维专家。用户会问你服务器相关的问题，
你需要给出具体的命令和操作步骤。回答要简洁，直接给命令。
"""
ollama create linux-expert -f Modelfile
ollama run linux-expert
>>> nginx 502 怎么排查

这里的 num_ctx 32768 是关键：它让这个模型每次加载都用 32K 上下文，而不是默认的 4096。读代码库、接 Agent 这类场景，4096 很快就会被撑爆，前面的内容被截断，模型表现会突然变差。只想要大上下文、不改系统提示词的话，Modelfile 里写 FROM 和 PARAMETER num_ctx 两行就够了：

printf 'FROM qwen2.5-coder:7b\nPARAMETER num_ctx 32768\n' > Modelfile
ollama create qwen2.5-coder-32k -f Modelfile

上下文越大，KV 缓存占用越多，显存不够时会落到 CPU 上，用 ollama ps 确认一下 PROCESSOR 列。

ollama launch：一条命令接入编程工具

ollama launch 在 2026 年 1 月随 0.15 版本推出。以前想让 Claude Code 用本地模型，要自己设置 ANTHROPIC_BASE_URL、假的 token 等一堆环境变量（具体原理和手动配置方式见《基于 Claude Code 与 Ollama 的混合云 AI 编程助手架构》）；现在 ollama launch 会替你把这些配好并直接启动工具：

# 交互式选择模型，然后启动 Claude Code
ollama launch claude

# 直接指定模型
ollama launch claude --model qwen3-coder

# 只写配置、不启动（适合 OpenCode、Droid 这类读配置文件的工具）
ollama launch opencode --config

# 把某个工具的配置恢复成默认
ollama launch codex --restore

不带参数运行 ollama launch 会进入交互菜单，先选工具再选模型。发布时支持 Claude Code、Codex、OpenCode 和 Droid（Factory 出的编程 Agent），到 0.35 版本已经扩展到 Copilot CLI、Qwen Code、Cline、VS Code 等十几个集成，完整列表以 ollama launch --help 为准。

几点实际使用中的经验：

  • 上下文窗口要够大。 官方建议编程工具至少用 64000 token 的上下文。用默认 4096 的模型去跑 Claude Code，几轮之后就会因为上下文被截断而答非所问。可以用上面的 Modelfile 做一个大上下文版本，或者设置下文的 OLLAMA_CONTEXT_LENGTH。
  • 模型选择。 官方推荐的本地模型有 glm-4.7-flash、qwen3-coder、gpt-oss:20b，其中 glm-4.7-flash 在 64K 上下文下需要约 23GB 显存。显存不够可以用云端模型，比如 glm-4.7:cloud、qwen3-coder:480b-cloud，名字带 cloud 的模型在 Ollama 云端运行、本地不占显存，但需要先 ollama signin 登录，数据也会离开本机。
  • 对本地小模型的预期。 7B/14B 级别的模型做单文件修改、简单 bug 修复还可以；多文件重构、长链路规划时容易出现指令遵循不到位、工具调用格式出错。复杂任务还是切回云端模型更省时间。

模型生命周期管理

# 主动卸载模型，立刻释放显存（不用等 keep-alive 超时）
ollama stop qwen2.5-coder:7b

# 复制模型
ollama cp qwen2.5-coder:7b my-coder

# 登录 ollama.com（使用云端模型需要）
ollama signin

ollama stop 在切换模型时很有用：旧模型还占着显存时，新模型可能只能部分放到 GPU 上。

环境变量调优

Ollama 的运行行为主要通过环境变量控制：

变量作用默认值
OLLAMA_CONTEXT_LENGTH默认上下文长度4096
OLLAMA_KEEP_ALIVE模型空闲后保留多久5m
OLLAMA_HOST监听地址127.0.0.1:11434
OLLAMA_ORIGINS允许跨域的来源（浏览器里的 Web 应用直连时需要）仅本地
OLLAMA_FLASH_ATTENTION启用 Flash Attention，降低长上下文的显存占用视硬件而定
OLLAMA_KV_CACHE_TYPEKV 缓存量化（f16/q8_0/q4_0）f16
OLLAMA_MAX_LOADED_MODELS最多同时加载几个模型GPU 数 × 3，CPU 为 3
OLLAMA_NUM_PARALLEL单个模型的并发请求数1

注意：Linux 上 Ollama 作为 systemd 服务运行，在自己的 shell 里 export 这些变量是不生效的。 要写进服务配置：

sudo systemctl edit ollama.service

在打开的编辑器里加：

[Service]
Environment="OLLAMA_CONTEXT_LENGTH=32768"
Environment="OLLAMA_KEEP_ALIVE=30m"
Environment="OLLAMA_FLASH_ATTENTION=1"

保存后重载并重启：

sudo systemctl daemon-reload
sudo systemctl restart ollama

macOS 桌面版用 launchctl setenv OLLAMA_CONTEXT_LENGTH 32768 设置后重启 Ollama 应用；手动前台跑 ollama serve 的话，在同一个 shell 里 export 即可。

安全提示
OLLAMA_HOST=0.0.0.0 会把 API 暴露到所有网卡，而 Ollama 的 API 没有鉴权。只在可信内网这么做，并配合防火墙或带鉴权的反向代理，不要直接暴露到公网。

Docker 部署

需要隔离环境或在服务器上统一管理时，可以用官方镜像：

# CPU 版本
docker run -d -v ollama:/root/.ollama \
  -p 11434:11434 --name ollama \
  ollama/ollama

# NVIDIA GPU 版本（需要先装 nvidia-container-toolkit）
docker run -d --gpus=all \
  -v ollama:/root/.ollama \
  -p 11434:11434 --name ollama \
  ollama/ollama
# 在容器里拉模型
docker exec -it ollama ollama pull qwen2.5-coder:7b

# 从宿主机调用 API
curl http://localhost:11434/api/tags

-v ollama:/root/.ollama 把模型存到 Docker volume 里，容器重建后不用重新下载。容器版的环境变量用 docker run -e OLLAMA_CONTEXT_LENGTH=32768 ... 传入。

常见问题

模型下载很慢

国内网络从官方源拉模型可能较慢。Ollama 拉取走 HTTPS，要设置的是 HTTPS_PROXY（不是 HTTP_PROXY），而且同样要设在服务进程上，而不是执行 ollama pull 的 shell：

# sudo systemctl edit ollama.service
[Service]
Environment="HTTPS_PROXY=http://127.0.0.1:7890"

显存不够怎么办

  • 选更小的模型或更低精度的量化版本：同一个 7B 模型，Q4_K_M 约 4.7GB，FP16 约 15GB；
  • 适当减小上下文长度，或者开启 OLLAMA_FLASH_ATTENTION 和 OLLAMA_KV_CACHE_TYPE=q8_0 降低 KV 缓存占用；
  • 实在放不下时 Ollama 会自动做 GPU/CPU 混合推理，不用手动配置，只是会变慢。

同时运行多个模型

显存足够时，Ollama 可以同时加载多个模型，分别在不同终端里 ollama run 即可，用 ollama ps 查看。上限由 OLLAMA_MAX_LOADED_MODELS 控制，超出后会按最近使用情况卸载旧模型。
