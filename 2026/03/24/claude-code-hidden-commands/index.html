Claude Code 进阶命令手册：23 个容易被忽略的命令和快捷键

 2026-03-24  Coding-Agent Claude Code 效率工具 命令行技巧 AI Coding

团队里有同事用了三个月 Claude Code，还不知道在空输入框里按两下 Esc 可以回退代码。

我问了一圈，发现这不是个例。Claude Code 迭代很快，几乎每周都有新命令、改名或行为调整，很多变化只出现在 CHANGELOG 里，不翻就不会知道。

所以我把日常最常用的命令和快捷键整理了一遍，并逐条对照了官方命令文档和交互模式文档。不是大而全的文档搬运，是我每天真在用的东西。

版本说明：本文内容以 2026-10 的 Claude Code v2.1.295 为准。命令会继续改名或调整，遇到对不上的地方，以会话里输入 / 弹出的命令列表和 /release-notes 为准。

一. /btw——插个嘴但不留痕迹

Claude 正在帮你重构一个大模块，你突然想问个相关的小问题——以前你一问，这段问答就进了对话历史，Claude 回来继续干活时可能被带偏。

现在打 /btw，空格，写问题，发送：

/btw 刚才你说的那个配置文件叫什么来着？

答案以浮层显示，按空格、回车或 Esc 关闭，这段问答不进入对话历史。几个要点：

  • Claude 干活时也能问：side question 独立运行，不打断当前回合。
  • 没有工具权限：它只根据当前上下文回答，不会去读文件、跑命令或搜索。所以适合问”刚才读过的代码里 X 是什么”，不适合问它还没看过的东西。
  • 几乎不额外花钱：提示缓存还热的时候，除了答案本身没什么额外成本。
  • 不带问题直接打 /btw，可以翻看之前问过的 side question。

我现在每个长会话里都会用几次，问完就关，主线上下文干干净净。

二. /rewind——后悔药，还能选择性吃

在输入框为空时按两下 Esc，或者打 /rewind（别名 /checkpoint、/undo）。

选中要回到的那条消息后，会弹出这些选项：

  • Restore code and conversation：代码和对话一起回退
  • Restore conversation：只回退对话，保留代码
  • Restore code：只回退代码，保留对话
  • Summarize from here：把从这里往后的对话压缩成摘要，释放上下文
  • Summarize up to here：把这里之前的对话压缩成摘要，保留后面的消息

“只回退代码、保留对话”特别适合做实验：让 Claude 试一种写法，不行就把代码退回去，对话留着——Claude 还记得刚才聊了什么、知道这条路不通，直接换方向，不用重新解释需求。

有个限制要知道：checkpoint 只追踪 Claude 用文件编辑工具做的修改，通过 Bash 命令改的文件（rm、mv、cp 等）回退不了，子代理在后台做的修改通常也不在内。它是会话级的后悔药，不能替代 git。

三. /model opusplan——规划用 Opus，执行用 Sonnet

这个选项就躺在 /model 列表里，但名字不直观，很多人直接划过去了。

/model opusplan

opusplan 是一个模型别名：在 plan mode 下用 Opus 做推理和架构决策，退出 plan mode 开始执行时自动切到 Sonnet 写代码。也可以启动时直接 claude --model opusplan。

对 Opus 额度有限的订阅用户来说，这是个省额度的折中：规划需要理解项目架构和依赖关系，Opus 更擅长；具体写代码的环节 Sonnet 通常够用，而且更快。省多少取决于你在 plan mode 里待多久，建议自己用 /usage 对比一下。

四. /simplify——多个子代理并行挑毛病

先澄清一个常见误会：/simplify 不是第三方插件提供的，它是 Claude Code 自带的 bundled skill，装好就能用。

输入 /simplify，Claude Code 会并行启动四个审查子代理，检查你当前的代码改动（截至 2026-10 的划分）：

  • 复用：有没有已有的 helper 可以直接用，有没有重复逻辑
  • 简化：有没有更简洁的写法
  • 效率：有没有不必要的计算、可以优化的循环
  • 抽象层次：这个改动是不是放在了合适的层级

审查完它会直接应用修改。也可以传路径或 PR 引用，审查指定目标。注意它只管代码质量，不找正确性 bug——找 bug 用 /code-review。

我现在的习惯是，跟 Claude 来回写了几个大功能之后，顺手跑一遍 /simplify。AI 写的代码经常有微妙的冗余——多余的 import、重复的逻辑、能复用现有函数的地方，它基本都能挑出来。

五. /branch 和 /fork——对话分叉

这两个命令以前是同一个东西，现在分开了：

  • /branch [name]：在当前位置给对话开一个分支，并切换到分支里继续；原对话保留，可以用 /resume 切回去。
  • /fork [prompt]：把当前对话复制成一个后台会话，你留在原会话里继续干活。带 prompt 的话，副本会立刻开始做那件事。

Claude 帮你梳理完一个方案，你想试两种不同的实现——/branch 一下，两条线各走一边，最后挑效果好的。想让副本在后台干，自己接着聊，就用 /fork。

跟 /rewind 的区别：/rewind 是回到过去，/branch 是开辟新的世界线。

六. /loop——会话里的定时轮询

/loop 5m 检查一下部署状态

带间隔就按固定频率执行（支持 s、m、h、d，最小粒度 1 分钟）。不写间隔时，Claude 会根据情况自己决定下次多久后再跑（1 分钟到 1 小时之间），比如构建快结束时等得短、没动静时等得长。连 prompt 都不写，就跑内置的维护 prompt（或你的 .claude/loop.md）。

我用得最多的场景是等部署：/loop 3m 检查 CI 状态，如果失败了告诉我原因。

几个细节：

  • 固定间隔的循环任务创建 7 天后自动过期：最后触发一次，然后删除自己，防止被遗忘的循环一直跑。
  • 它是会话级的：只在 Claude Code 运行且空闲时触发，关掉终端就停。用 --resume 恢复会话时，未过期的定时任务会被恢复，但自定节奏的 /loop 需要重新启动。

七. /remote-control——在手机上接管终端会话

终端里打 /remote-control（别名 /rc），这个会话就能从 claude.ai 或手机 App 上远程操作。需要 claude.ai 订阅账号登录。

代码仍然在你的电脑上跑，手机只是遥控器：文件系统、MCP 服务器、项目配置都在本地。

适合什么场景？比如让 Claude 跑一个长任务，然后去倒咖啡，路上掏出手机看看进度，顺手发个指令微调一下。

八. /export——把聊天记录带走

/export
/export design-discussion.txt

把当前对话导出为纯文本。带文件名就直接写入文件，不带就弹出对话框，让你选择复制到剪贴板或存成文件。

听起来不起眼，但有时候特别有用。你跟 Claude 讨论了半小时架构方案，中间很多来回推敲，不保存下来后面很难找。

我还有个用法：导出后交给另一个 AI 工具，让它看看 Claude 改了半天没改好的代码。两个模型互相审一下，有时能发现单独用一个发现不了的问题。

九. /insights——让 Claude 反过来分析你

打 /insights，会生成一份 HTML 报告，分析你在这台机器上最近的会话：常在哪些项目里工作、怎么用 Claude Code、哪些环节容易出问题，以及值得尝试的功能（云端会话里不可用）。

我第一次跑的时候，它指出我总在手动跑同一组测试命令，建议做成 hook 自动执行。隔一段时间跑一次，对调整自己的使用习惯挺有帮助。

十. /usage（/cost）——看看这次花了多少

/usage

/cost 现在是 /usage 的别名（/stats 也是）。它显示当前会话的花费、订阅计划的用量限额和活动统计；Pro / Max / Team / Enterprise 用户还能看到哪些操作在消耗计划额度。

用 API key 的开发者尤其需要它——不然一个复杂任务跑下来花了多少钱心里没数。让 Claude 分析大型代码仓库这类任务之后，我都会顺手看一眼。

十一. /doctor——先别慌，让它自己查

/doctor

现在的 /doctor（别名 /checkup）是一个 bundled skill：检查安装、设置、扩展（插件、MCP 等）和 CLAUDE.md 的问题，给出修复建议，你确认后由 Claude 来改。

遇到莫名其妙的错误先跑一下 /doctor，很多时候问题出在环境配置上，不是代码的锅。

十二. Hooks——让 Claude Code 在固定时机自动跑脚本

严格来说这不是一个命令，是 Claude Code 的 Hook 系统——你在 settings.json 里写好规则，它就会在特定时机自动跑脚本。（上图只是示意，实际事件名以下文和官方文档为准。）

{
  "hooks": {
    "SessionStart": [
      {
        "hooks": [
          { "type": "command", "command": "bash ~/.claude/hooks/check-proxy.sh", "async": true }
        ]
      }
    ],
    "Stop": [
      {
        "hooks": [
          { "type": "command", "command": "bash ~/.claude/hooks/cleanup.sh" }
        ]
      }
    ]
  }
}

注意结构：每个事件下是一组 { "matcher": ..., "hooks": [...] }，具体命令写在内层的 hooks 数组里，type 不能省；async: true 表示放到后台跑，不阻塞会话。

最常用的事件有这几个：SessionStart（会话启动）、UserPromptSubmit（提交 prompt 时）、PreToolUse / PostToolUse（调用工具前后）、Stop（Claude 回答结束时）、SessionEnd（会话结束）。此外还有 PreCompact、Notification、SubagentStop 等二十多个事件，完整列表见官方 hooks 文档。在 PreToolUse 里以退出码 2 结束，可以直接拦下这次工具调用。什么规则该写进 CLAUDE.md、什么该写成 hook，可以参考我的 CLAUDE.md 配置手册。

我用 hook 做了一个配置检查：每次 Claude Code 启动，自动检测 API 代理是否可用，不可用就提醒我切换配置，省得每次手动排查。

十三. /status——快速摸个底

/status

打开设置界面的 Status 页，显示版本、当前模型、账号和连接状态（包括代理配置）。Claude 正在回答时也能用。

快速确认”我现在用的是哪个模型””登录的是哪个账号”，比到处翻方便。想看上下文占用用 /context，想看 MCP 服务器连接状态用 /mcp。

十四. /schedule——关了终端也能按时跑

/loop 是会话级的，关了终端就停。需要持久化的定时任务，用 /schedule（别名 /routines）创建云端的 routine，用自然语言描述就行：

/schedule 每天早上 9 点检查项目依赖是否有安全更新

routine 跑在 Anthropic 的云端，不需要你的电脑开机，但它拿到的是仓库的新克隆，访问不到你本机的文件，最小间隔 1 小时。如果需要读本地文件、按分钟级频率跑，可以用 Claude Desktop 的定时任务，或者干脆交给 GitHub Actions 的 schedule 触发器。

适合那种需要定期执行的运维类任务——每天检查依赖更新、每周生成代码质量报告之类的。

十五. 快捷键——手指记住了脑子就轻松了

这几个快捷键我天天用，但很多人不知道。

Ctrl+V——直接粘贴截图，不需要先存成文件。debug 遇到报错，截屏粘过去就行。iTerm2 里也可以用 Cmd+V，Windows / WSL 上是 Alt+V。

Ctrl+J——换行，任何终端都能用。macOS 上 Option+Enter 也行，但要先把终端的 Option 键设成 Meta。

Ctrl+R——反向搜索之前输入过的 prompt 历史。

Ctrl+U——删除光标到行首的内容。

Shift+Tab——切换权限模式：default（每步询问）、acceptEdits（自动接受文件修改）、plan（只规划不动手），在可用时还会轮到 bypassPermissions 和 auto。

Esc（单按）——中断 Claude 当前的回答或工具调用，已经做完的部分会保留，方便你改方向。

Esc Esc（连按两次）——输入框有内容时清空草稿（按 Up 能找回）；输入框为空时打开 /rewind 菜单。

Ctrl+G——用外部编辑器写 prompt，VS Code、Vim 都行，写完保存关闭，内容自动填回去。写长 prompt 不用在终端里憋屈了。

Option+T（macOS）/ Alt+T（Windows / Linux）——开关扩展思考。注意：Opus 5.5、Sonnet 5.5 等新模型始终开启扩展思考，这个开关对它们无效，想调思考深度用后面的 /effort。

Ctrl+L——强制重绘屏幕，输入和对话历史都保留。屏幕显示错乱时按一下。

十六. /compact——清上下文但不失忆

很多人上下文快满的时候直接 /clear，一刀切，全没了。

/compact 会把前面的对话压缩成一段摘要，释放上下文空间，但 Claude 还记得你们之前聊了什么。

/compact
# 或者带一句话告诉它重点保留什么
/compact 保留关于数据库迁移方案的讨论

聊了很久、上下文告警的时候 /compact 一下，之前定好的方案它还记着，接着干就行。项目根目录的 CLAUDE.md 在压缩后会重新从磁盘读入，不用担心丢规则。

跟 /clear 的区别：/clear 是开一个全新的空白对话，/compact 是把笔记压缩了塞口袋里。

十七. /resume——关了终端也能接着聊

不小心关了终端，一个小时的对话也不会丢。

# 直接接上最近一次会话
claude --continue

# 打开会话列表挑一个
claude --resume

会话里打 /resume 也会弹出会话列表，选一个就接着聊。

配合 /rename 更好用——给当前会话起个名字，下次直接按名字找：

/rename 重构用户模块
# 下次
/resume 重构用户模块

我做跨好几天的大任务时都会 /rename 一下，第二天 /resume 接着来，之前的对话上下文都在。

十八. /context——看看上下文还剩多少

/context

用彩色方格图显示当前上下文用了多少、还剩多少、哪些东西最占空间，还会给出优化建议。

我以前一直凭感觉判断”差不多该 compact 了”，有了 /context 才发现，有时候一个大文件或一堆 MCP 工具定义就吃掉了一大块上下文。知道瓶颈在哪，优化就有方向。

十九. /diff——看看到底改了啥

Claude 改了一堆文件，想看具体改了什么，不用再切出去跑 git diff：

/diff

它展示工作区里所有未提交的改动，包括 Claude 做的修改和你自己改的部分。在 Claude 改过文件之后，还能按对话轮次查看每一轮的改动——“第三轮 Claude 改了这三个文件”一目了然，这是比 git diff 好用的地方。

二十. /color——多开的时候不会搞混

/color blue

给当前会话的提示栏换个颜色。支持 red、blue、green、yellow、purple、orange、pink、cyan，default 恢复默认，不带参数随机挑一个。

听着像玩具功能，但同时开三四个终端窗口跑不同任务的时候就知道了——哪个是前端、哪个是后端、哪个是测试，一眼分清。我的习惯是前端用 cyan，后端用 green，调试用 red。

二十一. /effort——给 Claude 换档

/effort high

可选档位：low、medium、high、xhigh、max，以及让 Claude 自己判断的 auto；/effort status 查看当前档位。max 只对当前会话生效。具体支持哪些档位取决于模型（比如 Opus 4.6 没有 xhigh，设了会降到 high）。

low 适合简单问答，回得快；high 及以上适合复杂架构设计和难缠的 bug，Claude 会想得更久。

跟 /model 的区别：/model 换的是”谁来干活”，/effort 调的是”干活多认真”。两个可以叠加。

我日常用 auto，遇到棘手的 bug 临时 /effort max，解决完再调回来。

二十二. /security-review——提 PR 前过一遍安全

/security-review

分析当前分支相对 origin 默认分支的 diff，专门找安全问题——注入、鉴权问题、数据泄露这类风险。它需要仓库有 origin 远程。

跟 lint 不一样，它不查代码风格，只查安全问题；而且只看你这个分支改的部分，不扫全仓库。我把它放在开 PR 之前的固定流程里。

二十三. ! 和 @——两个冷门但好用的输入技巧

这两个不是命令，是输入时能用的特殊前缀。

! 开头——进入 shell 模式，直接跑命令，输出会进入对话上下文。

! git log --oneline -5

不用等 Claude 帮你跑，自己先看一眼；跑完的输出 Claude 也能看到，后续可以直接引用。

@ 符号——文件路径自动补全。

打个 @，开始敲文件名，会弹出补全列表。选中后，文件内容会被加到上下文里。

比你说”帮我看看 src/utils/helper.ts”高效——@ 补全不会打错路径，Claude 也不用再单独读一次。

写在最后

上面 23 个功能，有不少是最近几个月才出现或改过名的——/cost 变成了 /usage 的别名，/fork 和 /branch 分了家，/doctor 和 /simplify 变成了 bundled skill。过几个月再看，大概又会有一批变化。

想跟上变化，最省事的是隔段时间跑一下 /release-notes，它会在终端里按版本列出更新说明；也可以看 Claude Code GitHub 仓库里的 CHANGELOG 和官方文档。

非要只选 3 个的话，我投 /btw、/compact 和 /resume。这仨真的改变了我和 Claude Code 协作的方式。
