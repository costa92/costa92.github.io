Claude Code 进阶命令手册：23 个容易被忽略的命令和输入前缀

Claude Code 迭代很快，命令改名、合并、变成 skill 是常事，很多变化只写在 CHANGELOG 里。这篇是我日常真在用的 23 个：21 个斜杠命令（/branch 和 /fork 合在一节）加 !、@ 两个输入前缀，Hooks 和快捷键另外放在后面，不计入这 23 个。每条都对照过官方命令文档和交互模式文档，命令名和别名又在本机的程序里核对了一遍。

我怎么核对的：–help 加程序里的命令注册表

斜杠命令不在 claude --help 里，--help 只列启动参数和子命令。所以我分两步核对：启动参数看 --help；斜杠命令直接在本机安装的程序里搜命令注册（原生安装版是单个可执行文件，命令定义以 name:"xxx" 的形式写在里面）。

2026-10-30 在 Ubuntu 26.04 + Claude Code 2.1.314（原生安装）上实测，只看帮助和程序文本，没有登录、没有开会话：

$ claude --version
2.1.314 (Claude Code)

$ claude --help    # 截取三项，空白按原样保留
  -c, --continue                        Continue the most recent conversation in
                                        the current directory
  --effort <level>                      Effort level for the current session
                                        (low, medium, high, xhigh, max)
  -r, --resume [value]                  Resume a conversation by session ID or
                                        name, or open interactive picker with
                                        optional search term

从程序里搜出来的命令名、别名和描述（截取本文涉及的部分）：

命令别名程序里的描述
/btw [question]—Ask a quick side question without interrupting the main conversation
/rewind/checkpoint、/undo—
/branch [name]—Create a branch of the current conversation at this point
/fork [prompt]—Copy this conversation into a new background session and keep working here
/usage/cost、/statsShow session cost, plan usage, and activity stats
/doctor/checkupHealth-check your setup and fix issues…
/remote-control/rcControl this session from your phone or claude.ai/code
/schedule/routinesCreate and manage scheduled remote Claude Code agents
/resume/continueResume a previous conversation
/rename [name]/nameRename the current conversation
/context [all]—Visualize current context usage as a colored grid
/diff—View uncommitted changes and per-turn diffs

/insights 也是注册命令，类型是 prompt，描述为 “Generate a report analyzing your Claude Code sessions”。/loop、/simplify、/security-review、/code-review 没有这种命令注册，它们出现在程序的内置 skill 名单里。这也解释了为什么它们的行为更像”一段提示词流程”而不是固定功能。

核对中发现两处和我原来写法不一样的地方：/fork 在程序里注册了两个版本，另一个是 /fork <directive>，描述为 “Spawn a background agent that inherits the full conversation”，两者都带开关条件，你看到哪个取决于账号和版本；/resume 和 /rename 也各有别名（/continue、/name），文档里不太显眼。

版本说明：下文以 2.1.314 为准。遇到对不上的地方，以会话里输入 / 弹出的列表和 /release-notes 为准。

上下文管理：问一句、压一下、看一眼

/btw：插个嘴但不留痕迹

Claude 正在重构一个大模块，你想问个相关的小问题。直接问，这段问答会进对话历史，可能把它带偏。用 /btw：

/btw 刚才你说的那个配置文件叫什么来着？

答案以浮层显示，按空格、回车或 Esc 关闭，这段问答不进入对话历史。几个要点：

  • Claude 干活时也能问：side question 独立运行，不打断当前回合。
  • 没有工具权限：它只根据当前上下文回答，不读文件、不跑命令。适合问”刚才读过的代码里 X 是什么”，不适合问它还没看过的东西。
  • 提示缓存还热的时候，除了答案本身几乎没有额外成本。
  • 不带问题直接打 /btw，可以翻看之前问过的 side question。

我每个长会话里都会用几次，主线上下文保持干净。

/compact：清上下文但不失忆

上下文快满时直接 /clear 是一刀切。/compact 把前面的对话压缩成摘要，释放空间，但 Claude 还记得之前聊过什么：

/compact
# 或者告诉它重点保留什么
/compact 保留关于数据库迁移方案的讨论

项目根目录的 CLAUDE.md 在压缩后会重新从磁盘读入，规则不会丢。/clear 是开一个全新的空白对话，/compact 是把笔记压缩了塞口袋里。

/context：看看上下文还剩多少

/context

用彩色方格图显示上下文用了多少、哪些东西最占空间，还会给出优化建议；带 all 参数看完整明细。我以前凭感觉判断”差不多该 compact 了”，用了 /context 才发现，有时一个大文件或一堆 MCP 工具定义就吃掉了一大块。

/export：把聊天记录带走

/export
/export design-discussion.txt

带文件名就直接写入文件，不带就弹出对话框，选择复制到剪贴板或存成文件。讨论了半小时的架构方案，不存下来后面很难找。我还会把导出的记录交给另一个 AI 工具，让它看看 Claude 改了半天没改好的代码，两个模型互相审，有时能发现单独用一个发现不了的问题。

回退与分叉：试错成本压到最低

/rewind：后悔药，还能选择性吃

输入框为空时按两下 Esc，或者打 /rewind（别名 /checkpoint、/undo）。选中要回到的那条消息后，有这些选项：

  • Restore code and conversation：代码和对话一起回退
  • Restore conversation：只回退对话，保留代码
  • Restore code：只回退代码，保留对话
  • Summarize from here：把从这里往后的对话压缩成摘要
  • Summarize up to here：把这里之前的对话压缩成摘要，保留后面的消息

“只回退代码、保留对话”适合做实验：让 Claude 试一种写法，不行就把代码退回去，对话留着，它知道这条路不通，直接换方向。

限制要知道：checkpoint 只追踪 Claude 用文件编辑工具做的修改，通过 Bash 命令改的文件（rm、mv、cp 等）回退不了，子代理在后台做的修改通常也不在内。它是会话级的后悔药，不能替代 git。

/branch 和 /fork：对话分叉

  • /branch [name]：在当前位置给对话开一个分支并切进去，原对话保留，可以用 /resume 切回去。
  • /fork [prompt]：把当前对话复制成一个后台会话，你留在原会话里继续。带 prompt 的话，副本会立刻开始做那件事。

方案梳理完想试两种实现，/branch 一下两条线各走一边；想让副本在后台干、自己接着聊，用 /fork。/rewind 是回到过去，/branch 是开辟新的世界线。

/resume：关了终端也能接着聊

# 接上当前目录最近一次会话
claude --continue

# 打开会话列表挑一个，也可以直接跟会话 ID 或名字
claude --resume

会话里打 /resume（别名 /continue）也会弹出列表。配合 /rename 更好用：

/rename 重构用户模块
# 下次
/resume 重构用户模块

2.1.314 的 --help 里还有个 -n, --name <name>，启动时就能给会话起名，名字会显示在提示框、/resume 列表和终端标题里。跨好几天的大任务，我第二天直接 claude --resume 重构用户模块。

模型与思考深度

/model opusplan：规划用 Opus，执行用 Sonnet

/model opusplan

opusplan 是一个模型别名：在 plan mode 下用 Opus 做推理和架构决策，退出 plan mode 开始执行时切到 Sonnet 写代码。启动时也可以 claude --model opusplan。2.1.314 的程序里能搜到 opusplan 和 opusplan[1m] 两个写法，相关说明是”a session whose model setting is ‘opusplan’ … runs a different model in plan mode”。

对 Opus 额度有限的订阅用户，这是个省额度的折中。省多少取决于你在 plan mode 里待多久，用 /usage 自己对比。

/effort：给 Claude 换档

/effort high

--help 里列出的档位是 low、medium、high、xhigh、max；会话里另有让 Claude 自己判断的 auto，/effort status 查看当前档位。具体支持哪些档位取决于模型，程序里不同模型的档位列表并不一样，设了不支持的档位会降级。

low 适合简单问答；high 及以上适合复杂架构设计和难缠的 bug。/model 换的是”谁来干活”，/effort 调的是”干活多认真”，两个可以叠加。我日常用 auto，遇到棘手的 bug 临时 /effort max，解决完再调回来。

审查：提交前让它自己挑毛病

/simplify：多个子代理并行挑毛病

/simplify 是 Claude Code 自带的 bundled skill，在程序的内置 skill 名单里能看到它，装好就能用，不是第三方插件。

它会并行启动审查子代理，检查当前改动的四个方面：复用（有没有现成 helper、重复逻辑）、简化、效率、抽象层次。审查完直接应用修改，也可以传路径或 PR 引用审查指定目标。它只管代码质量，不找正确性 bug，找 bug 用同样在内置名单里的 /code-review。

跟 Claude 来回写了几个大功能之后，我会顺手跑一遍。多余的 import、重复逻辑、能复用现有函数的地方，它基本都能挑出来。

/security-review：提 PR 前过一遍安全

/security-review

分析当前分支相对 origin 默认分支的 diff，专门找注入、鉴权、数据泄露这类风险，需要仓库有 origin 远程。程序里能看到它在非 git 目录下的提示：”/security-review needs to run inside a git repository”。它不查代码风格，只看这个分支改的部分。我把它放在开 PR 之前的固定流程里。

/diff：看看到底改了啥

/diff

展示工作区里所有未提交的改动，包括 Claude 做的和你自己改的。比 git diff 多一样东西：按对话轮次查看每一轮的改动（程序里的描述是 “View uncommitted changes and per-turn diffs”）。全屏模式下它变成一个可以开关的 diff 面板。

状态与诊断

/usage（/cost、/stats）：看看这次花了多少

/usage

/cost 和 /stats 现在都是 /usage 的别名。它显示当前会话花费、订阅计划的用量限额和活动统计，Pro / Max / Team / Enterprise 用户还能看到哪些操作在消耗额度。用 API key 的开发者尤其需要它，让 Claude 分析大型仓库之后我都会看一眼。

/status：快速摸个底

/status

显示版本、当前模型、账号、API 连通性和工具状态（包括代理配置），Claude 正在回答时也能用。想看 MCP 服务器连接状态用 /mcp。

/doctor：先别慌，让它自己查

/doctor

/doctor（别名 /checkup）检查安装、没用上的扩展、重复或臃肿的 memory 文件、慢 hook、更新和权限，给出修复建议，你确认后由 Claude 来改。会话外还有一个 claude doctor 子命令，--help 里写的是 “Check the health of your Claude Code installation”。遇到莫名其妙的错误先跑它，很多时候问题出在环境配置上。

/insights：让 Claude 反过来分析你

打 /insights，会生成一份报告，分析你在这台机器上最近的会话：常在哪些项目里工作、哪些环节容易出问题、值得尝试的功能（云端会话里不可用）。2.1.314 的程序里它的描述是 “Generate a report analyzing your Claude Code sessions”，运行时提示 “analyzing your sessions”，报告会另存一份 HTML。它受组织策略 allow_insights 控制，团队账号里可能被管理员关掉。

定时与远程

/loop：会话里的定时轮询

/loop 5m 检查一下部署状态

带间隔就按固定频率执行，支持 s、m、h、d，但最小粒度是 1 分钟：程序里对秒级间隔直接报错 “minimum interval is 1 minute”，分钟数超过 59 会提示改用小时。不写间隔时，Claude 自己决定下次多久后再跑；连 prompt 都不写，就跑内置的维护 prompt（或你的 .claude/loop.md）。

我用得最多的是等部署：/loop 3m 检查 CI 状态，如果失败了告诉我原因。

按官方文档，固定间隔的循环任务创建 7 天后自动过期，防止被遗忘的循环一直跑。它是会话级的，只在 Claude Code 运行且空闲时触发，关掉终端就停。

/schedule：关了终端也能按时跑

需要持久化的定时任务，用 /schedule（别名 /routines）创建云端 routine，用自然语言描述：

/schedule 每天早上 9 点检查项目依赖是否有安全更新

routine 跑在 Anthropic 云端，不需要你的电脑开机，但拿到的是仓库的新克隆，访问不到本机文件，最小间隔 1 小时。需要读本地文件、按分钟级频率跑，用 Claude Desktop 的定时任务或 GitHub Actions 的 schedule 触发器。

/remote-control：在手机上接管终端会话

终端里打 /remote-control（别名 /rc），这个会话就能从 claude.ai 或手机 App 上远程操作，需要 claude.ai 订阅账号。启动时也可以直接 claude --remote-control [name]。代码仍然在你的电脑上跑，手机只是遥控器。让 Claude 跑一个长任务，去倒咖啡的路上掏出手机看看进度，顺手发个指令微调。

扩展：Hooks

Hooks 严格说不是命令：你在 settings.json 里写好规则，Claude Code 在特定时机自动跑脚本。（上图只是示意，事件名以官方文档为准。）

{
  "hooks": {
    "SessionStart": [
      {
        "hooks": [
          { "type": "command", "command": "bash ~/.claude/hooks/check-proxy.sh", "async": true }
        ]
      }
    ],
    "Stop": [
      {
        "hooks": [
          { "type": "command", "command": "bash ~/.claude/hooks/cleanup.sh" }
        ]
      }
    ]
  }
}

结构上，每个事件下是一组 { "matcher": ..., "hooks": [...] }，具体命令写在内层 hooks 数组里，type 不能省；async: true 表示放到后台跑，不阻塞会话。

常用事件：SessionStart、UserPromptSubmit、PreToolUse / PostToolUse、Stop、SessionEnd，此外还有 PreCompact、Notification、SubagentStop 等，完整列表见官方 hooks 文档。在 PreToolUse 里以退出码 2 结束，可以拦下这次工具调用。什么该写进 CLAUDE.md、什么该写成 hook，可以参考我的 CLAUDE.md 配置手册。

我用 hook 做了一个启动检查：每次 Claude Code 启动，自动检测 API 代理是否可用，不可用就提醒我切换配置。

输入技巧与外观

/color：多开的时候不会搞混

/color blue

给当前会话的提示栏换个颜色，default 恢复默认，不带参数随机挑一个。同时开三四个终端跑不同任务时，前端 cyan、后端 green、调试 red，一眼分清。

! 和 @：两个输入前缀

! 开头进入 shell 模式，直接跑命令，输出进入对话上下文：

! git log --oneline -5

@ 是文件路径补全：打个 @ 开始敲文件名，选中后文件内容加到上下文里。比说”帮我看看 src/utils/helper.ts”高效，不会打错路径。

快捷键：手指记住了脑子就轻松了

  • Ctrl+V：直接粘贴截图。iTerm2 里也可以 Cmd+V，Windows / WSL 上是 Alt+V。
  • Ctrl+J：换行，任何终端都能用。macOS 上 Option+Enter 也行，但要先把 Option 键设成 Meta。
  • Ctrl+R：反向搜索 prompt 历史。
  • Ctrl+U：删除光标到行首的内容。
  • Shift+Tab：切换权限模式，default、acceptEdits、plan 之间轮转，可用时还会轮到 bypassPermissions 和 auto。
  • Esc：中断当前回答或工具调用，已做完的部分保留。
  • Esc Esc：输入框有内容时清空草稿（按 Up 找回）；为空时打开 /rewind。
  • Ctrl+G：用外部编辑器写 prompt，保存关闭后内容自动填回。
  • Option+T（macOS）/ Alt+T（Windows / Linux）：开关扩展思考。部分新模型的思考是自适应的，这个开关对它们可能不起作用，想调深度用 /effort。
  • Ctrl+L：强制重绘屏幕，输入和历史都保留。

快捷键我没法从程序文本里逐个核对，以上以官方交互模式文档为准。

跟上变化的办法

这次核对下来，变化最大的是别名：/cost 并进了 /usage，/rewind 多了 /undo，/fork 和 /branch 分了家，/doctor 多了别名 /checkup，/simplify 变成了内置 skill。隔段时间跑一下 /release-notes，或者看 GitHub 仓库里的 CHANGELOG 和官方文档。

非要只选 3 个，我投 /btw、/compact 和 /resume。
